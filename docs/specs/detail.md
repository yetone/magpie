# 详细设计：已有调用记录的列表与详情

## 1. 数据来源

列表与详情直接使用现有 `usage.Record`。下钻只按模型、供应商、客户端与排行图表口径过滤，接口和排序见 [需求规范](spec.md) 与 [仪表盘设计](dashboard.md)。

```json
{
  "t": "2026-09-30T10:14:22.318+08:00",
  "agent": "codex",
  "provider": "openai",
  "host": "api.openai.com",
  "model": "gpt-5.5",
  "in": 4210,
  "out": 850,
  "cache_read": 3200,
  "cache_write": 500,
  "reasoning": 320,
  "effort": "medium",
  "ms": 2840,
  "ttft_ms": 1950,
  "status": 200,
  "session": "sess_8f21a",
  "kind": "review"
}
```

取消账号字段、尝试首字字段和前置等待分解；旧记录可直接展示。会话等字段缺失时显示 `—`。

## 2. 下钻调用列表

采用紧凑表格，每行一条记录，列为时间、状态、客户端、模型／供应商、总耗时、端到端首字、输入／输出 Tokens、会话／调用类型。

| 时间 | 状态 | 客户端 | 模型／供应商 | 总耗时 | 首字 | Tokens | 会话／类型 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 10:14:22 | 200 | Codex | gpt-5.5 · openai | 2.84s | 1.95s | 4.21k in · 850 out | sess_8f21a · review |
| 10:12:05 | 429 | Claude Code | sonnet-3-5 · anthropic | 1.1s | — | 12.4k in | — |

- 200 使用绿色状态徽章；429 橙色，5xx 红色，499 灰色中断标记；其他状态直接展示状态码。
- 首字列显示已有 `ttft_ms`；没有有效记录时显示 `—`。不展示尝试首字或前置等待星号。
- 模型下方显示 `provider`，不拼接账号。
- 可能包含邮箱的既有会话文本复用全局 Hide emails；分析页的视图与掩码按钮一起注册，细节见 [实施方案](plan.md)。

## 3. 原地调用详情

点击行时在其下方展开详情，全部值来自该条记录：

| 分组 | 字段与示例 |
| :--- | :--- |
| 基础信息 | 本地发生时间、客户端、调用类型、会话 ID 及复制按钮 |
| 路由 | 供应商、域名、模型、推理程度 |
| 性能 | 总耗时 2840ms、端到端首字 1950ms、解码速度 955.1 tok/s |
| Token 与缓存 | 输入 4210、输出 850、缓存读取 3200、缓存写入 500、完整提示词总量 7910 |
| 缓存率 | 沿用用量页：`3200 / (4210 + 3200)`，显示约 43%；写入量单独列出 |
| 推理 | 思考输出 320、正文输出 530，思考计数属于总输出 |
| 状态 | HTTP 状态码；错误时展示该状态码的双语通用说明 |

解码速度沿用现有有效性条件：`status < 400 && ttft_ms > 0 && out > 0 && ms > ttft_ms`；本例为 `850 / ((2840 - 1950) / 1000)`。无有效解码数据时显示 `—`。

缓存率分母 `in + cache_read` 是现有界面的统计口径，完整提示词总量为 `in + cache_read + cache_write`。二者分别标注；写入量不加入缓存率分母。分母为 0 时显示 `—`。

状态说明只根据已有状态码生成，不展示账本未记录的上游原始错误正文或尝试失败历史。

## 4. 交互与双语

- 明细及详情使用 CSS `grid-template-rows: 0fr -> 1fr`，180ms 过渡。
- 沿用 `app.js` 的 `.view` 点击锚点与 ResizeObserver 持续补偿。展开、折叠和切换明细不得使用 `scrollIntoView` 或重置页面滚动。
- 所有标签和通用状态说明接入 `i18n.js`；会话 ID 旁提供复制按钮。
