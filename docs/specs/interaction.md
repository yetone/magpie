# 交互设计：独立分析看板页面与联动工作流

## 1. 整体导航与入口交互

### 1.1 用量页（Usage）进入分析看板
- **入口位置**：用量页顶部操作栏右侧（`#view-usage .usage-head`）新增图标操作按钮：
  ```html
  <button id="openAnalytics" class="text" data-tt="质量与分析看板" aria-label="Analytics">
    <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" aria-hidden="true">
      <path d="M3 3v18h18"/>
      <path d="m19 9-5 5-4-4-3 3"/>
    </svg>
    <span data-t>Analytics</span>
  </button>
  ```
- **点击交互行为**：
  - 点击按钮调用 `show("analytics")`；
  - 顶部导航栏焦点状态维持在 `Usage`（或在地址栏更新 `?view=analytics`，便于刷新或外链回放）；
  - 主视图从 `#view-usage` 平滑切换至 `#view-analytics`；
  - **继承时间范围**：页面进入时完整继承当前用量页选中的时间范围（如用量页正看着 `7d`，进入分析看板直接以 `7d` 为基准加载）；
  - **继承与保存返回位置**：记录切入分析看板前用量页的滚动位置与状态。

### 1.2 从分析看板返回用量页
- **返回按钮**：分析看板头部最左侧提供面包屑式返回链接：
  `← 用量 (Usage) / 质量与分析 (Analytics)`
- 点击随时平滑切回用量主视图，准确恢复之前记录的滚动位置与标签状态。

## 2. 分析看板主页面结构布局

页面自上而下分为控制区与三个分析主题区块，图表与 KPI 的具体口径遵循《[仪表盘设计](dashboard.md)》规范：

```text
+-----------------------------------------------------------------------------------+
|  [← Usage / Analytics]   [ Today | 7d | 30d | All ]                               |  <- 1. 顶部控制栏
|  [ 全部 (on) ] [ 按模型 ] [ 按供应商 ] [ 按客户端 ] | [ 模型 ▾ ] [ 供应商 ▾ ] [ 客户端 ▾ ] |  <- 2. 模式切换与筛选
+-----------------------------------------------------------------------------------+
|  一、可靠性      [KPI 磁贴]  1.1 错误率排行 (DESC) | 1.2 异常趋势 (只读)           |  <- 3. 主题区块
|  二、响应速度    [KPI 磁贴]  2.1 端到端 TTFT P95 排行 (DESC) | 2.2 解码速度排行 (ASC)|
|  三、成本与缓存  [KPI 磁贴]  3.1 成本排行 (DESC) | 3.2 缓存率排行 (ASC)            |
+-----------------------------------------------------------------------------------+
```

- **宽窄屏自适应**：宽屏下同一主题内 2 张图表并排展示；窄屏（如面板嵌入或移动窗口）下自动折叠为单列流式布局；
- KPI 磁贴紧挨所属主题图表顶部放置，不再占用全局成排空间；
- 原地下钻明细直接在被触发的图表正下方展开，并在视图中严格维持单处激活。

## 3. 分析模式与筛选联动交互

### 3.1 模式切换器（Dimension Switcher）
- 采用单选分段控制器（Segmented Control），提供四个选项：
  `[ 全部 ]` `[ 按模型 ]` `[ 按供应商 ]` `[ 按客户端 ]`
- **纯前端展示模式**：模式切换不改变请求接口地址，底层始终统一调用 `GET /api/analytics?period=...&model=...&provider=...&agent=...`；一次请求获取完整 summary 指标以及 `rankings.model`、`rankings.provider`、`rankings.agent` 三套排行数据；
- 默认选中 **全部**：先了解宏观健康度，再切换具体实体维度定位瓶颈。

### 3.2 筛选栏（Filter Bar）与重算规则
选中某个分析维度时，该维度用于实体分组排行，**另外两组维度成为筛选下拉选择器**；选中「全部」时，三组维度均作为筛选器：

| 模式 | 筛选器 | 排行图形态 |
| :--- | :--- | :--- |
| **全部**（默认） | `[ 模型 ▾ ]` `[ 供应商 ▾ ]` `[ 客户端 ▾ ]` | 退化为单数字卡片（磁贴去重呈现） |
| **按模型** | `[ 供应商 ▾ ]` `[ 客户端 ▾ ]` | 按模型排行的条形图 |
| **按供应商** | `[ 模型 ▾ ]` `[ 客户端 ▾ ]` | 按供应商排行的条形图 |
| **按客户端** | `[ 模型 ▾ ]` `[ 供应商 ▾ ]` | 按客户端排行的条形图 |

- **统一服务端筛选重算**：
  - 用户改变任意下拉筛选器（模型 / 供应商 / 客户端）或时间周期时，前端向服务端发起带筛选参数的完整聚合请求；
  - 服务端基于底层全量 `usage.Record` 重新计算各图指标与排行后返回；
- **切换模式时的筛选保留规则**：
  - 切换至「按 X」分组模式时，**清除 X 维度已有的筛选值**（避免同一维度既分组又筛选产生逻辑冲突），**其余维度的筛选值严格保留**；
  - 切换回「全部」模式时，当前已有的所有筛选条件全部保留；
  - 示例：在「按模型」模式下已筛选 `供应商 = OpenAI`，切换至「按供应商」模式后，`供应商` 筛选被自动清空，模型分组被取消并转为按供应商排行；若此前还筛选了 `客户端 = Codex`，则该客户端筛选继续有效。
  - 清除筛选导致条件变化时重新请求服务端；条件未变时直接选择已返回的排行。筛选、周期或模式变化时收起旧明细。

## 4. 原地下钻与调用列表交互

### 4.1 触发元素与交互边界
- **可下钻触发源**：
  1. 实体排行条形图中的每一根实体条形；
  2. 全部模式下的指标卡片 / 对应区域；
- **无下钻 / 只读元素**：
  - **1.2 异常趋势图为只读展示**：不可点击堆叠柱子，不按时间桶下钻，也不与图表 1.1 的实体条形发生高亮联动；
  - 没有任何状态切片下钻（如单点 429 红色分段直接下钻特定错误码已取消）；
  - 没有任何延迟直方图或 Token 分桶下钻；
- **合并已有筛选**：
  - 点击实体条形时，系统自动将该实体值与当前顶部已生效的筛选参数**合并**（如已有 `agent=codex`，在模型图点击 `gpt-5.5`，合并为 `agent=codex&model=gpt-5.5`）；
  - 全部模式下点击单数字卡片时，不附加新增实体，仅携带当前全局筛选参数。

### 4.2 下钻请求与列表展示
- **接口契约**：
  - 前端调用 `GET /api/analytics/calls`；
  - 参数传递：`period`、`model`、`provider`、`agent`、`chart_id`（1.1 / 2.1 / 2.2 / 3.1 / 3.2）、`limit`（默认且最大上限 50）；
  - 对应 Go 函数为 `RecentCalls(p, filter, chartID, limit)`；
  - 服务端基于筛选后的完整数据集，根据 `chart_id` 对应的口径与排序规则排好序后，截取前 50 条调用返回；
- **就地平滑展开**：
  - 下钻列表容器嵌入在当前被点击图表的正下方，采用 CSS `grid-template-rows: 0fr -> 1fr`，180ms 过渡；
  - 列表头部展示当前生效的过滤标签 Chips（如 `模型: gpt-5.5` `供应商: OpenAI`）与结果条数，右侧提供 `[收起明细 ×]` 按钮；
  - **全局单处展开**：点击另一张图表的条形或卡片时，自动平滑收起先前的展开内容，同一时刻页面仅有一处激活下钻。

### 4.3 滚动锁定与防抖（Scroll Anchoring）
- 下钻展开或收起会导致文档流高度动态变化；
- 系统严格使用点击锚点记录与 `ResizeObserver` 动态补偿容器的 `scrollTop`，抵消高度突变造成的视野漂移；
- 严禁调用原生 `scrollIntoView`，杜绝任何页面跳跃与滚动抖动，保证用户视线焦点稳固停留在所点图表位置。
