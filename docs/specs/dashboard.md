# 仪表盘设计：按分析主题分组的排行条形图规范

## 1. 核心图表设计原则：异常排序横向条形图（Ranked Bar Charts）

日常排障与服务分析的核心诉求是**“一眼找出哪个在拖后腿”**。
因此，分析看板中的主要图表统一采用「GROUP BY <当前分析维度> ORDER BY <异常程度，最差在上>」的横向条形图：

- **Y 轴（实体维度标签）**：按当前选中的分析维度（模型 / 供应商 / 客户端）分行排列（仅基于现有的 `model`、`provider`、`agent` 字段，供应商不含账号）；
- **X 轴（指标长度）**：条形长度代表该指标的值；
- **排序规则**：最异常的实体排在最上面。「异常」的方向逐图明确定义：
  - 1.1 错误率：DESC（从高到低）
  - 1.2 异常趋势：只读时间轴，不参与实体排序
  - 2.1 端到端 TTFT P95：DESC（从慢到快）
  - 2.2 解码速度：ASC（从慢到快）
  - 3.1 成本：DESC（从高到低）
  - 3.2 缓存率：ASC（从低到高）
- **交互与下钻**：每一根实体条形与全部模式下的卡片均可点击，点击后将实体合并到当前筛选条件，就地下钻最近调用明细。异常趋势图为只读观察，不点击也不与其他图表联动。

### 1.1 通用排序规则：有效样本门槛
按比例、速度或分位数排序时，样本极少的实体会排到最前面，误导判断。因此按图表自身的分母设置有效门槛：
- **错误率（1.1）**：总调用数 ≥ 10 次；
- **端到端 TTFT P95（2.1）**：有效样本数（`TTFT > 0` 且 `Status < 400`）≥ 10 次（非流式与失败请求无首字，不计入延迟分母）；
- **解码速度（2.2）**：严格沿用现有用量页 `Totals.Speed()` 的有效样本定义（`TTFT > 0`、`Status < 400`、`Output > 0` 且 `Millis > TTFT`），且有效样本数 ≥ 10 次；
- **成本（3.1）**：无特殊门槛，按计费总额排序；未定价调用并入末尾「未定价」行；
- **缓存率（3.2）**：有效输入量门槛为 `input + cache_read ≥ 10k Tokens`；全零实体归入末尾「无缓存记录 / 未知」行；
- 未达门槛的实体折叠到图表末尾的「样本不足（N 项）」行，不参与主排序，点击仍可下钻查看。

## 2. 分析主题与分组总览

看板固定 6 张图表，按用户要回答的问题归为三个主题。每个主题在页面上是一个带标题的分组区块，区块顶部是该主题的 KPI 磁贴，下面是该主题的图表。

| 主题 | 回答的问题 | KPI 磁贴 | 图表（ID 固定） |
| :--- | :--- | :--- | :--- |
| **一、可靠性** | 哪里在失败？从什么时候开始的？ | 成功率、429 / 5xx 次数 | 1.1 错误率排行 (DESC)、1.2 异常趋势 (只读) |
| **二、响应速度** | 哪里慢？是首字响应慢，还是生成写得慢？ | 端到端 TTFT P95、解码速度 | 2.1 端到端 TTFT P95 排行 (DESC)、2.2 解码速度排行 (ASC) |
| **三、成本与缓存** | 钱花在哪？哪里的缓存没用好？ | 总成本、缓存率 | 3.1 成本排行 (DESC)、3.2 缓存率排行 (ASC) |

分组依据：
- **可靠性**放在最上面：失败是最需要立刻处理的问题；
- **响应速度**聚焦端到端首字延迟与后续输出解码速度，两者直接决定用户感知；
- **成本与缓存**放在一起，是因为缓存率低的实体是否值得优化，取决于它的成本占比。

原「全局常驻 KPI 栏」拆分到三个主题区块的顶部，每块磁贴紧挨着解释它的图表，不再单独成排。

## 3. 页面布局

```text
+-----------------------------------------------------------------------------------+
|  [← Usage / Analytics]   [ Today | 7d | 30d | All ]                               |
|  [ 全部 ] [ 按模型 ] [ 按供应商 ] [ 按客户端 ]  |  [ 模型 ▾ ] [ 供应商 ▾ ] [ 客户端 ▾ ] |
+-----------------------------------------------------------------------------------+
|  一、可靠性                                                                       |
|  [ 成功率 98.6% ]  [ 429: 14 次 ]  [ 5xx: 2 次 ]                                  |
|  1.1 错误率排行                    |  1.2 异常趋势 (只读)                          |
+-----------------------------------------------------------------------------------+
|  二、响应速度                                                                     |
|  [ 端到端 TTFT P95 1.2s ]  [ 解码速度 52 tok/s ]                                  |
|  2.1 端到端 TTFT P95 排行          |  2.2 解码速度排行                             |
+-----------------------------------------------------------------------------------+
|  三、成本与缓存                                                                   |
|  [ 成本 ≈$12.40 ]  [ 缓存率 64.2% · 写入 1.2M tok ]                                |
|  3.1 成本排行                      |  3.2 缓存率排行                               |
+-----------------------------------------------------------------------------------+
|  ▼ 下钻明细（点击任一条形或全部卡片后在所点图表下方展开）                          |
+-----------------------------------------------------------------------------------+
```

- **宽窄屏自适应**：宽屏下同一主题内的图表两两并排；窗口宽度不足（如 panel 模式或移动端）时自动自适应为单列纵向排列；
- 三个主题区块始终按上述顺序展开，不提供折叠：总共 6 张图，单页即可完整呈现；
- **下钻明细在被点击的图表下方展开**，而不是固定在页面底部，避免点击后发生大幅滚动。

## 4. 主题一：可靠性

**KPI 磁贴**：
- 成功率：`status < 400` 的调用数 / 总调用数；
- 429 次数、5xx 次数。

### 图表 1.1：错误率排行
- **排序**：`GROUP BY <维度> ORDER BY 错误率 DESC`；
- **口径**：分母沿用原设计总调用数。分子为 `429 + 5xx + 其他 4xx`。**499 明确排除在错误分子之外**（499 为客户端主动断开连接，不计入服务端或供应商故障）；
- **展示**：条形按错误类型分段着色（429 橙、5xx 红、其他 4xx 灰），条尾标注次数；
  ```text
  claude-3-5-haiku   ██████████████████████ 8.4% (429: 21, 5xx: 3)
  gpt-5.5            ████████               3.1% (429: 5)
  deepseek-chat      ██                     0.8% (5xx: 1)
  ```
- **维度说明**：供应商维度仅为 `provider` 名称，不拆分账号。

### 图表 1.2：异常趋势
- **定位**：本主题内唯一的非排行图，用于直观查看异常发生的时间分布；
- **逻辑**：X 轴为时间桶，桶的粒度与用量页一致（Today 按小时、7d/30d 按天、All 按周），每个桶一根堆叠柱，按 429 / 5xx / 其他 4xx 分色；
- **交互边界**：**只读展示，不可点击，不与其他图表联动**。不提供点击柱子按时间桶过滤，也不在点击实体条形时切换趋势过滤。

## 5. 主题二：响应速度

**KPI 磁贴**：
- 端到端 TTFT P95（全局视角流式首字耗时）；
- 解码速度（全局有效流式输出速度，单位 `tok/s`）。

### 图表 2.1：端到端 TTFT P95 排行
- **排序**：`GROUP BY <维度> ORDER BY P95(ttft_ms) DESC`（最慢在上）；
- **口径**：仅统计成功且有首字记录的流式调用（`TTFT > 0` 且 `Status < 400`），门槛为有效样本 ≥ 10 次；
- **展示**：主条形展示 P95 端到端 TTFT，条尾标注 P50 参考值：
  ```text
  qwen-max           ██████████████████████ P95 2,450ms · P50 900ms
  gpt-5.5            ████████████           P95 1,280ms · P50 520ms
  deepseek-v3        ███                    P95 310ms   · P50 180ms
  ```

### 图表 2.2：解码速度排行
- **排序**：`GROUP BY <维度> ORDER BY tok/s ASC`（输出最慢的排在最前）；
- **口径**：严格沿用现有用量页 `Totals.Speed()` 计算口径：
  - 有效样本严格限制为 `TTFT > 0`、`Status < 400`、`Output > 0` 且 `Millis > TTFT`；
  - 速度 = `累计 DecodeOut / (累计 DecodeMs / 1000)`，单位 `tok/s`；
  - 有效样本数 ≥ 10 次；
- **展示**：条形长度代表速度值，条尾标注实际 `tok/s`。

## 6. 主题三：成本与缓存

**KPI 磁贴**：
- 周期总成本（估算金额）；
- 缓存率（当前界面口径）与写入 Token 标注。

### 图表 3.1：成本排行
- **排序**：`GROUP BY <维度> ORDER BY 成本 DESC`（花销最多排在最前）；
- **口径**：沿用用量页定价规则（按 models.dev 列表价估算），无价格记录的调用计入末尾「未定价」行；
- **展示**：条尾标注占当前筛选后总成本的百分比。

### 图表 3.2：缓存率排行
- **排序**：`GROUP BY <维度> ORDER BY 缓存率 ASC`（缓存效果最差的排在最前）；
- **口径**：严格对齐现有用量界面口径（`app.js` 5376-5378 行）：
  $$\text{缓存率} = \frac{\sum \text{cache\_read}}{\sum \text{input} + \sum \text{cache\_read}}$$
  - **`cache_write` 严格单独呈现，绝不加入命中率分母**；
  - 完整提示词总量（`input + cache_read + cache_write`）仅作为单独附注展示，严禁将命中率分母误称为完整提示词；
  - 分母 `input + cache_read == 0` 时，显示为 `—`；
  - 有效输入门槛：`input + cache_read ≥ 10k Tokens`；
- **全零实体分类（无缓存记录 / 未知）**：
  若某实体的 `cache_read == 0` 且 `cache_write == 0`，统一归入末尾「无缓存记录 / 未知」行，不参与主排序；
- **展示**：条尾单独标注输入量 `input` 与缓存写入量 `cache_write`，辅助判断优化价值；缓存率计算仍沿用上述界面口径：
  ```text
  Codex              ███                    12% (未命中 14.2M tok · 写入 2.1M)
  Claude Code        ██████████             58% (未命中 5.8M tok · 写入 800k)
  Pi                 ██████████████████     88% (未命中 1.1M tok · 写入 150k)
  未报告缓存 (2 项)
  ```

## 7. 分析模式与图表的关系

顶部模式切换器共四个选项：`[ 全部 ]` `[ 按模型 ]` `[ 按供应商 ]` `[ 按客户端 ]`。
分析模式仅为前端视图切换展现逻辑，底层统一调用服务端接口进行完整数据集聚合。

### 7.1 按维度分组模式
选中某个维度时，所有排行图的 GROUP BY 对象随之切换，另外两组维度转为筛选器：

| 选中的分析维度 | 图表分组实体 (Y轴) | 筛选下拉项 1 | 筛选下拉项 2 |
| :--- | :--- | :--- | :--- |
| **按模型** | 模型名称 (`model`) | `[全部供应商 ▾]` | `[全部客户端 ▾]` |
| **按供应商** | 供应商名称 (`provider`) | `[全部模型 ▾]` | `[全部客户端 ▾]` |
| **按客户端** | 客户端标识 (`agent`) | `[全部模型 ▾]` | `[全部供应商 ▾]` |

*注：现有数据无账号字段，供应商维度仅为供应商本身。*

### 7.2 全部（不分组）模式
不指定分析维度时，统计整个周期内（经筛选后）的全局调用指标：

- **筛选器**：模型、供应商、客户端三组维度都作为筛选器出现；
- **排行图退化为单数字卡片**：各排行图退化为单数字卡片展示：

  | 图表 | 全部模式下的单数字卡片 |
  | :--- | :--- |
  | 1.1 错误率排行 | `错误率 3.2%`（429: 26 · 5xx: 4 · 其他 4xx: 1） |
  | 2.1 端到端 TTFT P95 排行 | `端到端 TTFT P95 1.2s`（P50 520ms） |
  | 2.2 解码速度排行 | `解码速度 52 tok/s` |
  | 3.1 成本排行 | `总成本 ≈$12.40` |
  | 3.2 缓存率排行 | `缓存率 64.2%`（未命中 22.1M tok · 写入 1.2M） |

- **去重规则**：单数字卡片与主题顶部的 KPI 磁贴指标重合时（2.1、2.2、3.1、3.2），只保留 KPI 磁贴，将卡片附注与下钻行为合并进该磁贴，同一个数字只展示一次；
- **异常趋势（1.2）不变**：按时间分桶展示，全部模式下展示全局堆叠柱状图；
- **最小样本门槛不适用**：样本为 0 时卡片显示 `—` 与“本周期内无数据”；
- **下钻**：点击单数字卡片或对应区域，展开该指标的全局明细（不附加实体过滤）。

### 7.3 默认模式
进入分析看板时默认为 **全部** 模式：先看全局健康度，再切到具体维度排查拖后腿的实体。

## 8. 通用条形图点击下钻交互规范

1. **点击单根条形**（全部模式下为点击单数字卡片）：将该实体与已有筛选条件合并（全部模式下不附加实体条件）；
2. **原地展开**：在被点击的图表下方就地展开「最近调用明细列表（最多 50 条）」：

   | 主题 | 所点图表 | 明细列表排序与过滤口径 |
   | :--- | :--- | :--- |
   | 可靠性 | 1.1 | 仅失败调用（`Status >= 400` 且排除 499），时间倒序 |
   | 可靠性 | 1.2 (异常趋势) | **只读图表，不支持点击下钻** |
   | 响应速度 | 2.1 | 仅限成功流式调用（`TTFT > 0` 且 `Status < 400`），按 `ttft_ms` 从慢到快 |
   | 响应速度 | 2.2 | 仅限有效解码调用，按 `tok/s` 从慢到快 |
   | 成本与缓存 | 3.1 | 按单次调用成本从高到低 |
   | 成本与缓存 | 3.2 | 按未命中输入量 `input` 从大到小 |

3. **服务端筛选与截断**：
   - 下钻请求接口为 `GET /api/analytics/calls`，参数包括 `period`、`model`、`provider`、`agent`、`chart_id`、`limit`（默认且最多 50 条）；
   - 服务端在账本全量记录上先完整应用条件过滤与排序，最后截取前 50 条返回，绝不在内存浅层截断后再排序；
4. **单处展开**：同一时刻整个看板仅允许一处展开明细，点击另一图表时原展开自动关闭；
5. **滚动绝对锁定**：展开与收起严格使用点击锚点与 `ResizeObserver` 动态补偿计算，禁用 `scrollIntoView`，杜绝任何页面跳跃抖动。

---

## 9. 决策结论

- **指标与维度收敛**：完全基于现有 `usage.Record` 账本字段（`model`、`provider`、`agent`），彻底剔除账号、网关前置等待、真 TTFT（落地节点分离）等需改造网关的数据；
- **图表精简为 6 张**：1.1 错误率排行 (DESC)、1.2 异常趋势 (只读)、2.1 端到端 TTFT P95 排行 (DESC)、2.2 解码速度排行 (ASC)、3.1 成本排行 (DESC)、3.2 缓存率排行 (ASC)；
- **交互边界确立**：趋势图只读不联动；条形图与全部卡片支持原地结合已有筛选下钻最近 50 条明细；无直方图或状态切片下钻。
