MothX on any model

MothX (OSCHINA's oschina/mothx, the mothx command, formerly vibecoding) is a coding agent in the terminal, written in Go. Its providers and the model it starts on are in one settings.json. magpie adds a provider named magpie and makes it the default, so MothX runs on any model in magpie: DeepSeek, GLM, Kimi, Qwen, Claude or a ChatGPT subscription.

Set up MothX

  1. Add a provider in magpieAdd an API key on the Providers page, or sign in to a subscription.
  2. Pick a model for MothX on the Agents pagePick a model via magpie, and a thinking level if you want one.
  3. Restart MothXMothX reads its settings when it starts, so an open session keeps its model until it starts again.
Terminal
magpie mothx deepseek/deepseek-v4-pro

settings.json

The config folder is $MOTHX_DIR, else %APPDATA%\mothx on Windows and ~/.mothx elsewhere. What magpie writes:

Terminal
{
  "defaultProvider": "magpie",
  "defaultModel": "deepseek/deepseek-v4-pro",
  "defaultThinkingLevel": "high",
  "providers": {
    "magpie": {
      "baseUrl": "http://127.0.0.1:3425/v1",
      "api": "openai-chat",
      "apiKey": "",
      "thinkingFormat": "openai",
      "models": [
        { "id": "deepseek/deepseek-v4-pro", "name": "…", "reasoning": true,
          "input": ["text"], "contextWindow": …, "maxTokens": …,
          "cost": { "input": …, "output": …, "cacheRead": …, "cacheWrite": … } }
      ]
    }
  }
}

MothX asks the default provider for the default model on that provider's api: openai-chat is baseUrl plus /chat/completions, under Bearer apiKey. Each of magpie's models is one entry, with whether it reads images, its context window, its cap on a reply and its price per million tokens; without them MothX takes its own default window and cap, and can't count a turn's cost. Headers or an httpProxy you put in magpie's provider stay, and your own providers aren't touched. MothX in a WSL distro is set up the same way, in ~/.mothx there.

Thinking levels

defaultThinkingLevel is the level a session starts at: off, minimal, low, medium, high, xhigh or max, narrowed to the ones a model takes when magpie knows them. MothX sends a level only for a model whose entry says reasoning is true. magpie writes thinkingFormat: "openai", so MothX asks every model as reasoning_effort, which the gateway carries to each vendor's own form. Without it MothX guesses the vendor from the model id and the address: a model named qwen… got Qwen's enable_thinking, a deepseek… one only thinking:{type:enabled}, whatever served it. A thinkingFormat you already set is left alone.

Restart MothX

MothX reads settings.json at start-up, so a running MothX needs a restart; magpie tells you when a mothx or vibecoding process is running. MothX's own /model and /auth dialogs write the whole file back, and magpie's settings survive that. Its requests say Vibecoding Client/<version> as their User-Agent, and Usage counts them as MothX.

Switching back

Switching back takes out defaultProvider, defaultModel and providers.magpie, and a providers object left empty. When the file then says the same as before magpie's first write, the original file is put back byte for byte.

Terminal
magpie mothx default

FAQ

Can MothX run on DeepSeek, GLM or a ChatGPT subscription?

Yes. Pick a via-magpie model for MothX on magpie's Agents page, then restart MothX.

Does this work for vibecoding too?

Yes. vibecoding is MothX's old name; magpie takes it for MothX, with the same settings.json.

How does the thinking level reach the model?

magpie sets thinkingFormat to openai, so MothX sends reasoning_effort, which the gateway turns into each vendor's own form.

Does switching back restore my settings?

Yes. magpie takes out the default and the provider it added; when the file says the same as before, the original is put back as it was.
