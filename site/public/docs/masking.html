Privacy masking

magpie can mask what your agents send before it leaves this computer. API keys, passwords and tokens, and when you ask, emails, phone numbers and words of your own, go to the vendor as placeholders such as {{API_KEY_es6eu6jk}}. In the reply each placeholder turns back into its value, so your agent and your files keep the real thing and the vendor never sees it. It runs on this computer, in magpie’s gateway, and is off by default.

It covers what goes through magpie. An agent connected to magpie sends its requests through the gateway, and they are masked whichever provider or account answers. An agent that calls a vendor directly, not through magpie, is not covered.

Turn it on

  1. Open the pageGo to Settings → Privacy.
  2. Mask secretsUnder What to mask, set Mask secrets to On: API keys, private keys, tokens and passwords.
  3. Personal data, if you want itSet Mask personal data to On for emails, phone numbers, ID and bank card numbers. Each further kind of personal data then gets its own switch below it.
  4. Your own wordsIn Masked words, list names, codenames or hosts to keep from vendors, one on each row (several pasted with commas between become a row each). Masked words in any case makes Nightjar mask NIGHTJAR too. A secret magpie doesn’t know, such as your gateway’s own keys, goes under Masking rules: what it starts with, or a regular expression.
  5. Try itPaste a text into Try it to see exactly what the vendor would get. What you paste there isn’t kept.

It applies from the next request, with no restart and nothing to change in your agent. The work is done by the built-in plugin Privacy masking (redact, in Settings → Plugins), which is on whenever any masking is asked for.

There is no CLI command for it. Without the window (magpie serve, Docker), open the same page with magpie web, or set it in ~/.config/magpie/settings.json (/config/magpie/settings.json in Docker). The masker reads the file on every request:

settings.json 
{
  "redact": true,
  "redactPersonal": true,
  "redactWords": ["Nightjar", "db.acme-corp.cn"]
}

What is masked

SwitchWhat it finds
Mask secretsPrivate key blocks (-----BEGIN … PRIVATE KEY-----). API keys by their shape: sk-… (OpenAI, Anthropic, OpenRouter), ghp_/github_pat_, glpat-, AIza…, xox…-, sk_live_, AKIA/ASIA, hf_, gsk_, xai-, npm_, pypi-, dop_v1_, SG., and relay keys like oc_sk_…. JWTs. The password in user:password@host. The value of a field named for a secret, as .env files and configs have them: DB_PASSWORD=…, api_key: …, client_secret, token, credential. Your own Masking rules. Wallet private keys by the shape their wallets export: a Bitcoin WIF, a BIP32 xprv, an Ethereum or TRON 0x key, a Solana key or id.json keypair, a Sui suiprivkey1…, an Aptos ed25519-priv-0x…, a Stellar seed, a NEAR ed25519:… key, a Nostr nsec1…, an age identity, a Zcash extended spending key, and a 12 to 25 word seed phrase after seed or mnemonic whose every word is in the BIP39 list. A key with no prefix of its own is masked only when it checks out: a WIF or xprv by its checksum, a Solana key by its public half, a Stellar seed by its CRC, so a Solana transaction signature goes as written. A 0x key has the shape of a transaction hash, so it is masked only after a key’s name (PRIVATE_KEY=, --private-key, new Wallet(…), 私钥); a hash, a storage slot or a sha256 sum goes as written. An exchange’s API key, secret and passphrase go by their fields’ names.
Mask personal dataEmails, mainland China mobile numbers (not an 11-digit id: one under order_id or after 订单号 goes as written), Chinese ID numbers and bank card numbers whose checksum adds up. Also on by default: US Social Security numbers, passport numbers (after passport, 护照 or パスポート), IBANs, birthdays (next to birthday, DOB or 生日, and over a year ago, so today’s date stays), MAC addresses and serial numbers (after S/N). Off until you turn them on, since agents send them in nearly every request: the user name in home folders (sent as a made-up name, the same every turn, so the model reads a real folder rather than a placeholder), user and computer names (user@host), public IP addresses (sent as a name such as public-ip-kvxqmrtz, so the model still knows the address is public and connects with it, and the real address goes back into its commands) and cloud storage buckets. A wallet or contract address (0x and 40 hex digits) is public and goes as written; a private key is still masked.
Masked wordsEach word you listed, exactly, as {{TERM_…}}. A date, such as 1990-05-12, matches that day however it is written: 1990/5/12, 1990.05.12, 1990年5月12日, 19900512, May 12, 1990, and 13/05/1990 style only where the day can’t be read as a month. Never another date or a version like 1990.5.12.1.
Find with a local modelUnder How it’s found. A model on this computer finds what no rule can: a name or an address in free text. It is on unless you turned it off, and AstrLink Guard downloads with the first masked request; until it is on disk, the rules mask alone. It needs Mask secrets or Mask personal data on, and finds under the same switches. The menu beside it picks the model: AstrLink Guard (Chinese and English, a 39 MB download, few false alarms in code, on a Mac it runs on the Neural Engine; the default) or OpenAI’s Privacy Filter (1.6 GB, uses the GPU, masks more ordinary values in code). Confidence threshold under it is how sure the model must be before a value is masked: Privacy Filter’s default is 0.5, AstrLink Guard’s 0.8, its publisher’s. Higher masks fewer ordinary values, and lets more real names and addresses through: the rules after the model drop most false alarms already, so the default is where we measured the fewest real values lost.

A placeholder is the kind plus eight characters of a keyed hash. The same value gets the same placeholder every time, so the conversation reads the same turn after turn and the vendor’s prompt cache stays valid. The values are held in memory only.

An example

With Mask secrets and Mask personal data on and Nightjar in Masked words, your agent sends:

Your agent sends 
Deploy Nightjar with OPENAI_API_KEY=sk-proj-8fK2mQx7Lp4Rt9Vw3Yz6Ab1Cd, then mail li.wei@acme-corp.cn or call 13800138000.
The vendor gets 
Deploy {{TERM_5hmsrhdc}} with OPENAI_API_KEY={{API_KEY_srhjgvja}}, then mail {{EMAIL_eh5um6mb}} or call {{PHONE_uf7iy2qq}}.

When the model answers “I set OPENAI_API_KEY to {{API_KEY_srhjgvja}} in .env”, your agent reads the real key there, in streamed text and tool-call arguments alike, so the file it writes has the real key. A placeholder the model rewrote a little (spaces inside the braces, another case) is still turned back.

Check that it works

  • Before: Try it on Settings → Privacy shows the text as the vendor would get it, with each value’s kind.
  • Each request: a shield badge with a count appears on the request in the Gateway page’s recent calls and in the Routing log. Point at it for the kinds; click it to open the request’s record.
  • Over time: Insights → Masking (also What was masked on the Privacy page) shows the values masked over 7 or 30 days by kind, agent and provider, and each request’s text as the vendor saw it, placeholders marked.

The records are kept in ~/.config/magpie/masking for 30 days: the agent, provider, model, and each placeholder’s kind, length and first characters, never the value.

When a value is found

Under When a value is found, choose per kind:

  • Mask (the default): sent as a placeholder.
  • Warn: sent as written, and the badge counts it in amber.
  • Block: the request is held back with a 400, “magpie held this request back: Settings › Privacy blocks API_KEY, and it has one (sk-…, 33 characters). Nothing was sent.” The message never has the value.

A value the task needs as it is, such as a team address or a test key, goes in Never mask: it is sent as written wherever it is found whole.

What it leaves alone, and limits

  • Thinking stays as the vendor wrote it. A thinking block with its signature, Gemini’s thoughts and Responses’ encrypted reasoning are sealed by the vendor and go back unchanged, so the signature still matches. Only values already masked elsewhere in the request are swapped in them.
  • Ids and tool definitions go as written: model ids, message and call ids, UUIDs, tool names, MCP server names, and tool schemas (their descriptions are masked), so a vendor or a tool can still check them.
  • Images and file data are sent as they are. Text inside a screenshot is not masked.
  • It fails closed. If masking is on and can’t run (the Privacy masking plugin turned off by hand, or the local model you turned on can’t answer), the request gets a 503 that says nothing was sent. It is never sent unmasked instead. The model on by default that can’t answer leaves the rules to mask alone.
  • A provider can skip it. Send requests unmasked on a provider sends its requests as written: a model on this computer or your local network (Ollama, LM Studio), and, if you choose, any other provider, a subscription or a plugin’s provider too. Turned on for one that isn’t local, the editor says its vendor gets your requests unmasked. A request that can fall back to a provider still masked is masked. magpie provider set ollama unmasked=yes does the same.
  • Or send what masking would change to one of them. In Settings › Privacy, Instead of masking, send to picks such a model. An agent’s request that masking would change then goes to it as written, so it can answer about the real names, and a request with nothing to mask goes where it was going. If that model fails, the request fails: it is never masked and sent to a vendor instead. Off by default.
  • The model sees placeholders. It can’t read or reason about a masked value; it can only pass it on. Put a value it must read under Never mask.
  • Rules find shapes. A phone number in another country’s format or a name in free text needs Find with a local model, or your own Masked words and Masking rules. Try your own text in Try it first.
