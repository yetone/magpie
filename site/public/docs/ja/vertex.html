Google Vertex AI を Claude Code・Codex などのエージェントで使う

Google Vertex AI（Google のドキュメントでは現在 Gemini Enterprise Agent Platform）は、自分の Google Cloud プロジェクトで Gemini を提供し、そのプロジェクトに課金されます。DeepSeek・GLM・gpt-oss などのパートナーモデルやオープンモデル、Anthropic の Claude も提供します。magpie の google-vertex プリセットは、これらを API キーなしで Claude Code・Codex・OpenCode などにつなぎます。各リクエストは Google の認証情報から作ったトークンで署名されます。

追加する

  1. API を有効にする。プロジェクトで Agent Platform API（aiplatform.googleapis.com）を有効にします。課金が有効である必要があります。
  2. サインインする。gcloud auth application-default login を実行するか、サービスアカウントのキーファイルを用意します。
  3. 追加してテストする。プロジェクト ID を指定してテストします。
ターミナル
gcloud auth application-default login
magpie provider add google-vertex project=my-project
magpie provider test google-vertex

アプリのエディターでは プロジェクト ID・ロケーション・認証ファイル・権限借用 で同じ内容を入力します。TUI の a はプロジェクトだけを聞き、残りは CLI で設定します。追加・一覧・表示では Google に問い合わせず、認証情報はリクエストの署名時に読みます。続いてエージェントのモデルを選びます。

ターミナル
magpie claude google-vertex/claude-sonnet-5-5
magpie codex google-vertex/gemini-3.1-pro-preview

ロケーション・認証情報・サービスアカウント

ターミナル
magpie provider set google-vertex location=us-central1        # global (default), us, eu or a region
magpie provider set google-vertex credentials=~/keys/vertex.json
magpie provider set google-vertex impersonate=vertex@my-project.iam.gserviceaccount.com
magpie provider set google-vertex impersonate=                # empty clears it
  • location= は global（既定。空にするとこれに戻る）、us、eu、または us-central1 などのリージョンです。
  • credentials= は gcloud のサインインの代わりに使う認証ファイル（サービスアカウントのキーなど）です。相対パスはコマンドを実行したフォルダーから補われます。
  • impersonate= はそのサービスアカウントとしてリクエストします。サインインしたアカウントに、そのアカウントの Service Account Token Creator ロールが必要です。
  • キーやアドレス（url= など）は拒否されます。トークンの送り先はプロジェクトとロケーションで決まる 1 つだけです。

ロケーションごとのモデル

ロケーションごとに提供されるモデルが違い、Vertex AI には問い合わせられる一覧がないため、magpie は各ロケーションに実際に応答したモデルを用意しています。

  • global：Gemini（gemini-3.8-flash、gemini-3.1-pro-preview、gemini-2.5-pro など）、3 つのパートナーモデル、claude-opus-5-5・claude-sonnet-5-5・claude-haiku-5-5 などの Claude。
  • us・eu：3.8・3.7・3.6・3.5 の Flash と gemini-3.5-flash-lite・gemini-3.1-flash-lite。
  • リージョン：gemini-2.5-pro・gemini-2.5-flash・gemini-2.5-flash-lite。

asia-northeast1 の gemini-3.5-flash のように、リージョンがもう 1 つ提供している場合は、使いたいモデルと一緒に入力します。ロケーションを変えても選んだモデルはそのままなので、変えたあとに選び直してください。

パートナーモデル

パートナーモデルの ID はスラッシュの前に提供元が入ります（deepseek-ai/deepseek-v4.1-flash-maas、zai-org/glm-5.2-maas、openai/gpt-oss-120b-maas）。magpie は同じ認証情報で、プロジェクト内の Google の OpenAI 互換 Chat Completions に問い合わせます。設定は不要です。ほかのモデル（プレビュー版や後から公開されたもの）は完全な ID で入力します。

ターミナル
magpie provider models google-vertex gemini-3.8-flash deepseek-ai/deepseek-v4.1-flash-maas google/gemma-4-26b-a4b-it-maas
magpie provider models google-vertex all     # back to the location's list
magpie provider test google-vertex zai-org/glm-5.2-maas

各パートナーモデルは、先にプロジェクトの Model Garden で有効にしてください。それまでは Google が拒否します。magpie provider test google-vertex は Gemini をテストします。パートナーモデルは単独で、アプリで右クリックするか、コマンドのあとにモデル ID を付けてテストします。

Vertex AI の Claude

ID が claude- で始まるモデルは、プロジェクト内の Anthropic の Messages API（streamRawPredict）に問い合わせます。Claude Code が CLAUDE_CODE_USE_VERTEX で問い合わせるのと同じで、追加の設定は不要です。どの API を話すエージェントでも使え、Codex や OpenCode も使えます。

  • global には、Claude Code が Vertex AI で使う ID で現在のモデルが並びます。
  • 古いモデルは claude-sonnet-4-5@20250929 のような日付付きの Vertex の ID で入力します。
  • ほかのロケーション（us-east5、europe-west1）では、そこで提供される Claude を入力します。
  • パートナーモデルと同じく、各 Claude は先に Model Garden で有効にし、単独でテストします。

Priority PayGo と Flex PayGo

Google の Priority PayGo と Flex PayGo はリクエストヘッダーで指定します。エディターの ヘッダー に X-Vertex-AI-LLM-Request-Type と X-Vertex-AI-LLM-Shared-Request-Type があり、値は Google のページのとおりです。CLI では次のようにします。

ターミナル
magpie provider set google-vertex header.=

よくあるエラー

  • no Google credentials at <file>：そこに認証ファイルがありません。自分で設定した credentials= なら直すか、credentials= だけで消します。それ以外は gcloud auth application-default login を実行します。
  • GOOGLE_APPLICATION_CREDENTIALS names <file>, which isn't there または … not a full path：この環境変数が読めないファイルを指していて、代わりに gcloud のものは読まれません。完全なパスにするか、変数を外すか、credentials= を設定します。
  • the sign-in was refused：サインインが期限切れか取り消されています。案内のコマンド（gcloud auth application-default login など）を実行してください。再起動なしで次のリクエストから新しいファイルを読みます。
  • aiplatform.endpoints.predict を含む 403 PERMISSION_DENIED：署名するアカウント（またはその借用先のサービスアカウント）がプロジェクトで Vertex AI を使えません。プロジェクトで Agent Platform User（roles/aiplatform.user）を付与します。
  • impersonating …: the sign-in was refused (403)：サインインしたアカウントに、そのサービスアカウントの Service Account Token Creator（roles/iam.serviceAccountTokenCreator）が必要です。

よくある質問

magpie で Vertex AI を使うのに API キーは必要ですか？

不要です。gcloud のアプリケーションのデフォルト認証情報、サービスアカウントのキーファイル、または借用したサービスアカウントで各リクエストに署名します。キーは拒否されます。

Claude Code から magpie 経由で Vertex AI の Claude を使えますか？

使えます。claude- のモデルは CLAUDE_CODE_USE_VERTEX と同じく Anthropic の Messages API に問い合わせ、Codex や OpenCode からも使えます。先に Model Garden で有効にしてください。

ロケーションを変えたらモデルが変わったのはなぜ？

ロケーションごとに提供モデルが違います。global が最も多く、us と eu は新しい Flash、リージョンは 2.5 系です。ほかは magpie provider models google-vertex で入力します。

403 PERMISSION_DENIED が出たら？

署名するアカウントにプロジェクトの Agent Platform User（roles/aiplatform.user）が必要です。サービスアカウントを借用するなら、そのアカウントの Service Account Token Creator も必要です。
