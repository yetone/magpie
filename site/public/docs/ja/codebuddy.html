CodeBuddy を任意のモデルで

CodeBuddy は Tencent の AI コーディングツールで、CLI の CodeBuddy Code（codebuddy、cbc）と CodeBuddy IDE があります。国際版（codebuddy.ai）も中国版（codebuddy.cn）もカスタムモデルを受け付けます。magpie はそこに magpie のモデルを書き込むので、CodeBuddy で DeepSeek、GLM、Kimi、Qwen、OpenAI や Anthropic のキー、ChatGPT や Copilot のサブスクリプションが使え、それらのモデルに CodeBuddy へのサインインは要りません。

CodeBuddy Code は両版共通の npm パッケージ @tencent-ai/codebuddy-code で、中国版は CODEBUDDY_INTERNET_ENVIRONMENT=internal で区別されます。どちらも ~/.codebuddy/models.json（CODEBUDDY_CONFIG_DIR があればそこ）からカスタムモデルを読み、CodeBuddy IDE も同じファイルを読みます。そのため magpie の CodeBuddy の行は一つで、CLI と IDE の両方に効きます。

CodeBuddy の設定

  1. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  2. CodeBuddy の行でモデルを選ぶエージェント ページで magpie のモデルを選びます。magpie はすべてのモデルを models.json に、選んだものを settings.json の model に書きます。
  3. 新しいセッションを始めるCodeBuddy Code はセッション開始時にモデルを読みます。codebuddy を再起動するか、開いているセッションで /clear を実行します。
ターミナル
magpie codebuddy deepseek/deepseek-v4-pro
magpie codebuddy            # 現在の設定を表示

models.json

magpie が書く各モデルはこのコンピューターの magpie ゲートウェイを指し、magpie が CodeBuddy に渡す Bearer キーで呼ばれます。CodeBuddy は Tencent のサーバーを通さず直接そこへリクエストし、CodeBuddy のサインインは要りません。

ターミナル
{"models": [{
  "id": "deepseek/deepseek-v4-pro", "name": "DeepSeek V4 Pro", "vendor": "magpie",
  "apiKey": "…", "url": "http://127.0.0.1:3425/v1/chat/completions",
  "maxInputTokens": …, "maxOutputTokens": …,
  "supportsToolCall": true, "supportsImages": …, "reasoning": {…}
}, …]}

maxInputTokens と maxOutputTokens は magpie のカタログから来ます。maxOutputTokens がないと CodeBuddy は自分の既定値で返答を切ります。思考するモデルにはレベル（supportedEfforts、defaultEffort）が、思考を切れるものには canDisableThinking が付き、200K を超えるコンテキストのモデルは contextWindow で二つのサイズを選べます。ファイルの変更は再起動なしで反映されます。

CodeBuddy Code

CLI では、セッション開始時のモデルは settings.json の model です。models.json の magpie のモデル id でも、CodeBuddy 自身のモデルでも構いません。magpie はキーで CodeBuddy のリクエストを見分けるので、使用量は CodeBuddy として記録されます。

CodeBuddy IDE

CodeBuddy.app（codebuddy.ai）と CodeBuddy CN.app（codebuddy.cn）は同じ ~/.codebuddy/models.json を読み、ファイルを監視して変更時にモデル一覧を同期し、magpie のモデルを IDE のモデル選択に並べます。IDE に CLI は要らず、IDE だけでも magpie に CodeBuddy の行が出ます。違いは二つ：IDE は CODEBUDDY_CONFIG_DIR に関係なくホームの .codebuddy を読み、settings.json の model は読まないので、モデルは IDE で選びます。

自分のモデル

models.json に自分で追加したモデルはそのまま残り、magpie は自分のモデルだけを元の位置で更新します。CodeBuddy で無効にした magpie のモデルは無効のまま、設定した既定の思考レベルもモデルが対応している限り保たれます。ファイルに availableModels（表示するモデル）があれば magpie のモデルが加えられ、ほかの項目はそのままです。

WSL

Windows では、CodeBuddy Code を入れた WSL ディストリビューションに専用の行があり、ディストリビューション内の ~/.codebuddy/models.json に、そこから届くゲートウェイのアドレスとキーで書き込みます。そこでは CODEBUDDY_CONFIG_DIR は読まれません。

元に戻す

行で CodeBuddy 自身のモデルを選ぶと、magpie は models.json から自分のモデルを外し、settings.json の model を選んだものにします。ターミナルからは：

ターミナル
magpie codebuddy default

よくある質問

CodeBuddy で DeepSeek、GLM、Kimi、Qwen は使えますか？

使えます。magpie がカスタムモデルとして ~/.codebuddy/models.json に書き込み、CodeBuddy Code と CodeBuddy IDE のモデル一覧に表示されます。

magpie のモデルに CodeBuddy のサインインは必要ですか？

いいえ。このコンピューターの magpie ゲートウェイを、magpie が CodeBuddy に渡すキーで直接呼びます。

中国版や CodeBuddy CN でも使えますか？

使えます。CLI は両版で同じ npm パッケージで、CodeBuddy.app と CodeBuddy CN.app も同じ models.json を読むので、一つの行ですべてに効きます。

モデルを変えても反映されません。

CodeBuddy Code はセッション開始時にモデルを読みます。codebuddy を再起動するか /clear を実行してください。IDE ではモデル選択で選びます。

同じモデルを他のエージェントでも：Claude Code で他のモデル、Kimi Code を任意のモデルで、Qwen Code を任意のモデルで、T3 Code を任意のモデルで。Tencent Cloud のモデルは Tencent Cloud。ノートでも同じモデルを：Obsidian を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
