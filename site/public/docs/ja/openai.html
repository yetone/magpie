OpenAI を Claude Code・Codex・Gemini CLI・OpenCode で使う

OpenAI は api.openai.com で二つの API、Responses と Chat Completions を提供しています。OpenAI 自身のモデルは Responses で使うのがよく、最新のモデルはそこでしか答えません。OpenAI の API キーを magpie に一度追加すれば、Claude Code・Codex・Gemini CLI・OpenCode などつないだすべてのツールが、magpie のゲートウェイ 127.0.0.1:3425 経由で OpenAI のモデルを使えます。ツールごとに別のモデルを選べます。Codex のリクエストはそのまま OpenAI に送り、ほかのツールのリクエストは途中で magpie が変換します。

このページは platform.openai.com の API キーについてです。ChatGPT Plus や Pro のサブスクリプションは別にサインインします。サブスクを任意のエージェントで を見てください。

OpenAI を追加する

  1. キーを取得platform.openai.com で作ります。sk- で始まります。
  2. プロバイダを追加magpie の プロバイダ で ＋ プロバイダを追加 を押し、OpenAI を選んでキーを貼り付け、保存します。magpie がそのキーで使えるモデルを OpenAI に問い合わせます。
  3. ツールで選ぶエージェント タブで、ツールの行のモデルを押し、gpt-6.1-sol などの OpenAI モデルを選びます。
ターミナル
magpie provider add openai <key>
magpie provider test openai

magpie のモデル ID は プロバイダ/モデル の形なので、OpenAI のモデルは openai/gpt-6.1-sol のようになります。前がプロバイダ、後ろが OpenAI 自身の ID です。キーは magpie の設定に保存され、magpie がシェルから読むことはありません。

OpenCode など magpie が取り込めるアプリで OpenAI をもう設定してあるなら、取り込むときに OpenAI プロバイダとして入ります。

エンドポイント

APIアドレス用途
Responseshttps://api.openai.com/v1OpenAI 自身のモデル（ID が gpt-、codex、または o と数字で始まるもの）：Codex はそのまま、Claude Code・Gemini CLI・OpenCode は変換して
Chat Completionshttps://api.openai.com/v1モデル一覧と、キーで使えるそれ以外のモデル

magpie の OpenAI プロバイダには Anthropic Messages のアドレスがないので、Claude Code のリクエストは常に変換します。OpenAI 自身のモデルは、Chat Completions を話すツールからでも magpie が Responses を先に使います。OpenAI があるモデルは /v1/responses でしか提供していないと答えると、magpie はそちらで問い合わせ直し、それを覚えます。モデルごとに API を自分で決めるには：

ターミナル
magpie model api openai/gpt-5.5 chat
magpie model api openai/gpt-5.5 --reset
magpie model apis openai

Azure OpenAI は別のプロバイダ、Azure OpenAI です。リソースのエンドポイント https://<resource>.openai.azure.com とキーを入れます。magpie は /openai/v1 以下の v1 API で Chat Completions と Responses を使い、キーを api-key ヘッダーで送り、リソースのデプロイをモデルとして並べます。gpt-5-codex のようにモデル名を付けたデプロイも、Responses を先に使います。

モデル一覧

magpie は一覧を OpenAI の https://api.openai.com/v1/models から取得するので、ツールにはそのキーで使えるモデルが並びます。名前・コンテキスト長・推論レベル・価格は models.dev の openai カタログから取ります。OpenAI が出したばかりでレベルがまだわからない推論モデルには、同じ系列の最新の推論モデルのレベルを使います。gpt-6.1-sol には gpt-6-sol のレベルが付きました。ツールに見せるモデルは、プロバイダのモデル一覧かターミナルで選べます。

ターミナル
magpie provider models openai +gpt-6.1-sol +gpt-6-luna +gpt-5.5
magpie provider refresh-every openai 1d

ツールごとの使い方

ターミナル
magpie claude openai/gpt-6.1-sol
magpie codex openai/gpt-6.1-sol
magpie gemini model openai/gpt-6.1-sol
magpie opencode openai/gpt-6.1-sol
  • Claude Code は Anthropic Messages を話しますが、OpenAI はこれを提供していません。magpie が各リクエストを Responses に変換し、返答を戻します。モデルの推論の要約は、Claude Code には思考として、続いて本文として届きます。Claude Code で他のモデル。
  • Codex は Responses を話すので、リクエストはそのまま OpenAI に送ります。apply_patch などのカスタムツール、推論のアイテム、Codex 自身の prompt_cache_key も含みます。ここでは Codex で Fast も選べます。推論 を見てください。Codex で他のモデル。
  • Gemini CLI は Google の Gemini API を話します。magpie が各リクエストを Responses に変換し、返答を戻します。Gemini CLI で他のモデル。
  • OpenCode は Chat Completions を話します。OpenAI 自身のモデルは Responses を先に使うので、magpie がリクエストをそちらに変換し、返答を戻します。キーで使えるそれ以外のモデルには、OpenCode のリクエストをそのまま送ります。OpenCode で他のモデル。

magpie が OpenAI のためにすること

  • プロンプトキャッシュのキー。変換して OpenAI に送るリクエストに prompt_cache_key がなければ、magpie が付けます。ツールが示すセッション、なければ最初のユーザーメッセージからハッシュで作るので、ツールについては何も明かしません。Codex が送るキーはそのまま使い、自分で設定したキーがあればそれが優先です。OpenAI がこのフィールドで 400 を返すと、magpie は外して問い合わせ直します。
  • 読み込んだ場所で渡すツール。Claude Code のツール検索が会話の途中で読み込んだツールは、ツール一覧に足すのではなく、読み込んだ位置に additional_tools のアイテムとして OpenAI の Responses API に送ります。キャッシュ済みの先頭部分がそのまま残ります。additional-tools=off にすると、ほかのツールと一緒に並べます。
  • よそで封印された推論。OpenAI が読めるのは自分で封印した推論（encrypted_content）だけです。別のキー・組織・アカウントで封印されたアイテムは拒否されます（“could not be verified”）。magpie はそのアイテムを外して問い合わせ直し、その会話について覚えます。Claude のモデルで一度動いたあとの Codex が推論アイテムに入れて持ち歩く Claude の思考は、リクエストが OpenAI に届く前に外します。
  • 前の返答。Responses のクライアントは、そのターンの新しい入力だけを送り、続く返答を指定できます（previous_response_id）。magpie はそうしたクライアントに返した返答をメモリに、呼び出し元のゲートウェイキーごとに保存します。OpenAI も返答を保存するので、指定された返答に同じキーで答えていれば、OpenAI には OpenAI 自身の ID のあとの新しい入力だけを送ります。HTTP で話す Codex は store を false にし、前の返答を指定しません。
  • Codex 自身の圧縮。compaction=native にすると、Codex の圧縮は Codex が送ったとおりに OpenAI に頼み、封印された圧縮アイテムはそのまま Codex に返します。読めるのは封印したキーだけなので、それを含むあとのリクエストはそのキーにだけ送ります。既定の compaction=magpie では magpie が要約します。
ターミナル
magpie provider set openai compaction=native
magpie provider set openai additional-tools=off

推論

  • 推論の強さ。ツールが求める推論の強さは、カタログにあるそのモデルのレベルのうち最も近いものに合わせます。gpt-6-sol には none・low・medium・high・xhigh・max があります。Responses では reasoning.effort として送り、summary を auto にするので、モデルの推論の要約も返ってきます。
  • 推論オフ。Gemini CLI のように magpie が変換するツールが推論をオフにし、モデルのレベルに none があるとき、magpie は none を求めます。
  • 暗号化された推論。ツールが include で求めるものは magpie がそのまま渡しますが、reasoning.encrypted_content を求めるのは推論があるときだけです。推論しないモデルにこれを付けると OpenAI が拒否します。Codex は封印されたアイテムを次のターンで送り返し、magpie はそれをそのまま渡します。
  • Fast。OpenAI のキーでは、Codex で GPT と o シリーズのモデルに Fast を選べます。magpie はこれを service_tier: "priority"、つまり OpenAI の優先処理として送ります。magpie で Codex に設定したサービス階層は、Codex の指定より優先します。

Web 検索

OpenAI の Responses API は自分で Web を検索します。Codex や Claude Code のようにツールがモデルに Web 検索を渡すとき、magpie は Responses でモデルに OpenAI 自身の web_search ツールを渡し、検索は OpenAI が行います。

費用・使用量

  • 費用。使用量 タブは、models.dev にある OpenAI の価格で呼び出しごとに費用を計算します。
  • キャッシュのトークン。返答がキャッシュ済みのプロンプトトークンを報告すると、使用量タブはそれをプロンプトの残りと分けて数えます。
  • キャッシュを生かす。キーが複数あるとき、会話のキャッシュに残す価値があり（1,024 トークン以上）、まだ温かい（5 分以内に読まれた）あいだは、その会話は同じキーを使い続けます。
  • サービス階層。呼び出しごとに、ツールが求めた階層、magpie が送った階層、OpenAI の返答が実際に使ったと言う階層を記録します。
  • 残高。magpie は OpenAI から残高を読みません。key-balance で自分で入力すると、使用量ページはそこから magpie がそれ以降のキーの呼び出しに付けた費用を引いて表示します。

複数のキーとフェイルオーバー

一つの OpenAI プロバイダに複数のキーを入れられます。その下の 別のキーを追加 を押すか、まとめて貼り付けます。リクエストはオンになっている最初のキーに行き、そのキーが尽きるかレート制限にかかると次のキーが引き継ぎます。二つの組織のキーのように分けておきたいときは、プロバイダをもう一度追加します。二つ目は openai-2 になります。

  • 支出上限。spend-cap で、キーごとに 1 日・1 か月・累計のドル上限を決められます。金額は使用量タブの計算で数え、上限に達するとルーティングはほかのキーとフォールバックに移ります。
  • フォールバック。fallback で、OpenAI の枠が尽きたときや落ちたときの行き先を決めます。別のプロバイダのモデルか、ルーティンググループです。
ターミナル
magpie provider spend-cap openai <key> 20 month
magpie provider key-balance openai <key> 25
magpie provider fallback openai deepseek/deepseek-v4-pro

うまくいかないとき

  • “The encrypted content for item rs_… could not be verified”。会話に、別のキー・組織・アカウントで封印された推論が含まれています。magpie はそのアイテムを外して問い合わせ直します。magpie がすること を見てください。
  • /v1/responses でしか答えないモデル。magpie が Responses に移し、それを覚えます。magpie model apis openai で、各モデルがどの API で問い合わせられるかがわかります。
  • prompt_cache_key で 400。magpie は自分で付けたキーを外して問い合わせ直します。
  • キーの確認。magpie provider test openai は各エンドポイントに、または指定した各モデルに小さなリクエストを送ります。--as codex や --as claude-code を付けると、そのツールと同じ形で送ります。

よくある質問

Claude Code で OpenAI のモデルを使うには？

magpie に OpenAI の API キーを追加し（プロバイダ、プロバイダを追加、OpenAI）、Claude Code の行で gpt-6.1-sol などのモデルを選ぶか、magpie claude openai/gpt-6.1-sol を実行します。OpenAI は Anthropic Messages API を提供していないので、magpie が Claude Code のリクエストを変換して OpenAI の Responses API https://api.openai.com/v1 に送り、返答を戻します。推論の要約は思考として届きます。

Codex で ChatGPT のサインインではなく OpenAI の API キーを使えますか？

使えます。キーを追加して magpie codex openai/gpt-6.1-sol を実行します。Codex は Responses を話すので、リクエストはカスタムツールや推論も含めてそのまま OpenAI に送り、Fast は優先処理として送ります。ChatGPT Plus や Pro のサインインは、サブスクリプションで別に設定します。

OpenCode で GPT モデルを使うには？

magpie でモデルを選ぶか、magpie opencode openai/gpt-6.1-sol を実行します。OpenCode は Chat Completions を話しますが、OpenAI 自身のモデルは Responses を先に使うので、magpie が OpenCode のリクエストをそちらに変換し、返答を戻します。Chat Completions で送りたいモデルには magpie model api openai/gpt-5.5 chat を実行してください。

Gemini CLI で OpenAI を使えますか？

使えます。Gemini CLI は Google の Gemini API を話すので、magpie がリクエストを OpenAI の Responses API に変換し、返答を戻します。ストリーミングとツール呼び出しも含みます。magpie gemini model openai/gpt-6.1-sol を実行してください。

magpie は OpenAI のプロンプトキャッシュを生かせますか？

生かせます。Codex 自身の prompt_cache_key はそのまま使います。キーのない変換リクエストには、セッションか最初のユーザーメッセージからハッシュで作ったキーを付けるので、ツールについては何も明かしません。キーが複数あるときは、キャッシュが温かいあいだ会話は同じキーを使い続けます。

OpenAI が encrypted content could not be verified と言うのはなぜ？

OpenAI が読めるのは、同じキー・組織・アカウントで封印した推論だけです。よそで封印された推論が会話に含まれていると、magpie はそのアイテムを外して問い合わせ直し、その会話について覚えます。

magpie は Azure OpenAI に対応していますか？

対応しています。別のプロバイダ、Azure OpenAI として使います。リソースのエンドポイントとキーを入れると、magpie は /openai/v1 以下の v1 API を使い、キーを api-key ヘッダーで送り、リソースのデプロイをモデルとして並べます。
