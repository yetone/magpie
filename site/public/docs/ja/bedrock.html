Amazon Bedrock を Claude Code・Codex などのエージェントで使う

magpie には Amazon Bedrock のプリセットが 2 つあります。Bedrock ランタイムの bedrock と、Bedrock の Mantle エンドポイントの bedrock-mantle です。どちらも同じ Bedrock API キーを使い、AWS のアクセスキーや SigV4 署名は不要です。追加すると、Claude Code・Codex・OpenCode などから Bedrock の Claude、OpenAI の GPT、gpt-oss・Qwen・DeepSeek・Kimi・GLM・MiniMax を使え、料金は自分の AWS アカウントに付きます。

追加する

  1. キーを作る。AWS コンソールの Bedrock ページで Bedrock API キーを作成します。
  2. 追加してリージョンを選ぶ。既定は us-east-1 です。アプリのエディターの リージョン で変えるか、CLI で設定します。
ターミナル
magpie provider add bedrock 
magpie provider set bedrock region=eu-west-1
magpie provider test bedrock

ランタイムのリージョンは us-east-1・us-east-2・us-west-2・eu-central-1・eu-west-1・eu-west-3・ap-northeast-1・ap-southeast-1・ap-southeast-2・ap-south-1 です。リージョンごとに Claude（Anthropic Messages）・Chat Completions・Responses のアドレスがあり、リージョンを変えると 3 つとも変わります。

モデル

Bedrock ランタイムには問い合わせられるモデル一覧がないため、magpie が一覧を用意しています。

  • Claude：global.anthropic.claude-opus-5-5・global.anthropic.claude-sonnet-5-5・global.anthropic.claude-haiku-4-5-20251001-v1:0 など。global. 推論プロファイルで、すべての商用リージョンがルーティングします。
  • OpenAI GPT：global.openai.gpt-6-astra・global.openai.gpt-6-sol・global.openai.gpt-6-luna。これも global. プロファイルです。
  • ほかの提供元：openai.gpt-oss-120b-1:0・qwen.qwen3-coder-480b-a35b-v1:0・deepseek.v3.2・moonshotai.kimi-k2.5・zai.glm-5・minimax.minimax-m2.5 などのリージョン内 ID。すべてのリージョンにあるとは限りません（ap-southeast-1 には gpt-oss がありません）。

1 つの地域に限られたプロファイル（us.・eu.・apac.・jp.・au.）は一覧にないので、ほかの自分のモデルと同じように入力します。

エージェントで使う

magpie はモデルごとに Bedrock の API を選びます。Claude は Anthropic Messages だけ、OpenAI の GPT（gpt-oss を除く）はまず Responses、残りは Chat Completions です。エージェントがどの API を話しても magpie が変換するので、Codex から Bedrock の Claude を、Claude Code から GPT を使えます。

ターミナル
magpie claude bedrock/global.anthropic.claude-sonnet-5-5
magpie codex bedrock/global.openai.gpt-6-sol

Bedrock Mantle

Mantle は Bedrock のもう 1 つのエンドポイント（bedrock-mantle.<リージョン>.api.aws）で、同じキーを使います。

ターミナル
magpie provider add bedrock-mantle  region=us-west-2
magpie provider test bedrock-mantle
  • ランタイムと違い Mantle はモデル一覧を返すので、一覧はアカウント自身のもので、Mantle だけのモデルも含まれます。
  • モデル ID はリージョン内のものだけです（anthropic.claude-sonnet-5、openai.gpt-oss-120b など）。global. や us. のプロファイルはありません。
  • Mantle の OpenAI API は 2 つのプレフィックスに分かれます。OpenAI のクローズドな GPT と xAI の Grok は /openai/v1、残りは /v1 です。magpie はモデルごとに選び、まだ知らない提供元が拒否されたらもう一方で 1 回だけ試し、通った方を覚えます。
  • Mantle のリージョンは 17 あり、ランタイムの eu-west-3 には Mantle がありません。

Claude Code の CLAUDE_CODE_USE_BEDROCK

CLAUDE_CODE_USE_BEDROCK（や _VERTEX・_MANTLE など）がオンだと、Claude Code はそのクラウドのエンドポイントに直接つなぎ、magpie を通りません。magpie は Claude Code をつなぐとき、自分が書く設定からそのスイッチを外して値を保存し、つなぐのをやめるときに元どおり戻します（その後あなたが設定し直した場合を除く）。AWS_* などクラウド自身の変数はそのままです。magpie が書かない場所（管理設定、~/.claude.json の env、ログインシェルの環境変数）にある場合は、エージェントページのチェックが変数名と場所を示します。

補足

  • Claude Code が Bedrock の受け付けない anthropic-beta を送ると、Bedrock は 400「Unexpected value(s) … for the anthropic-beta header」を返します。magpie はその beta を外してすぐ送り直し、以後そのプロバイダーには送りません。
  • Claude の API では、Bedrock の求めに合わせてキーを x-api-key だけで送ります。
  • ランタイムや Mantle のアドレスで追加したカスタムプロバイダーも認識され、同じルールが適用されます。

よくある質問

magpie で Bedrock を使うのに AWS アクセスキーは必要ですか？

不要です。Bedrock API キー 1 つで足り、magpie は SigV4 署名をしません。AWS コンソールの Bedrock ページで作成します。

Claude Code から magpie 経由で Bedrock の Claude を使えますか？

使えます。bedrock/global.anthropic.claude-sonnet-5-5 のようなモデルを選びます。CLAUDE_CODE_USE_BEDROCK はオフのままにしてください。オンだと magpie を通りません。magpie は自分が書く設定からそれを外します。

自分のリージョンで使えないモデルがあるのはなぜ？

global. の Claude と GPT はすべての商用リージョンでルーティングされますが、ほかの提供元のリージョン内 ID はリージョンによってありません。別のリージョンを選ぶか、そのリージョンにある ID を入力します。

Bedrock と Bedrock Mantle のどちらを使う？

キーは同じです。ランタイムには global. プロファイルと用意済みの一覧があり、Mantle はアカウント自身のモデル（Mantle 限定のものを含む）をリージョン内 ID だけで返します。
