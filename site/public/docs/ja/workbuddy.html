ドキュメント · ガイド

WorkBuddy を任意のモデルで

WorkBuddy は Tencent の CodeBuddy のデスクトップアプリです。自分のモデルを ~/.workbuddy/models.json（$WORKBUDDY_CONFIG_DIR があればそこ）から OpenAI chat completions 形式で読みます。magpie がこのファイルに自分のモデルを書き込むので、WorkBuddy のモデルピッカーに DeepSeek・GLM・Kimi・Qwen・Claude・ChatGPT サブスクリプションなど magpie のモデルが並びます。

WorkBuddy の設定

  1. magpie でプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  2. エージェント ページで WorkBuddy のプロバイダーを magpie にするWorkBuddy のピッカーに magpie が選んだモデルが並びます。
  3. WorkBuddy でタスクごとにモデルを選ぶモデルは WorkBuddy のウィンドウでタスクごとに選び、magpie のモデルは custom-local:<id> と表示されます。出てこないときは WorkBuddy を再起動してください。magpie のエージェントページから再起動できます。

再起動が要る理由：WorkBuddy 5.6 は起動時にファイルがあったときだけ models.json を監視し、しかもファイルそのものを監視するので、書き換えが再起動まで読まれないことがあります。

models.json

このファイルはモデルのリストか、CodeBuddy Code の CLI が書く {"models":[…],"availableModels":[…]} のどちらかで、magpie は両方を読み書きします。WorkBuddy 自身のローカルモデルも同じリストにあり（local: true）、magpie は触りません。magpie のモデルはどれもゲートウェイの /v1/chat/completions を指し、ツール呼び出しを有効にし、WorkBuddy 用の magpie のキーを持ちます：

ターミナル
// ~/.workbuddy/models.json (one of magpie's entries)
{
  "id": "deepseek/deepseek-v4-pro",
  "name": "…",
  "vendor": "magpie",
  "apiKey": "",
  "url": "http://127.0.0.1:3425/v1/chat/completions",
  "maxInputTokens": …,
  "maxOutputTokens": …,
  "contextWindow": { "supportedLengths": [200000, …], "defaultLength": … },
  "supportsToolCall": true,
  "supportsImages": …,
  "supportsReasoning": true,
  "reasoning": { "supportedEfforts": […], "canDisableThinking": …, "defaultEffort": "…" }
}

WorkBuddy は url に reasoning_effort 付きでリクエストを送り、apiKey を Bearer トークンにします。リクエストには CLI/<バージョン> WorkBuddy/<バージョン> とあるので、magpie はキーで WorkBuddy のリクエストを見分けます。WorkBuddy で編集したエントリは vendor Custom で保存されますが、magpie はキーで認識します。

コンテキストと返答の長さ

WorkBuddy がモデルメニューでコンテキストを選ばせるのは、contextWindow にサイズが 2 つ以上あるときだけです。magpie はウィンドウ全体の横に小さい 200K を加え、defaultLength はウィンドウ全体です。maxOutputTokens がないと WorkBuddy はすべての返答を自分の既定の長さで切るので、magpie はこれを書き込みます。

自分の設定はそのまま

WorkBuddy は起動するたびに数秒後、自分で models.json を書き換えます。このコンピューターで動かないローカルモデルを消し、apiKey を暗号化することもあります。magpie はこの書き換えを変更とはみなしません。ほかのエントリとキーは WorkBuddy が書いたままです：

  • WorkBuddy でオフにしたモデルはオフのままです。
  • 別のマシン（NAS など）の magpie を指すモデルは、そのアドレスとキーを保ちます。
  • 自分で入力した返答の上限はそのままです。
  • WorkBuddy のモデル設定で選んだ既定の推論の強さ（Auto を含む）は、モデルがまだ対応している限りそのままです。

WorkBuddy AI

国際版の WorkBuddy AI（www.workbuddy.ai、com.workbuddy.workbuddy-ai）は同じアプリで、データは ~/.workbuddy-ai にあります。magpie はこれを別のエージェントとして、専用のキーで接続します。Mac ではこのフォルダーではなくアプリそのもので見つけます。WSL の WorkBuddy も、ディストリビューションから届くゲートウェイのアドレスで接続できます。

元に戻す

magpie で WorkBuddy をオフにすると、magpie は models.json から自分のモデルを取り除き、ほかのエントリはそのまま残します。

よくある質問

WorkBuddy で DeepSeek や GLM を使えますか？

使えます。magpie が ~/.workbuddy/models.json にモデルを書き込むので、WorkBuddy のモデルピッカーで custom-local から始まるモデルを選んでください。

WorkBuddy に magpie のモデルが出てこないのはなぜですか？

WorkBuddy が書き換えに気づいていない可能性があります。再起動してください。magpie のエージェントページから再起動できます。

magpie は WorkBuddy の設定を変えますか？

変えません。オフにしたモデル、NAS を指すモデル、入力した返答の上限、既定の推論の強さはそのままです。

国際版の WorkBuddy AI でも使えますか？

使えます。データは ~/.workbuddy-ai にあり、magpie は別のエージェントとして接続します。

同じモデルを他のエージェントでも：VS Code を任意のモデルで、CodeBuddy を任意のモデルで、Claude Science を任意のモデルで、Pencil を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
