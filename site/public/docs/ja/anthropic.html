Anthropic を Claude Code・Codex・Gemini CLI・OpenCode で使う

Anthropic は Claude を api.anthropic.com の Messages API で提供しています。Anthropic の API キーを magpie に一度追加すれば、Claude Code・Codex・Gemini CLI・OpenCode などつないだすべてのツールが、magpie のゲートウェイ 127.0.0.1:3425 経由で Claude のモデルを使えます。ツールごとに別のモデルを選べます。別の API を話すツールのリクエストは、途中で magpie が変換します。

Anthropic を追加する

  1. キーを取得console.anthropic.com で作ります。API キーは sk-ant-api で始まります。
  2. プロバイダを追加magpie の プロバイダ で ＋ プロバイダを追加 を押し、Anthropic を選んでキーを貼り付け、保存します。magpie がそのキーで使えるモデルを Anthropic に問い合わせます。
  3. ツールで選ぶエージェント タブで、ツールの行のモデルを押し、claude-opus-5-5 などの Claude モデルを選びます。
ターミナル
magpie provider add anthropic <key>
magpie provider test anthropic

magpie のモデル ID は プロバイダ/モデル の形なので、Anthropic のモデルは anthropic/claude-opus-5-5 のようになります。前がプロバイダ、後ろが Anthropic 自身の ID です。キーは magpie の設定に保存され、magpie がシェルから読むことはありません。

OpenCode や Alma で Anthropic をもう設定してあるなら、magpie がそれらのアプリから取り込むときに Anthropic プロバイダとして入ります。

このページは API キーの話です。Claude Pro や Max のサブスクリプションは別にサインインします。サブスクを任意のエージェントで を見てください。

エンドポイント

APIアドレス用途
Messageshttps://api.anthropic.com/v1/messagesすべてのツールのリクエスト。Claude Code のものはそのまま、Codex・Gemini CLI・OpenCode のものは変換して
モデルhttps://api.anthropic.com/v1/modelsモデル一覧

magpie の Anthropic プロバイダには Chat Completions や Responses のアドレスがないので、そのどちらか、または Google の Gemini API を話すツールのリクエストは Messages に変換し、返答も変換して戻します。ストリーミングとツール呼び出しも含みます。

モデル一覧

magpie は一覧を Anthropic の https://api.anthropic.com/v1/models から、すべてのページを取得するので、ツールにはそのキーで使えるモデルが並びます。名前・コンテキストウィンドウ・価格は models.dev の anthropic カタログから取ります。ツールに見せるモデルは、プロバイダのモデル一覧かターミナルで選べます。

ターミナル
magpie provider models anthropic +claude-opus-5-5 +claude-sonnet-5-5 +claude-haiku-5-5
magpie provider refresh-every anthropic 1d

Claude Opus 5.5・Sonnet 5.5・Haiku 5.5 は 1M トークンを受け付けます。ここまで長いウィンドウでは、Codex は毎ターン会話をどんどん多く送る代わりに 272K で圧縮します。magpie model compact off にするとウィンドウ全体まで使います。Claude Code では、Claude のモデルは Anthropic と同じく自分のウィンドウで動きます。[1m] の付いたものを選ばない限り 200K です。

ツールごとの使い方

ターミナル
magpie claude anthropic/claude-opus-5-5
magpie codex anthropic/claude-opus-5-5
magpie gemini model anthropic/claude-sonnet-5-5
magpie opencode anthropic/claude-sonnet-5-5
  • Claude Code は Anthropic Messages を話すので、リクエストは Claude Code が送ったとおりに Anthropic へ届きます。自前のキャッシュの印・思考・beta もそのままで、直すのは下に挙げるものだけです。Claude Code で他のモデル。
  • Codex が話す OpenAI Responses を Anthropic は提供していません。magpie が各リクエストを Messages に変換して返答を戻し、プロンプトに Anthropic のキャッシュの印を付け、ツール呼び出しのループのあいだ Claude の署名付きの思考を引き継ぎます。Codex で他のモデル。
  • Gemini CLI は Google の Gemini API を話します。magpie が各リクエストを Messages に変換し、返答を戻します。Gemini CLI で他のモデル。
  • OpenCode は magpie に Chat Completions で話すので、そのリクエストも Messages に変換します。OpenCode で他のモデル。

magpie が Anthropic 向けにすること

magpie が変換するリクエストは、Anthropic の Messages API が求める形で組み立てます。Anthropic が拒否するいくつかのものは、Claude Code のリクエストでも直します。

  • プロンプトキャッシュ。Anthropic は cache_control の印が付いたブロックまでしかキャッシュせず、ほかの API から来たリクエストには印がありません。magpie はシステムプロンプト（ないときは最後のツール）と会話の最後のブロックに、多くて二つの印を付けるので、次のターンはそれまでの内容をキャッシュから読めます。自前の cache_control を持つリクエストはその印を残し、magpie は何も足しません。
  • Codex には 1 時間のキャッシュ。Codex のターンは 5 分以上空くことが多いので、magpie が Codex のリクエストに付ける印は 1 時間もちます。Codex が prompt_cache_retention に in_memory を求めたときは別です。1 時間の ttl を受け付けない上流には 5 分の印で問い合わせ直し、magpie はそれを覚えておきます。
  • 署名付きの思考。Claude は自分の思考に署名し、ツール呼び出しのループの次のターンでそれを送り返すよう求めます。Codex は推論項目の encrypted_content に、署名ごと思考ブロックを受け取り、magpie はそれを元のまま Anthropic に送り返します。伏せられた思考も封をしたまま戻します。署名のない思考は外し、ほかのベンダーが署名した思考（ルーティンググループで先に使った DeepSeek のものなど）も、Claude が拒否するので外します。
  • ツール呼び出し。中断されたターンが答えのない呼び出しを残すと、結果が得られないと伝える答えを付けます。Anthropic が見たことのない呼び出しへの答えはテキストにします。どちらも、そのままでは Anthropic がリクエストを拒否します。呼び出しの履歴があるのにツールが宣言されていないときは、それらを宣言して tool_choice を none にします。ツール必須は any、名前指定は tool、並列呼び出しオフは disable_parallel_tool_use として送ります。
  • サンプリング。Opus 4.7 以降・Sonnet 5 と 5.5・Haiku 5.5・Fable 5 は temperature・top_p・top_k を拒否しますが、Claude Code の自動モードの分類器はこれらを送ります。magpie はこれらのモデルにはそれらを送りません。
  • Beta。ツールが anthropic-beta で求めた beta は Anthropic に渡します。ただし Claude Code 自身のサインイン用の beta（oauth-…）は除きます。それが指す資格情報は magpie の外に出ないからです。
  • 構造化出力。スキーマどおりの JSON を求めるリクエストは、output_config.format として Anthropic に送ります。

推論

  • 推論の強さ。Claude 4.6 以降のモデルは適応的に思考します。変換したリクエストの強さは output_config.effort で送り、思考は適応型にして要約の表示（display: summarized）を求めます。Opus 4.7 以降は、求めないと思考の本文を返さないからです。Opus と Sonnet 4.6 には xhigh がないので、xhigh は max として求めます。
  • 思考の予算。それより前の Claude には思考の予算を送ります。low は 4,096 トークン、medium は 10,000、high は 24,000、xhigh と max は 32,000 で、リクエストの max_tokens に収まるように合わせます。
  • 新しいモデルへの予算。4.6 以降のモデルに思考の予算を付けたリクエスト（Claude Opus 5.5 は “requires adaptive thinking” で拒否します）は、適応型の思考にし、予算を最も近い強さに置き換えて送ります。
  • 推論オフ。Codex や Chat クライアントが強さを none にすると、低い予算ではなく思考オフになります。オフの受け付け方はモデルごとに違います。Sonnet 5.5 には between_tools を送り、high より上の強さは high で求めます。Opus 5.5 と Fable 5 は常に思考するので thinking を外します。Opus 5 と Haiku 5.5 は xhigh や max の代わりに high で求めます。それより前の Claude は送ったとおりに受け付けます。Claude Code の思考オフのリクエストも同じように合わせます。

Web 検索

Anthropic は自分で Web を検索します。Claude Code の WebSearch はそのまま Anthropic に届きます。Codex・Gemini CLI・Chat クライアントが検索を求めると、magpie は magpie の検索サービスではなく、Anthropic 自身の web_search_20250305 ツールを Claude に渡します。検索はリクエストごとに 5 回までです。

費用・使用量

  • キャッシュのトークン。使用量 タブは、Anthropic が報告するとおりに、キャッシュの読み込み・5 分のキャッシュ書き込み・1 時間のキャッシュ書き込みを、プロンプトの残りと分けて数えます。
  • 費用。使用量タブは、models.dev にある Anthropic の価格で呼び出しごとに費用を計算します。カタログに 1 時間の書き込みの価格がないときは、Anthropic の請求と同じく入力価格の 2 倍で数えます。magpie は Anthropic から残高を読みません。key-balance で自分で入力すると、使用量ページはそこから magpie がそれ以降のキーの呼び出しに付けた費用を引いて表示します。
  • キャッシュを生かす。キーが複数あるとき、会話のキャッシュに残す価値があり（1,024 トークン以上）、まだ温かい（5 分以内に読まれた。1 時間で書いたものは 1 時間以内）あいだは、その会話は同じキーを使い続けます。

複数のキーとフェイルオーバー

一つの Anthropic プロバイダに複数のキーを入れられます。その下の 別のキーを追加 を押すか、まとめて貼り付けます。リクエストはオンになっている最初のキーに行き、そのキーが尽きるかレート制限にかかると次のキーが引き継ぎます。

  • 支出上限。spend-cap で、キーごとに 1 日・1 か月・累計のドル上限を決められます。金額は使用量タブの計算で数え、上限に達するとルーティングはほかのキーとフォールバックに移ります。
  • フォールバック。fallback で、Anthropic の枠が尽きたときや落ちたときの行き先を決めます。別のプロバイダのモデルか、ルーティンググループです。
  • ワークスペース。複数のワークスペースに届くキーは、anthropic-workspace-id ヘッダでリクエストごとのワークスペースを指定します。別の ID でプロバイダをもう一度追加し、そのヘッダ欄かターミナルでヘッダを設定します。そのモデルは anthropic-ws2/… のようになります。
ターミナル
magpie provider spend-cap anthropic <key> 20 month
magpie provider key-balance anthropic <key> 25
magpie provider fallback anthropic deepseek/deepseek-v4-pro
magpie provider add anthropic <key> id=anthropic-ws2 name="Anthropic WS2" header.anthropic-workspace-id=wrkspc_…

うまくいかないとき

  • “requires adaptive thinking”。4.6 以降のモデルに思考の予算を送りました。magpie は適応型の思考にして最も近い強さで送ります。推論 を見てください。
  • 思考をオフにすると 400。Sonnet 5.5・Opus 5.5・Fable 5 はどれも disabled を拒否し、Opus 5 と Haiku 5.5 は xhigh と max のときに拒否します。magpie はモデルごとに受け付ける形でオフにします。
  • “temperature is deprecated for this model”。magpie は、temperature・top_p・top_k を拒否するモデルにはそれらを送りません。
  • “tool_use ids were found without tool_result blocks”。中断されたターンが答えのない呼び出しを残しました。magpie が変換するリクエストでは、その呼び出しに結果が得られないと伝える答えを付けます。
  • “Invalid signature in thinking block”。その会話は先にほかのベンダーで動いていました。magpie は、ほかのベンダーが署名した思考と署名のない思考を、Claude に送る内容から外します。
  • cache_control と ttl についての 400。上流が、magpie が Codex 用に付ける 1 時間の印を受け付けません。magpie は 5 分の印で問い合わせ直し、そのプロバイダには以後それを使います。
  • “this is an Anthropic API key, not a setup-token”。キーを Claude サブスクリプションのサインインに入れました。代わりに Anthropic プロバイダとして追加してください。
  • キーの確認。magpie provider test anthropic は各エンドポイントに、または指定した各モデルに小さなリクエストを送ります。--as codex や --as claude-code を付けると、そのツールと同じ形で送ります。

よくある質問

Claude Code で Anthropic の API キーを使うには？

magpie に Anthropic の API キーを追加し（プロバイダ、プロバイダを追加、Anthropic）、Claude Code の行で claude-opus-5-5 などの Claude モデルを選ぶか、magpie claude anthropic/claude-opus-5-5 を実行します。Claude Code は Anthropic Messages を話すので、リクエストは送ったとおりに https://api.anthropic.com へ届き、途中で直すのはモデルが拒否するものだけです。

Codex で Claude のモデルを使えますか？

使えます。Codex が話す OpenAI Responses を Anthropic は提供していないので、magpie が各リクエストを Messages API に変換し、返答を戻します。プロンプトには 1 時間もつキャッシュの印を付け、ツール呼び出しのループのあいだ Claude の署名付きの思考を Codex の encrypted_content で引き継ぎます。magpie codex anthropic/claude-opus-5-5 を実行してください。

magpie 経由で OpenCode から Claude を使うには？

magpie でモデルを選ぶか、magpie opencode anthropic/claude-sonnet-5-5 を実行します。OpenCode は magpie に Chat Completions で話すので、magpie がリクエストを Anthropic の Messages API に変換し、プロンプトにキャッシュの印を付け、推論の強さをモデルに合わせます。

Gemini CLI で Claude を使えますか？

使えます。Gemini CLI は Google の Gemini API を話すので、magpie がリクエストを Anthropic の Messages API に変換し、返答を戻します。ストリーミングとツール呼び出しも含みます。magpie gemini model anthropic/claude-sonnet-5-5 を実行してください。

magpie が変換するリクエストでも Anthropic のプロンプトキャッシュは効きますか？

効きます。Codex・Gemini CLI・OpenCode のリクエストには自前のキャッシュの印がないので、magpie がシステムプロンプトと会話の最後のブロックに多くて二つの印を付け、次のターンはそれまでの内容をキャッシュから読みます。自前の cache_control を持つリクエストはその印を残します。Codex の印は 1 時間、ほかは 5 分もちます。

思考をオフにすると Claude が 400 を返すのはなぜ？

新しい Claude のモデルは、どれも thinking の disabled を受け付けるわけではありません。magpie は Sonnet 5.5 には between_tools を送り、常に思考する Opus 5.5 と Fable 5 には thinking を外し、Opus 5 と Haiku 5.5 には xhigh や max の代わりに high で求めます。それより前の Claude には送ったとおりに渡します。
