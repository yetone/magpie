Cindy を任意のモデルで

Cindy は Claude Code、Codex、Pi を動かすデスクトップアプリです。プロバイダーは自身のデータベースにあり、キーは暗号化され、新しいプロバイダーは Cindy 自身のインポートリンクからしか受け付けず、Cindy で確認します。そのため magpie は Cindy に何も書きません。magpie を 1 つのカスタムプロバイダーとして、ランタイムごとのエンドポイント付きでインポートリンクにして渡します。すると Cindy の Claude Code、Codex、Pi が magpie の任意のモデル（DeepSeek、GLM、Kimi、Qwen、OpenAI や Anthropic のキー、サインインした ChatGPT や Copilot のサブスクリプション）で動きます。

Cindy に magpie を追加

  1. Cindy を一度開くCindy が一度動くとデータフォルダー（Mac では ~/Library/Application Support/Cindy、グローバル版は CindyGlobal）ができ、magpie の エージェント ページに出ます。
  2. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  3. 「magpie を追加」をクリックCindy の行で magpie を追加 をクリックすると、magpie がインポートリンクを Cindy に渡します。
  4. Cindy で確認する確認するまで何も追加されません。その後、Cindy で Claude Code、Codex、Pi に Magpie プロバイダーのモデルを選びます。

何も起きないときは、このコンピューターに Cindy のリンク（cindy://）を開くプログラムがないか、登録したプログラムが移動されています。magpie は先にそれを確かめ、何もしないのではなく理由を伝えます。Cindy を一度開くか入れ直してから、もう一度クリックしてください。

リンクの中身

リンクの data は base64url でエンコードした JSON で、解くとこうなります：

ターミナル
cindy://provider/import?v=1&data=
{
  "kind": "custom", "name": "Magpie", "id": "magpie",
  "auth": {"method": "apiKey", "apiKey": "…"},
  "endpoints": [
    {"protocol": "anthropic-messages", "baseUrl": "http://127.0.0.1:3425",
     "targets": ["claude-code"], "modelsUrl": "http://127.0.0.1:3425/v1/models"},
    {"protocol": "openai-responses", "baseUrl": "http://127.0.0.1:3425/v1",
     "targets": ["codex"], "modelsUrl": "http://127.0.0.1:3425/v1/models"},
    {"protocol": "openai-chat", "baseUrl": "http://127.0.0.1:3425/v1",
     "targets": ["pi"], "modelsUrl": "http://127.0.0.1:3425/v1/models"}
  ]
}

Claude Code はゲートウェイそのものに Anthropic Messages で、Codex は OpenAI Responses、Pi は OpenAI Chat で、どちらもゲートウェイの /v1 に話します。どのエンドポイントもモデル一覧をゲートウェイの /v1/models から取るので、後で magpie に加えたプロバイダーも Cindy がモデルを取り直せば出てきます。

コマンドライン

ターミナル
magpie cindy add      # Cindy を開いて magpie を追加し、そこで確認

コマンドは開いたリンクを表示します。開けるプログラムがないときは、成功を装わず理由を伝えます。

追加済みを magpie が知る方法

magpie は Cindy のデータベースを読み取り専用で読みます。サインイン後はアカウントごとの cindy-<アカウント>.db、その前は cindy-local-v1.db です。どれかのカスタムプロバイダーに id か名前が magpie のもの、またはエンドポイントにゲートウェイのアドレスがあれば、行は追加済みと表示されます。Cindy が動いていても読め、書き込むことはありません。読めないときは、未追加ではなく不明と伝えます。

使用量とキー

リンクのキーは Cindy 専用なので、そのリクエストは magpie の使用量で他のエージェントとは別に Cindy として数えられます。

よくある質問

Cindy の Claude Code で DeepSeek や GLM を使えますか？

はい。Cindy に magpie を追加すると、Claude Code は Magpie プロバイダーの Anthropic エンドポイント経由で DeepSeek や GLM を含む magpie の任意のモデルを使えます。

magpie は Cindy の設定を変えますか？

いいえ。Cindy は新しいプロバイダーを自身のインポートリンクからしか受け付けず、Cindy で確認します。magpie は追加済みかを表示するためにデータベースを読むだけです。

「magpie を追加」で何も起きません。

このコンピューターに cindy:// リンクを開くプログラムがないか、登録したプログラムがもうありません。Cindy を一度開くか入れ直してからもう一度クリックしてください。どちらかは magpie が伝えます。

magpie のエージェントページに Cindy がありません。

Cindy がこのコンピューターで一度動いてデータフォルダーができると表示されます。Cindy を一度開いてからもう一度見てください。

同じモデルを他のデスクトップアプリでも：AionUi を任意のモデルで、magpie で Cherry Studio にすべてのモデルを、Shelley を任意のモデルで、Lody を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
