ドキュメント · ガイド

どのモデルでもウェブ検索

Claude Code には WebSearch、Codex には web_search がありますが、これらはモデルのプロバイダー自身が検索できるときにしか働きません。DeepSeek・GLM・Qwen など、多くのモデルの API は検索しません。magpie 経由で使うと、magpie が代わりに検索します。モデルには magpie の web_search ツールが渡され、呼ばれると magpie が検索して見つかったページをモデルに返し、検索とその出典はエージェントが知っている形で返ります。Claude Code や Codex でどのモデルに切り替えても、ウェブ検索はそのまま使えます。

設定

検索の出どころは二種類です。検索できるプロバイダーと、あなたが追加する検索 API。どちらも 設定 › モデル › ウェブ検索 にあります。

  1. 検索できるプロバイダーがあれば設定は不要magpie が自分で選びます。Google のサインイン、ChatGPT アカウント（Codex のサインイン）、Kimi Code・GLM Coding Plan・WorkBuddy のプランなどです。
  2. または検索 API を追加する検索 API に Tavily や Brave Search などのキーを追加します。検索できるプロバイダーがないときは、これらが検索します。
  3. 優先して使う検索 でどちらを先にするか選ぶ先のほうが失敗したら、もう一方を使います。

検索には使うサービスの枠や料金がかかることがあります。

代わりに検索するプロバイダー

モデルが自分でウェブ検索するプロバイダーは、検索できないモデルの代わりに検索できます。他のモデルの代わりに検索 で一つ選ぶか、magpie に任せます。

  • magpie が選んだもの：失敗するか何も見つからないと、次に検索できるプロバイダーに移ります。全部で三つまでです。
  • あなたが選んだもの：失敗したときは、失敗したとき でその後ろに置いたプロバイダーだけが順に代わります。まったく検索できないとき（枠を使い切った、レート制限）だけ、ほかの使える出どころ、最後に検索 API が試されます。
  • すべて失敗したときは、エラーがツールの結果としてモデルに返り、ターンは続きます。

自分のモデルを先に検索するプロバイダーもあります。Kimi Code のプランは自前の検索サービス、GLM Coding Plan はプラン付属の Web Search MCP サーバー（同じキーで、設定は不要）、WorkBuddy のプランは自前の検索サービス、Google のサインインは Google 検索です。ChatGPT アカウントは ChatGPT バックエンド自身の検索、つまり Codex の web.run が送るリクエストで検索します。

検索 API だけを使うなら、プロバイダーによる検索をオフにします。すべてのモデルが追加した検索 API だけを使い、一つもなければ magpie は検索ツールを加えません。プロバイダー自身のウェブ検索は変わりません。

検索 API

追加できる検索 API は Tavily、Brave Search、Exa、Firecrawl、You.com、DeepSeek、Doubao Search (Volcengine)、Yuanbao Search (Tencent Cloud)、TinyFish、SearXNG、そしてプラグインが提供するものです。一覧の順に使われ、ドラッグで並べ替えたり、個別にオフ（キーごと残して呼ばない）にしたりできます。CLI でも同じことができます。

ターミナル
magpie search add tavily 
magpie search add you              # You.com: free with no key (100 searches a day)
magpie search add searxng url=

magpie search                      # the search APIs, in the order they are asked
magpie search move  
magpie search count 10             # results per search, 1 to 20, 6 by default
  • 一つの API にカンマ区切りで複数のキーを入れると、検索ごとに順に使います。pick=order なら拒否されるまで最初のキーを使います。
  • SearXNG にはアドレスが必要です。ほかの API も url= で、その API と同じように応答する自前のエンドポイントを指せます。キーはそこにだけ送られます。
  • 1 回の検索の結果数：クライアントが件数を指定しないとき（Claude Code の WebSearch、Codex の web_search）の件数で、1〜20、既定は 6。1 件につきページ本文を最大 1500 バイト含むので、多いほどモデルが読む量も増えます。
  • magpie search mix <api>,<api> は複数の API に同時に聞き、まとめて最大 12 ページを返します。それぞれの API の枠を使います。

自分でウェブ検索するモデル

Grok や Gemini などのモデルは自分でウェブ検索し、クライアントのウェブ検索はそのまま渡されます。自分でウェブ検索するモデル を magpie の検索 にすると、ほかのモデルと同じく magpie のプロバイダーと検索 API を使います。ネイティブ検索 ならそのままです。

MCP サーバーとして

同じ検索は MCP サーバーでもあり、Cursor・Claude Desktop などどのエージェントにも追加できます。web_search ツールと、URL でページを読む web_fetch ツール（自前の取得ツールがないエージェント向け）があります。アドレスはウェブ検索ページの MCP サーバー の行にあり、既定では次のとおりです。

ターミナル
http://127.0.0.1:3425/mcp/magpie/web-search

Streamable HTTP のみです。stdio しか話せないクライアントは mcp-remote 経由でマウントします。別のコンピューターから（magpie をローカルネットワークで共有しているとき）は、ゲートウェイキーを Authorization: Bearer <key> で送ります。web_fetch は公開アドレスだけを、最大 30 秒・5 MiB まで読みます。

誰が検索したか

magpie の検索はすべて ルーティング ページに出ます。最初の出どころの代わりに別のものが検索したときは、誰が代わりに検索したかが出ます。

どのモデルでも画像認識と画像生成：画像を読めないモデルでもスクリーンショットを使え、エージェントから画像や動画も作れます。

よくある質問

DeepSeek はウェブ検索できますか？

DeepSeek の API 自体は検索しません。magpie 経由なら、Claude Code の WebSearch や Codex の web_search に magpie の検索が答えます。検索できるプロバイダーか、追加した検索 API を使います。

検索できるプロバイダーがないときは？

設定 › モデル › ウェブ検索 で Tavily や Brave Search などの検索 API を追加します。You.com はキーなしで 1 日 100 回使え、自前の SearXNG のアドレスも使えます。

検索に費用はかかりますか？

選んだサービスの枠を使います。検索するプロバイダーはその枠を使うか料金がかかり、検索 API はそれぞれの料金です。

Cursor で magpie のウェブ検索を使えますか？

使えます。/mcp/magpie/web-search を MCP サーバー（Streamable HTTP）として Cursor に追加すると、web_search と web_fetch の二つのツールが使えます。

関連ページ：DeepSeek を Claude Code・Codex・Gemini CLI・OpenCode で使う、エージェントが magpie を通らなくなったとき。エラーが出るときは よくあるエラーの直し方：401・429・502・504 など、または Discord で質問してください。
