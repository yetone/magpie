Claude Code・Codex で Ollama や LM Studio のローカルモデルを使う方法

Claude Code が話すのは Anthropic Messages、Codex が話すのは OpenAI Responses です。一方、ローカルのモデルサーバーが話すのは主に OpenAI Chat Completions で、Anthropic Messages も話すものがあります。magpie がその間に入るので、Ollama で pull したモデルや LM Studio で読み込んだモデルを Claude Code と Codex からそのまま使えます。

ゲートウェイは 127.0.0.1:3425 で動きます。magpie はエージェントをここへ向け、各リクエストをローカルサーバーへ送ります。サーバーがエージェントの API をそのまま話せるならリクエストはそのまま渡し、話せない場合は magpie がリクエストと応答を変換します。ストリーミングもツール呼び出しもそのままです。

Ollama・LM Studio

既定のポートでキー不要のプリセット。magpie がサーバーにモデル一覧を問い合わせます。

oMLX・MLX-Serve

Apple シリコン向けの MLX サーバーもプリセットがあります。

その他

vLLM、llama.cpp のサーバー、任意の OpenAI 互換 URL。同じマシンでも別のマシンでも。

対応サーバー

プロバイダを追加するとき、このマシン上 に並んでいます。

サーバー既定のアドレスmagpie が使う API
Ollamahttp://localhost:11434Chat Completions、Anthropic Messages
LM Studiohttp://localhost:1234Chat Completions
oMLXhttp://localhost:8000Chat Completions、Responses、Anthropic Messages
MLX-Servehttp://localhost:11234Chat Completions、Responses、Anthropic Messages

つまり、Claude Code は Ollama・oMLX・MLX-Serve にはリクエストをそのまま送り、LM Studio には magpie が変換して送ります。Codex は oMLX・MLX-Serve にはそのまま、Ollama・LM Studio には magpie が Responses を Chat Completions に変換して送ります。

セットアップ

  1. サーバーを起動するOllama でモデルを pull するか LM Studio で読み込み、サーバーを動かしたままにします。
  2. magpie に追加するプロバイダ タブで ＋ プロバイダを追加 を押し、このマシン上 から Ollama か LM Studio を選びます。キーは不要です。magpie がサーバーにモデルを問い合わせ、ollama/… や lmstudio/… として表示されます。
  3. エージェントのモデルを選ぶエージェント タブで Claude Code か Codex の行のモデルをクリックし、ローカルモデルを選びます。magpie が Claude Code の settings.json や Codex の config.toml を書き換えます。新しいセッションから使えます。

ターミナルからも同じことができます。

ターミナル
ollama pull qwen3
magpie provider add ollama
magpie models                     # すべてのモデル（プロバイダ/モデル）
magpie claude ollama/qwen3        # Claude Code
magpie codex ollama/qwen3         # Codex

エージェントの中でも、Claude Code と Codex の /model に magpie のモデルが並ぶので、ローカルモデルとクラウドのモデルをそこで切り替えられます。各エージェントの設定で何が変わるかは Claude Code でほかのモデルを使う と Codex でほかのモデルを使う を参照してください。

別のポート、別のマシン

サーバーが別のポートで待ち受けている場合や、GPU マシンや NAS など別のマシンで動いている場合は、プロバイダの編集画面で サーバーアドレス を変えます。各 URL がそのアドレスへ移り、パスはそのままです。

ターミナル
magpie provider add lmstudio address=http://192.168.1.5:1234
magpie provider set ollama address=192.168.1.20:11434
magpie provider set ollama address=     # 既定のアドレスに戻す

自己署名証明書の HTTPS サーバーには、編集画面の 証明書を検証しない で接続できます。そのプロバイダ自身のホストにだけ効きます。

vLLM、llama.cpp などのサーバー

プリセットのないサーバーは カスタム で追加します。http://localhost:8080/v1 のような URL を貼り付け、API を検出 を押すと、magpie がその URL で Chat Completions・Responses・Anthropic Messages・Gemini にそれぞれ最小のリクエストを送り、応答したものを使います。キーが要らないサーバーなら空欄のままで構いません。

コンテキストウィンドウ

エージェントは、モデルが受け付けるリクエストの長さを前提に会話を組み立てます。Claude Code は知らないモデルを 200K とみなし、Codex は伝えられたウィンドウの 90% で会話を圧縮します。ローカルモデルはずっと小さいウィンドウで読み込まれていることが多いので、実際の値を magpie に伝えてください。プロバイダの編集画面の 詳細設定 にある コンテキストウィンドウ で、全モデルにも個別のモデルにも設定できます。magpie がそれをエージェントに伝えます。

ターミナル
magpie provider set ollama context=32k
magpie provider set ollama context.qwen3=128k

マスク

magpie の プライバシーマスク は、リクエストがゲートウェイを出る前にキーやトークンなどの秘密をプレースホルダーに置き換えます。ローカルサーバーへのリクエストも同じです。モデルが自分のマシンやネットワーク内で動いているなら、編集画面で リクエストをマスクしない をオンにするか、magpie provider set ollama unmasked=yes を実行します。判断はあなた次第です。Ollama のクラウドモデルや、ローカルで動かしている中継サービスは、アドレスに関係なくリクエストをベンダーへ送ります。

よくある質問

Claude Code で Ollama は使えますか？

使えます。magpie に Ollama を追加し、Claude Code のモデルにそのモデルを選ぶだけです。magpie が Claude Code の settings.json にゲートウェイのアドレスを書き込み、Ollama の Anthropic 互換 API が Claude Code のリクエストをそのまま受け取ります。

Codex で Ollama や LM Studio は使えますか？

使えます。Codex は Responses API しか話さないので、magpie がリクエストを Chat Completions に変換して Ollama や LM Studio に送り、応答を戻します。ツール呼び出しも同じです。oMLX と MLX-Serve は Responses をそのまま受け付けます。

API キーは必要ですか？

いいえ。ローカルのプリセットにはキーが要りません。サーバーにキーを設定している場合は、プロバイダの編集画面で入力します。

別のマシンで動くモデルも使えますか？

使えます。プロバイダのサーバーアドレスを http://192.168.1.20:11434 のようにそのマシンに変えてください。

ローカルモデルだと Claude Code の長い会話が失敗するのはなぜですか？

Claude Code は知らないモデルを 200K とみなすからです。magpie でプロバイダに実際のコンテキストウィンドウを設定すれば、Claude Code も Codex も上限に達する前に圧縮します。

元に戻すには？

magpie でエージェント自身のモデルを選ぶか、magpie claude default や magpie codex default を実行します。magpie が書いたものは取り除かれ、置き換えたものは元に戻ります。

クラウドのモデルを使うなら Claude Code でほかのモデルを使う と Codex でほかのモデルを使う を参照してください。困ったときは Discord で質問してください。
