Mister Morph

仕組み Mister Morph の設定 config.yaml コンテキスト長 思考レベル profiles と routes 元に戻す

ドキュメント · ガイド

Mister Morph を任意のモデルで

Mister Morph（morph コマンド）は設定を ~/.morph/config.yaml、または MISTER_MORPH_CONFIG が指すファイルに持ちます。メインのモデルは llm.model で、llm.inference_provider のベンダーに llm.endpoint で llm.api_key を使って問い合わせます。プロバイダーを加える一覧がないため、magpie がこの llm の項目を引き受け、Mister Morph が DeepSeek、GLM、Kimi、Qwen、Claude、ChatGPT サブスクリプションなど magpie の任意のモデルで動きます。

Mister Morph の設定

  1. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  2. エージェント ページで Mister Morph のモデルを選ぶvia magpie のモデルを選び、必要なら思考レベルも選びます。morph は他のツールの名前でもあるので、magpie はコマンドではなく ~/.morph フォルダーで見つけます。このフォルダーは初回実行、morph install、デスクトップアプリのセットアップで作られます。
  3. 新しいタスクを始めるMister Morph の Console は新しいタスクから新しいモデルを使います。開いている morph チャットは再起動してください。
ターミナル
magpie morph deepseek/deepseek-v4-pro

config.yaml

magpie は llm 以下に次の項目を書きます。inference_provider は openai_response_compatible で、Mister Morph 既定の OpenAI Responses API です。ゲートウェイはどのベンダーでもこれに対応します。endpoint はゲートウェイの /v1（/v1 で終わるアドレスに Mister Morph はもう一つ /v1 を付けません）、api_key は magpie のキー、model はカタログのモデル ID です。Mister Morph の中ではこのモデルは magpie/deepseek/deepseek-v4-pro と表示されます。さらに llm.headers の User-Agent を mistermorph にします。そうしないとリクエストには OpenAI SDK の User-Agent が付き、どこからのものか区別できません。

ターミナル
# ~/.morph/config.yaml (or $MISTER_MORPH_CONFIG)
llm:
  inference_provider: openai_response_compatible
  endpoint: http://127.0.0.1:3425/v1
  api_key: 
  model: deepseek/deepseek-v4-pro
  context_window_tokens: …
  headers:
    User-Agent: mistermorph
  reasoning_effort: high

llm.provider はそのままです。Mister Morph が inference_provider から導きます。WSL の Mister Morph も同じように設定されますが、そこでは MISTER_MORPH_CONFIG を読まないので ~/.morph/config.yaml を使います。

コンテキスト長

Mister Morph はモデルのコンテキスト長を、ID の最後のスラッシュより後ろで自前の一覧から調べるだけです。そこで magpie は知っているコンテキスト長を llm.context_window_tokens に書き、分からないときはこの項目を消します。

思考レベル

思考レベルは llm.reasoning_effort に書き、none、minimal、low、medium、high、xhigh、max から選べます。未設定なら Mister Morph は思考レベルを送りません。

ターミナル
magpie morph effort high

profiles と routes

llm.profiles と llm.routes は自分のもので、magpie は触りません。メインループを別の profile に送る route があれば、それもそのまま効きます。

元に戻す

magpie は初めて llm を引き受ける前に、それらの項目の元の値を保存します。元に戻すときはそれを戻し、元になかった項目は消します。User-Agent が llm.headers の唯一の項目だったときは headers ごと消します。Mister Morph 自身のモデルを選んだときも同じように戻してから、llm.model を選んだモデルにします。

ターミナル
magpie morph default

よくある質問

Mister Morph で DeepSeek、GLM、ChatGPT サブスクリプションを使えますか？

使えます。magpie のエージェントページで Mister Morph に via magpie のモデルを選ぶと、magpie が config.yaml の llm の項目を設定します。

magpie 経由の Mister Morph はどの API を使いますか？

Mister Morph 既定の OpenAI Responses API（openai_response_compatible）で、magpie のゲートウェイはどのベンダーでも対応します。

なぜ magpie は context_window_tokens を書くのですか？

Mister Morph は自前の一覧でしかコンテキスト長を調べず、そこに magpie のモデル ID がないため、magpie が分かっている長さを渡します。

llm.profiles と llm.routes は変わりますか？

変わりません。それらは自分のもので、magpie は llm の自分の項目だけを変え、元に戻すときに戻します。

同じモデルを他のエージェントでも：Grok App を任意のモデルで、fx を任意のモデルで、Aside を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
