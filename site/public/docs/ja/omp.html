omp を任意のモデルで

omp（oh-my-pi、omp コマンド）は Pi のフォークで、ターミナルのコーディングエージェントです。仕事の種類ごとにモデルのロールがあり、セッションは default、サブエージェントは task、小さな仕事は smol、レビューは slow、ほかに plan や commit などがあります。magpie が models.yml に magpie という名前のプロバイダーを加え、選んだロールをそこに向けると、omp の各ロールが DeepSeek、GLM、Kimi、Qwen、Claude、ChatGPT サブスクリプションなど magpie の任意のモデルで動きます。

omp の設定

  1. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  2. エージェント ページで omp のモデルを選ぶまず default ロールのモデルを選び、必要ならほかのロールと思考レベルも選びます。コマンドラインの magpie oh-my-pi も同じエージェントです。
  3. 新しいセッションを始めるomp の新しいセッションは default ロールのモデルで始まります。
ターミナル
magpie omp deepseek/deepseek-v4-pro

config.yml と models.yml

omp の設定は ~/.omp/agent/config.yml にあります。PI_CONFIG_DIR は ~/.omp の名前を変え、PI_CODING_AGENT_DIR は agent フォルダーを動かします。各ロールのモデルは modelRoles に「プロバイダー/モデル」で書かれ、magpie のモデルは magpie/<プロバイダー>/<モデル>、末尾に :レベル を付けられます。

ターミナル
# ~/.omp/agent/config.yml
modelRoles:
  default: magpie/deepseek/deepseek-v4-pro
  slow: magpie/…:high
enabledModels:
  - …
  - magpie/**

隣の models.yml では、magpie のプロバイダーはこのコンピューターではキー不要（auth: none）で、models には各モデルのコンテキストウィンドウ、一回の応答の上限、画像を読めるか、使える思考レベル、100 万トークンあたりの価格が付きます。価格があると omp は呼び出しごとの費用を数えられます。ないと magpie のモデルは omp 同梱のモデルに当たらず、費用はすべて 0 になります。models.yml の自分のプロバイダーや modelOverrides などはそのままです。

ターミナル
# ~/.omp/agent/models.yml
providers:
  magpie:
    baseUrl: http://127.0.0.1:3425/v1
    auth: none
    models:
      - id: deepseek/deepseek-v4-pro
        …

ロールごとのモデル

default はセッションが始まるモデルです。task はサブエージェント用で、scout と sonic は smol、reviewer は slow で動きます。未設定なら task は親セッションのモデル、smol と slow は default のモデルを使います。plan は計画モード、vision は画像、advisor はセカンドオピニオン（未設定なら slow が先）、commit はコミットメッセージ、tiny はセッション名を付け、memory は tiny に従います。default 以外のロールは自分の思考レベルを持てます。たとえばセッションは medium、slow は high です。レベルは minimal、low、medium、high、xhigh、max で、16.4.0 より前の omp は max を受け付けないので xhigh になります。magpie の 設定 › モデル › 画像で選んだ画像モデルは、omp 18.7.0 から omp 自身の Roles ビューの画像ロールに出ます。

enabledModels

enabledModels にモデルがある間、新しいセッションはそのリストに縛られます。default のモデルがリストになければ始まらず、omp はリストから別のモデルを選びます。そこでリストがあるときは magpie が magpie/** を加え、omp のピッカーと Ctrl+P にも magpie の全モデルが出るようにします。リストは自分のものです。magpie は既存のエントリ、順序、コメントを残し、リストがなければ作らず、フォルダーに限ったエントリには触れません。ほかのロールはこのリストに縛られません。

モデルごとに自分の API

Pi と同じく、各モデルはプロバイダー本来の API で呼ばれ、ゲートウェイは翻訳せずにそのまま中継します。OpenAI の Responses、Anthropic の Messages、Gemini の /v1beta です。Chat 経由だと、Claude はツール呼び出しの間で思考の署名を失っていました。Chat にはそれを置く場所がないからです。magpie は omp にセッション id と自分の名前をヘッダーで送らせるので、使用量では omp として数え、「ゲートウェイの会話を記録」も omp の会話を残します。

プロファイルと WSL

~/.omp/profiles/<名前>/agent の各プロファイルはそれぞれ別の omp で、エージェントページに omp#<名前> として、自分の config.yml と models.yml を持って並びます。OMP_PROFILE が選ぶものは既定の行です。WSL のディストリビューションの omp はそちらの ~/.omp/agent を使い、NAT 越しに Windows のアドレスへ届くときは、ゲートウェイをネットワークで共有するキーをプロバイダーに付けます。

元に戻す

magpie はロールを引き継ぐ前に元の値を保存し、ロールを戻すとそれをそのまま戻します。YAML のリストだったものは書かれていた形で戻ります。どこかのロール、フォールバックチェーン、タスクエージェントが magpie のモデルを使っている間は magpie のプロバイダーを models.yml に残し、使うものがなくなれば、magpie が加えた enabledModels のエントリと一緒に外します。

ターミナル
magpie omp default

よくある質問

omp で DeepSeek、GLM、ChatGPT サブスクリプションを使えますか？

使えます。magpie のエージェントページで omp の default ロールに via magpie のモデルを選び、新しいセッションを始めます。

smol、slow、commit にそれぞれ別のモデルを使えますか？

使えます。各ロールに magpie のモデルを選べ、default 以外は思考レベルもそれぞれ持てます。

default を設定したのに omp が別のモデルで始まるのはなぜですか？

enabledModels にモデルがあると、default のモデルがそこに入っている必要があります。magpie は magpie/** を加え、元に戻すと外します。

元に戻すと設定も戻りますか？

戻ります。各ロールは元の値に戻り、magpie を使うものがなくなればプロバイダーと enabledModels のエントリも外れます。

同じモデルを他のエージェントでも：Pi を任意のモデルで、StepCode を任意のモデルで、MothX を任意のモデルで、Ante を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
