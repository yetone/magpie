Ante を任意のモデルで

Ante は antigma.ai のターミナルのコーディングエージェントで、コマンドは ante です。同梱のプロバイダーに加え、catalog.json に自分のプロバイダーを重ねられます。magpie がそこに magpie という名前のプロバイダーを加え、settings.json でそこから起動させると、Ante が DeepSeek、GLM、Kimi、Qwen、Claude、ChatGPT サブスクリプションなど magpie の任意のモデルで動きます。

Ante の設定

  1. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  2. エージェント ページで Ante のモデルを選ぶvia magpie のモデルを選びます。
  3. Ante を再起動Ante は catalog.json をプロセスごとに一度だけ読むので、起動中のものは再起動が要ります。
ターミナル
magpie ante deepseek/deepseek-v4-pro

catalog.json

ファイルは ~/.ante/catalog.json、ANTE_HOME があれば $ANTE_HOME/catalog.json です。providers のキーが --provider に渡す名前です。magpie のエントリはゲートウェイの /v1 を指し、wire_style は OpenAiCompatible、つまり Ante が Chat Completions で話す形で、ゲートウェイはどのモデルもこれで受けます。magpie のモデルは Ante のモデルピッカーである preferred_models に並びます。

ターミナル
// ~/.ante/catalog.json
{
  "providers": {
    "magpie": {
      "display_name": "magpie",
      "base_url": "http://127.0.0.1:3425/v1",
      "wire_style": "OpenAiCompatible",
      "preferred_models": [
        { "id": "deepseek/deepseek-v4-pro", "display_name": "…",
          "context_limit": …, "max_tokens": …, "supported_efforts": […] }
      ]
    }
  }
}

エントリに auth はありません。ゲートウェイはこのコンピューターで待ち受け、そこからのリクエストはキーなしで通します。Ante は auth ブロックのないプロバイダーをサインイン済みとして扱います。bearer env_key を書くと Ante の環境変数にキーを置くことになり、それは自分で決めることです。magpie のエントリに自分で加えた auth、http_headers、extra_body は残り、ネットワークで共有したゲートウェイや WSL から使うときはそれでキーを送ります。自分のプロバイダーと models の部分には触れません。support_vision も書きません。Ante は言われない限りモデルが画像を見られるとみなし、false にするとゲートウェイの手前で画像を捨ててしまいます。ゲートウェイなら画像を見られないモデルに画像を説明できます。ルーティンググループには思考レベルを付けません。各ターンにどのメンバーが答え、何を受け付けるかはグループが決めるからです。

settings.json

カタログに載るだけでは足りません。セッションが始まるプロバイダーは ~/.ante/settings.json の provider と model で決まり、どちらもなければ Ante はカタログ順で最初のサインイン済みプロバイダーを使います。同梱のものが先に並びます。そこで magpie はこの二つも書き、元の値を保存します。

ターミナル
// ~/.ante/settings.json
{ "provider": "magpie", "model": "deepseek/deepseek-v4-pro" }

Ante の再起動

Ante はプロセスごとに一度カタログを読むので、変更には再起動が要ります。読み込みは寛容で、読めないエントリは通知付きで飛ばし、残りは読み込みます。そのため壊れたエントリがあっても失うのは magpie のプロバイダーだけで、自分のものは残ります。

元に戻す

元に戻すと、Ante の元の provider と model を戻し（なければ空のままにして Ante の自動検出に任せ）、カタログから magpie のエントリを外します。空になった providers と magpie が作ったファイルも消します。magpie の設定中に Ante 自身の /providers で選んだものは自分の選択なので、そのまま残ります。

ターミナル
magpie ante default

よくある質問

Ante で DeepSeek、GLM、ChatGPT サブスクリプションを使えますか？

使えます。magpie のエージェントページで Ante に via magpie のモデルを選び、Ante を再起動します。

カタログに magpie があるのに Ante が使わないのはなぜですか？

Ante は settings.json の provider と model で始まり、なければ同梱の最初のサインイン済みプロバイダーを使います。magpie はこの二つも書きます。

magpie のエントリに API キーがないのはなぜですか？

ゲートウェイはこのコンピューターではキー不要で、Ante は auth のないプロバイダーをサインイン済みとみなします。自分で加えた auth は残ります。

元に戻すと設定も戻りますか？

戻ります。元の provider と model が戻り、magpie のエントリは外れます。その間に Ante で選んだものは残ります。

同じモデルを他のエージェントでも：omp を任意のモデルで、StepCode を任意のモデルで、Avibe を任意のモデルで、Aside を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
