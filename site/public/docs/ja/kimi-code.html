Kimi Code

仕組み Kimi Code を接続 各モデルに書く内容 反映のタイミング 自分の設定 元に戻す よくある質問

ドキュメント · ガイド

Kimi Code を任意のモデルで

Kimi Code は Moonshot のコーディング Agent kimi で、設定に自分のプロバイダとモデルを加えられます。magpie はそこに自分のモデルを加えるので、kimi で Kimi だけでなく magpie にある任意のモデルを使えます：DeepSeek、GLM、Qwen、OpenAI や Anthropic のキー、ChatGPT や Copilot のサブスク。kimi にキーを貼る必要はありません。他のエージェントで Kimi のモデルを使うには Claude Code や Codex で Kimi を参照してください。

Kimi Code の設定は ~/.kimi-code/config.toml（$KIMI_CODE_HOME）です。magpie は Kimi 独自の型で magpie という名前のプロバイダを加え、ゲートウェイのアドレスと専用のキーを書き、モデルごとに [models."magpie/<provider>/<model>"] テーブルを一つ書くので、magpie のモデルが kimi の /model に並びます。そして default_model を選んだモデルにします。思考は reasoning_content として双方向に渡り、ゲートウェイは各リクエストをモデルのプロバイダ向けに変換します。旧 Python 版 kimi-cli は Kimi Code のフォルダがないときだけ ~/.kimi（$KIMI_SHARE_DIR）に設定します。Kimi Code は引き継いだ後 ~/.kimi-code しか読まないからです。WSL の Kimi Code も同じように設定します。

Kimi Code を接続

  1. magpie にプロバイダを追加プロバイダ タブで API キーを追加するか、サブスクにサインインします。
  2. Kimi Code の行でモデルを選ぶAgent タブで magpie の下のモデルを選びます。
  3. kimi で使うKimi Code は実行中に変更を読みます。magpie のモデルはすべて /model にも並びます。
ターミナル
magpie kimi deepseek/deepseek-v4-pro    # Kimi Code を DeepSeek で
magpie kimi                             # Kimi Code の今のモデル

各モデルに書く内容

  • 名前とコンテキストkimi のピッカーとステータス行に出る名前と max_context_size。kimi が間に合うように圧縮できます。
  • 思考レベルレベルのあるモデルには thinking と、Kimi Code の思考ピッカー用の support_efforts と default_effort。常に考えるモデルには always_thinking。
  • 画像とツール画像を受け取るモデルには image_in、Kimi Code では tool_use、magpie が返答の上限を知っているモデルには max_output_size。

magpie のテーブルに自分で設定した値（たとえば default_effort）は、次の同期でもそのまま残ります。

反映のタイミング

Kimi Code 2.x は設定を監視しているので、開いているセッションにもすぐ新しいモデルが入ります。Web 版やデスクトップ版では Settings › Providers を開き直すかページを再読み込みすると、ピッカーに出ます。旧 kimi-cli は起動時に設定を読むので、開いている kimi セッションを再起動してください。

自分の設定

Kimi Code のサインイン、自分のプロバイダとモデルはそのまま残り、Kimi Code の行にも magpie のモデルと並んで出ます。magpie プロバイダのテーブルに自分で加えたキー（custom_headers や env）も残ります。それまでの default_model は取っておき、あとで戻します。

元に戻す

行で自分のモデルを選ぶか、行から magpie を外すか、magpie kimi default を実行します。magpie は前の既定モデルを（Kimi にまだあれば）戻し、自分のモデルテーブルとプロバイダを削除します。

よくある質問

Kimi Code で Kimi 以外のモデルを使えますか？

使えます。magpie にあるモデルはすべて kimi の /model に並びます：DeepSeek、GLM、Qwen、GPT、Claude など。

Kimi Code で ChatGPT サブスクを使えますか？

使えます。magpie で ChatGPT にサインインし、Kimi Code の行で magpie の下の GPT モデルを選びます。kimi のリクエストは magpie に届き、magpie がサブスクを使います。

旧 Python 版 kimi-cli でも使えますか？

使えます。~/.kimi-code がないとき、magpie は kimi-cli の ~/.kimi に書き、Kimi Code だけが読むキーは書きません。変更後は開いているセッションを再起動してください。

WSL の Kimi Code でも使えますか？

使えます。magpie は WSL ディストリの Kimi Code も設定し、プロバイダはディストリから届くゲートウェイを指します。

同じモデルを他のエージェントでも：OpenCode で他のモデル、Claude Code で他のモデル、Qwen Code を任意のモデルで、Pi を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
