ドキュメント · ガイド

VS Code を任意のモデルで

VS Code 内蔵の Chat（GitHub Copilot Chat）には VS Code Stable 1.122 から Custom Endpoint プロバイダーがあり、GitHub へのサインインや Copilot プランなしで他社のモデルを使えます。モデルのグループは settings.json の隣の chatLanguageModels.json にあり、VS Code はこのファイルを監視して変更を読み直します。magpie はそこに自分のグループを加え、VS Code の Chat は DeepSeek、GLM、Kimi、Qwen、Claude、ChatGPT サブスクなど magpie の任意のモデルで動きます。

VS Code を設定する

  1. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  2. エージェント ページで VS Code のモデルを選ぶvia magpie のモデルを選びます。
  3. VS Code の Chat でモデルを選ぶmagpie のモデルは Chat のモデル選択の magpie グループにあります。表示されなければ VS Code で Developer: Reload Window を実行します。

chatLanguageModels.json

magpie は {"vendor": "customendpoint", "name": "magpie"} のグループを書き、magpie のカタログを並べます。各モデルはゲートウェイの /v1/chat/completions を指し、ツール呼び出しをオンにします。エージェントモードはツールを呼べるモデルしか表示しないためです。

ターミナル
// chatLanguageModels.json (beside settings.json)
[
  {
    "name": "magpie",
    "vendor": "customendpoint",
    "apiType": "chat-completions",
    "models": [
      {
        "id": "deepseek/deepseek-v4-pro",
        "name": "…",
        "url": "http://127.0.0.1:3425/v1/chat/completions",
        "toolCalling": true,
        "vision": …,
        "contextWindow": …,
        "maxOutputTokens": …,
        "requestHeaders": { "Authorization": "Bearer " }
      }
    ]
  }
]

グループの apiKey はこのファイルに書けず、VS Code はシークレットストレージからしか読みません。そこで各モデルは requestHeaders の Authorization で magpie のトークンを送り、Custom Endpoint のモデルはそれをキーの代わりに使うので、キーを求められることはありません。あなた自身のグループはそのままです。

新しいチャットのモデル

新しいチャットのモデルは chat.defaultModel 設定で決まり、magpie はカタログの ID にします。Chat のモデル選択で選んだモデルは VS Code のストレージに保存され、この設定には入りません。

ターミナル
// settings.json
"chat.defaultModel": "deepseek/deepseek-v4-pro"

プロファイルと Insiders

既定のプロファイルの chatLanguageModels.json は User フォルダーにあり、他のプロファイルはそれぞれ自分のものを持ちます。magpie はすべてのプロファイルにグループを書き、後で作られたものにも加えます。VS Code Insiders は自分の User フォルダーと自分の行を持ち、同じように設定されます。ポータブル版の VS Code はデータフォルダーにファイルを置き、magpie はそこも見つけます。

VSCodium

VSCodium には内蔵の Copilot Chat がなく、Marketplace のものを入れます。その最後のリリース（0.48.1）には Custom Endpoint がなく、OpenAI Compatible プロバイダー（customoai）があります。magpie はインストールされた拡張の package.json が宣言する方に合わせて書きます。OpenAI Compatible は同じファイルの同じグループを使い、requestHeaders の Authorization を捨てるため、トークンは x-api-key で送ります。このプロバイダーは Copilot Chat が個人の Copilot プランのある GitHub にサインインしている間だけ表示されます。

さらに VSCodium の Chat 機能をオンにし（chat.disableAIFeatures=false）、product.json に GitHub.copilot-chat の defaultChatAgent と trustedExtensionAuthAccess が必要です。その後 Developer: Reload Window を実行します。エージェントページにも表示されます。

元に戻す

magpie で VS Code 自身のモデル（Copilot の Auto など）を選ぶと、chat.defaultModel をそのモデルにし、他のプロファイルはそれぞれ元に戻し、グループは Chat の選択肢に残ります。magpie で VS Code をオフにすると、各プロファイルの chat.defaultModel を元に戻し、グループも取り除きます。

よくある質問

Copilot プランなしで VS Code の Chat に DeepSeek や GLM を使えますか？

はい。VS Code 1.122 からの Custom Endpoint プロバイダーは GitHub サインインも Copilot プランも不要で、magpie が chatLanguageModels.json にグループを書きます。

Chat に magpie のモデルが表示されないのはなぜですか？

VS Code 1.122 以降が必要です。そのうえで VS Code で Developer: Reload Window を実行してください。

magpie のキーはどこに入りますか？

VS Code は apiKey をシークレットストレージからしか読まないため、magpie は各モデルの requestHeaders にトークンを入れ、キーを求められることはありません。

VSCodium でも使えますか？

はい。Marketplace の Copilot Chat が必要で、その OpenAI Compatible プロバイダーは個人の Copilot プランのある GitHub にサインインしている間だけ表示されます。

同じモデルを他のエージェントでも：Claude Science を任意のモデルで、Claude Desktop を任意のモデルで、mu を任意のモデルで、WorkBuddy を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
