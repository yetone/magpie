Reasonix Studio を任意のモデルで

Reasonix Studio 2.x とその CLI は同じ config.toml と .env を使います。magpie はそこに magpie という名前の provider を加え、ローカルの magpie ゲートウェイに向けるので、Reasonix の executor と planner それぞれに DeepSeek、GLM、Kimi、Qwen、GPT、ChatGPT サブスクリプションなど magpie の任意のモデルを選べます。他の provider、キー、プロジェクトやセッションの設定はそのままです。

Reasonix の設定

  1. magpie の エージェント ページを開くReasonix Studio の行を探します。モデルの欄は executor です。
  2. magpie のモデルを選ぶ一覧は Reasonix Studio 自身のモデルと via magpie のモデルの 2 グループです。後者を選ぶと magpie が provider とキーを書き、default_model を magpie/<モデル> にします。
  3. 必要なら effort と planner を選ぶ推論レベルのあるモデルは effort を選べます。planner は別のモデルにするか、off で個別の planner をなくせます。
ターミナル
magpie reasonix magpie/deepseek/deepseek-v4-pro   # executor
magpie reasonix effort high
magpie reasonix planner magpie/deepseek/deepseek-v4-flash # a separate planner, or: off

書かれる内容

Reasonix のフォルダーは REASONIX_HOME、なければ Windows では %APPDATA%\reasonix、それ以外では ~/.reasonix です。WSL の Reasonix は Linux の ~/.reasonix を使い、ディストリビューションから届くアドレスでゲートウェイを書きます。magpie が書く内容：

ターミナル
# ~/.reasonix/config.toml
default_model = "magpie/deepseek/deepseek-v4-pro"

[[providers]]
name = "magpie"
kind = "openai"
base_url = "http://127.0.0.1:3425/v1"
api_key_env = "MAGPIE_REASONIX_API_KEY"
models = ["…", "…"]
default = "deepseek/deepseek-v4-pro"
reasoning_protocol = "openai"
no_proxy = true

[providers.model_overrides."deepseek/deepseek-v4-pro"]
supported_efforts = ["…"]
context_window = …
max_output_tokens = …

# ~/.reasonix/.env
MAGPIE_REASONIX_API_KEY=…

各モデルにはコンテキストウィンドウ、最大出力、画像対応、推論レベルが付き、推論レベルのないモデルは reasoning_protocol = "none" です。magpie のモデルが変わると provider を更新します。Studio に [desktop] provider_access があれば magpie を加えます。キーは .env にだけ書き、config.toml には変数名だけを書きます。

magpie が触るのは自分の項目だけです。magpie が作っていない magpie provider がある、別の provider が MAGPIE_REASONIX_API_KEY を使っている、.env に同じ変数が 2 回ある、のいずれかなら上書きせずエラーにします。元に戻すときに default_model を復元するため、magpie は自分の設定フォルダーに復元記録を置きます（設定のみで、上流の認証情報は含みません）。

executor と planner

executor は default_model、planner は [agent] planner_model で、それぞれ magpie か Reasonix 自身の provider から選べます。planner が magpie を使っている間は、executor を自分のモデルに戻しても magpie の provider は残ります。

反映されるタイミング

Reasonix Studio 2.x とネイティブ 1.39.x/2.x CLI は起動時にグローバル設定を読むので、変更後は新しいプロセスを起動してください。プロジェクトやセッションで指定したモデルは executor と planner より優先されます。

元に戻す

既定に戻すと magpie は自分が足した分だけを取り消します。magpie provider を消し、default_model を接続前の値に戻し（なければ消し）、provider_access から magpie を外し、.env から magpie のキーを消します。magpie が作ったファイルは空になれば削除します。後から自分で選んだモデルや、他の provider とキーの変更は残ります。一覧の Reasonix Studio グループからモデルを選び直しても戻せます。

ターミナル
magpie reasonix default

よくある質問

Reasonix Studio で DeepSeek、GLM、ChatGPT サブスクリプションを使うには？

magpie のエージェントページで Reasonix Studio の executor に via magpie のモデルを選びます。magpie が config.toml に magpie provider、.env にキーを書き、default_model を magpie/<モデル> にします。

planner を別のモデルにできますか？

できます。planner 欄は [agent] planner_model に書き、別の magpie モデル、Reasonix 自身のモデル、off を選べます。

変えても Reasonix に反映されません。

Reasonix は起動時にグローバル設定を読みます。新しい Studio か CLI のプロセスを起動してください。プロジェクトやセッションのモデル指定も優先されます。

自分の provider やキーは変わりますか？

いいえ。magpie が増減するのは magpie という provider と MAGPIE_REASONIX_API_KEY だけで、自分で作っていない同名の項目があればエラーにして上書きしません。

同じモデルを他のエージェントでも：jcode を任意のモデルで、Crush を任意のモデルで、OpenCode で他のモデル、AtomCode を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
