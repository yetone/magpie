Azure OpenAI

概要 追加する デプロイがモデル エージェントで使う API Management とヘッダー 補足

ドキュメント · ガイド

Azure OpenAI を Codex・Claude Code などのエージェントで使う

Azure OpenAI は、自分の Azure リソースで OpenAI のモデルや、Kimi・DeepSeek・Grok などほかの提供元のモデルを提供します。magpie の azure プリセットは、そのリソースを Codex・Claude Code・OpenCode などにつなぎます。エンドポイントとキーはリソース自身のもので、モデル ID はデプロイの名前です。

追加する

  1. エンドポイントとキーを確認する。Azure ポータルでリソースの「キーとエンドポイント」を開き、エンドポイントとキーをコピーします。
  2. 追加する。アプリで Azure OpenAI を選び、エンドポイント に貼り付けるか、CLI で追加します。
ターミナル
magpie provider add azure  url=https://my-resource.openai.azure.com
magpie provider test azure

アドレスはどの形でも構いません。https://<リソース>.openai.azure.com、…/openai、…/openai/v1、api-version 付きの従来のデプロイ URL、リソース名だけでも使えます。magpie はどれもリソースの v1 API（/openai/v1、2025 年 8 月から一般提供）に問い合わせます。Chat Completions・Responses・モデル一覧は OpenAI と同じパスにあり、api-version は不要です。.openai.azure.com・.cognitiveservices.azure.com・.services.ai.azure.com のホストに対応します。

キーは api-key ヘッダーで送り、Bearer にはしません。Azure の Bearer は Entra ID トークンだからです。

デプロイがモデル

追加すると、magpie はキーでリソースにデプロイ一覧を問い合わせ、その名前がモデル ID になります。データプレーンが一覧を返さないときは v1 API のモデル一覧を使いますが、これは各デプロイがモデル名どおりに名付けられている場合にだけ一致します。どちらも取れないときは、デプロイ名を入力するようエラーが案内します。

ターミナル
magpie provider models azure my-gpt-5-5 my-gpt-6-sol

Azure はほかの提供元のモデルもホストしており、models.dev では推論レベルなしで載っているため、magpie はこの一覧を提供元自身の情報としては扱いません。

エージェントで使う

Codex は Responses を使い、Claude Code など Anthropic のエージェントは magpie が Azure の API に変換します。

ターミナル
magpie codex azure/my-gpt-5-5
magpie claude azure/my-gpt-5-5

API Management とヘッダー

リソースの前に API Management ゲートウェイ（またはリソースのホストではないアドレス）がある場合、magpie は指定した URL をそのまま使い、v1 API に移しません。エディターの ヘッダー でヘッダーを追加でき、値の ${sessionId}・${threadId}・${subagentId} は会話の ID に置き換わります。ゲートウェイが 1 つの会話を 1 つのアカウントに固定できます。

ターミナル
magpie provider set azure 'header.X-Session=${sessionId}'

補足

  • ほかのアプリから取り込んだ Azure のプロバイダーも azure プリセットになり、リソースの v1 API を使います。
  • Azure の content_filter は、リクエストの誤りではなく提供元の安全フィルターとして扱われます。ルーティンググループの別のアカウントやモデルが答えられることがあります。
  • Codex が返す推論アイテムは、そのまま Azure に転送するリクエストでは外します（store が true のときを除く）。Azure も OpenAI と同じく保存済みアイテムからその ID を探し、見つからないと 400「Item with id 'rs_…' not found」を返すためです。
  • OpenAI の Decisions API（/v1/decisions）も Azure の /openai/v1/decisions に送れます。モデルはデプロイ名です。

よくある質問

magpie は Azure OpenAI に対応していますか？

対応しています。azure プリセットでリソースのエンドポイントとキーを入れると、/openai/v1 の v1 API にキーを api-key ヘッダーで送り、デプロイをモデルとして一覧にします。

モデル ID には何を入れる？

モデル名ではなくデプロイ名です。magpie がリソースにデプロイ一覧を問い合わせ、取れないときは magpie provider models azure <デプロイ…> で入力します。

api-version は必要ですか？

不要です。magpie は Azure の v1 API を使い、従来の /openai/deployments/…?api-version= のアドレスも v1 API に移します。

リソースの前に API Management ゲートウェイがある場合は？

ゲートウェイのアドレスを入れれば、magpie はそのまま使います。必要なヘッダーはヘッダー欄に追加し、${sessionId} などは会話の ID に置き換わります。
