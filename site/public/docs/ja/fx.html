fx

仕組み fx の設定 settings.json モデル一覧 自分で設定したもの fx の再起動 元に戻す

ドキュメント · ガイド

fx を任意のモデルで

fx（fx.sh、Vercel Labs 製。同名の JSON ビューアーとは別物）は設定を ~/.fx/settings.json に持ちます。provider は使うプロバイダー（gateway、codex、grok、または自分で加えたもの）、models は各プロバイダーのモデル、providers は自分で加えたプロバイダーです。magpie がここに magpie というプロバイダーを加えると、fx が DeepSeek、GLM、Kimi、Qwen、Claude、ChatGPT サブスクリプションなど magpie の任意のモデルで動きます。

fx の設定

  1. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  2. エージェント ページで fx のモデルを選ぶvia magpie のモデルを選びます。fx はよくある名前なので、magpie はコマンドではなく ~/.fx フォルダーで fx を見つけます。
  3. fx を再起動fx は起動時に設定を読みます。
ターミナル
magpie fx deepseek/deepseek-v4-pro

settings.json

magpie のモデルを選ぶと、magpie は provider を magpie に、models.magpie を deepseek/deepseek-v4-pro のようなモデルにし、providers.magpie を書きます。プロトコルは openai-chat-completions、base_url はゲートウェイの /v1、auth は none でキーは要りません。fx の中ではこのモデルは magpie/deepseek/deepseek-v4-pro と表示されます。

ターミナル
// ~/.fx/settings.json
{
  "provider": "magpie",
  "models": { "magpie": "deepseek/deepseek-v4-pro" },
  "providers": {
    "magpie": {
      "protocol": "openai-chat-completions",
      "base_url": "http://127.0.0.1:3425/v1",
      "auth": { "type": "none" },
      "tool_choice_mode": "send",
      "model_metadata": {
        "deepseek/deepseek-v4-pro": { "supports_tool_use": true, "supports_vision": …, "context_window": …, "max_output_tokens": … }
      }
    }
  }
}

fx は自分で加えたプロバイダーに思考レベルを送らないので、思考レベルの選択はありません。WSL の fx も同じように設定され、base_url はそのディストリビューションから見たゲートウェイのアドレスです。

モデル一覧

fx のモデルピッカーに並ぶのは model_metadata です。magpie のカタログのモデルで、どれもツール対応とされ、画像対応かどうか、コンテキスト長、出力上限が付きます。fx はコンテキスト長以上の出力上限を受け付けないので、その場合 magpie は出力上限を書きません。fx が受け付けるのは 256 モデルまでで、超えると設定ファイル全体を拒否するため、magpie は最大 256 個を書き、使用中のモデルを先頭に置いて切り捨てられないようにします。カタログが変わると、fx が接続されている間 magpie が一覧を更新します。

自分で設定したもの

fx のプロバイダーには reviewer_model（auto 権限モードが確認に使うモデル）を設定できます。magpie はこれを書かず、自分で設定したものは残ります。tool_choice_mode は magpie が send と書き、omit に変えたものは残ります。プロトコル、アドレス、auth、model_metadata は magpie が管理します。type none の横に env があると fx が拒否するため、auth は丸ごと書き直します。

fx の再起動

fx は起動時に設定を読みます。モデルを変えたときに fx が動いていれば、magpie は開いている fx セッションを再起動するよう伝えます。

元に戻す

fx 自身のモデルを選ぶと、magpie は providers.magpie と models.magpie を消し、provider が magpie ならそれも消します。fx は magpie なしで使うプロバイダーに戻り、設定がなければ Vercel の AI Gateway です。選んだモデルはそのプロバイダーの models に入り、default ならそれを消して fx 自身の既定モデルにします。

ターミナル
magpie fx default

よくある質問

どの fx のことですか？

Vercel Labs のコーディングエージェント fx（fx.sh）で、設定は ~/.fx にあります。JSON ビューアーの fx とは別のプログラムです。

fx で magpie を使うのに API キーは要りますか？

要りません。fx の中の magpie プロバイダーは auth none で、このコンピューターのゲートウェイにつながります。

fx に magpie のモデルが最大 256 個しか出ないのはなぜですか？

model_metadata が 256 を超えると fx が設定ファイル全体を拒否するため、magpie は最大 256 個を書き、使用中のモデルを先頭にします。

元に戻すと fx はどのプロバイダーを使いますか？

magpie なしで使うプロバイダーです。設定がなければ Vercel の AI Gateway です。

同じモデルを他のエージェントでも：Aside を任意のモデルで、Ante を任意のモデルで、omp を任意のモデルで、Grok App を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
