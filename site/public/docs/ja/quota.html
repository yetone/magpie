サブスクリプションとキーの残り枠を見る

Claude の 5 時間枠はあとどれだけ？Codex の週の枠はいつリセット？DeepSeek の残高は足りる？magpie は各ベンダーに問い合わせ、すべてのサブスクリプションとプランの各枠の使用量と再開時刻を、各キーの残高と並べます。使用量 タブで見られ、CLI とローカル API でも読めます。

magpie quota

magpie quota は、magpie にあるすべてのサブスクリプション、プラン、キーの残りを一覧します。各枠の使用量と再開時刻、各キーの残高を、その場で（または 1 分以内に）ベンダーへ問い合わせます。プロバイダー名を付けるとそれだけを表示します。

ターミナル
magpie quota                       # every subscription, plan and key
magpie quota codex claude --json   # for scripts and agents
magpie quota refresh claude        # read one card again
magpie quota history --days 7 --json
  • --json はスクリプトとエージェント向けで、各項目に lastServedAt（ゲートウェイ経由で最後に答えた時刻）があり、最新のものに last: true が付きます。
  • magpie quota refresh は、使用量 タブのカードの更新ボタンと同じく一枚を読み直します。30 秒以内に読んだものは問い合わせません。
  • Claude アカウントの使用量は、Claude Code が答えるときか /usage を実行したときに伝わります。refresh はそのアカウント自身のフォルダーで Claude Code の /usage を実行して読みます。通常の magpie quota はそうしません。

スクリプトとエージェント向け

ゲートウェイはローカル API でも同じ内容を返します（ポートは設定のゲートウェイアドレス）。別のマシンからは、magpie をローカルネットワークで共有している間だけ、そのキーを API キー（Authorization: Bearer または x-api-key）として届きます。

ターミナル
curl http://127.0.0.1:3425/v1/magpie/quotas
curl 'http://127.0.0.1:3425/v1/magpie/quotas/history?days=7&provider=codex'

magpie 公式のスキル magpie-quota は、エージェントに magpie quota --json を読ませ、magpie quota wait で待たせます。ライブラリ のスキルマーケットの先頭にあります。

通知

サブスクリプションやプランのどれかの枠が指定の割合まで使われたとき（枠ごとに一回）、または残高が指定額以下になったとき（その通貨かクレジットで、それを超えてチャージされるまで一回）、magpie アプリが通知します。どちらも既定はオフで、off で止めます。

ターミナル
magpie quota alert 80              # notify at 80% used, once per window
magpie quota alert --balance 5     # notify when a balance falls to 5 or under
magpie quota alert                 # what is set

枠が戻るまで待つ

magpie quota wait codex は、magpie でオンの Codex アカウントのどれかに枠が戻ると返ります。アカウントのメールやログイン名、<provider>/<account> を書くとそれだけを待ちます。ゲートウェイが動いていなくても自分でベンダーに問い合わせ、最も早いリセットの少し後に（1〜10 分ごとに）読み直し、何を待っているかを stderr に出します。止まった作業をスクリプトで続けるには：

ターミナル
magpie quota wait codex --timeout 6h
until codex exec …; do magpie quota wait codex || break; done

終了コードは、枠が戻れば 0、--timeout（30m、6h）が先に来れば 1、知らない名前なら 2、Ctrl+C なら 130 です。

履歴

magpie quota history は、magpie が読んだ各サブスクリプションとプランの枠の推移で、45 日間保存されます（UTC 時刻、変化したときだけ記録、各枠はリセットごとに区切り）。各枠の最新の読み取りを出し、--json なら --days 日前からのすべてを、/v1/magpie/quotas/history と同じ形で返します。

Codex アカウントのリセット

レート制限のリセットを持つ Codex アカウントは、その回数を表示します。

ターミナル
magpie quota reset                 # spends one held reset; asks first
magpie quota auto-reset on
magpie quota credits off
  • magpie quota reset は一回使って、アカウントの現在の枠を再開させます。取り消せないので先に確認します。--yes なら確認しません。
  • magpie quota auto-reset on は、週の枠を使い切りほかのアカウントも受けられないときに自分で一回使います（週に一回まで、5 時間枠の使い切りでは使いません）。期限切れ間近のものは、枠を使っていれば期限の約 30 分前に使います。既定はオフです。
  • magpie quota credits off は、枠を使い切った Codex アカウントにクレジットを使わせません。ルーティングは使い切りとして扱い、リクエストはほかのアカウント、グループ、フォールバックへ回ります。既定のオンなら作業が続きます。

エージェントごとのトークン使用量とコスト：エージェント・モデル・アカウント・セッションごとの費用と、中継サービスの実際の価格。

よくある質問

Claude Code の 5 時間枠と週の残りはどう見ますか？

magpie quota を実行するか、magpie の 使用量 タブを開きます。Claude アカウントの使用量は Claude Code が答えるか /usage を実行したときに更新され、magpie quota refresh claude で /usage を実行して読み直せます。

Codex の枠が戻ったら自動で続けられますか？

できます。スクリプトで until codex exec …; do magpie quota wait codex || break; done とすると、枠が戻ったときに magpie quota wait が返り、コマンドが再び動きます。

使用量がいっぱいに近づいたら通知できますか？

magpie quota alert 80 で、どれかの枠が 80% に達したとき magpie アプリが通知します。--balance 5 は残高が 5 以下になったときです。どちらも既定はオフです。

エージェントが自分で枠を読めますか？

読めます。magpie quota --json と GET http://127.0.0.1:3425/v1/magpie/quotas は同じ内容を返し、公式スキル magpie-quota がエージェントに読み方と待ち方を教えます。
