Codex で DeepSeek・Kimi・GLM・Claude など他のモデルを使う

Codex が話す API は OpenAI Responses だけです。magpie はあなたのコンピューター上に、追加したすべてのプロバイダについてこの API を話すゲートウェイを置き、Codex の config.toml を代わりに書きます。するとモデルが推論レベル付きで Codex の /model に並びます。

ゲートウェイは 127.0.0.1:3425 で動きます。DeepSeek や Zhipu GLM の Coding Plan のようにプロバイダ自身が Responses API を提供する場合、Codex のリクエストはそのまま渡されます。Kimi、MiniMax、Qwen のように Chat Completions や Anthropic Messages しか提供しない場合や、Claude のサブスクリプションの場合は、magpie がリクエストと応答を変換します。ストリーミングとツール呼び出しも含みます。

中国のモデル

DeepSeek、Kimi と Kimi Code、Zhipu GLM（従量課金または Coding Plan）、Z.ai、MiniMax、Qwen。中国向けエンドポイントがあるものはそれも使えます。

Claude

Claude サブスクリプションのモデル、または Anthropic キーのモデル。

その他

OpenAI 互換または Anthropic 互換の任意の URL とキー、Copilot と Antigravity のアカウント、Ollama、LM Studio。

セットアップ

  1. プロバイダを追加するmagpie の Providers タブで ＋ Add provider を押し、DeepSeek、Kimi、Zhipu GLM、MiniMax、Qwen のいずれかを選んで API キーを貼り付け、保存します。magpie がベンダーに提供モデルを問い合わせます。
  2. Codex のモデルを選ぶAgents タブで Codex の行のモデルをクリックし、deepseek/deepseek-v4-pro などを選びます。一覧の下のスライダーで推論レベルを設定します。magpie は両方を ~/.codex/config.toml に書き込みます。
  3. Codex を再起動するCodex はモデル一覧を起動時に作ります。切り替えたら Codex アプリを再起動し、codex は新しいセッションを開いてください。

ターミナルからも同じことができます：

ターミナル
magpie provider add deepseek sk-…
magpie models                        # すべてのモデルを provider/model で表示
magpie codex deepseek/deepseek-v4-pro
magpie codex effort high
Zhipu GLM の Coding Plan。 Zhipu GLM または Z.ai を追加するときは、キーに合ったプランを選んでください。Coding Plan のキーには専用のエンドポイントがあり、従量課金のエンドポイントに送ると残高がないと返されます。

Codex の /model に並ぶモデル

magpie のモデルは Codex の /model に Codex 自身のモデルと並んで表示されるので、そこでも切り替えられます。各モデルには Codex が動かすのに必要な情報が付いています：推論レベルとデフォルトのレベル、コンテキストウィンドウ、そして Codex が一緒に送るベースの指示です。

どう並ぶかは、Codex のサインイン方法によって変わります：

  • ChatGPT にサインインしている場合。 Codex は自身の OpenAI プロバイダとサインインを保ちます。magpie は openai_base_url で Codex をゲートウェイに向けます。Codex 自身のモデルはこれまでどおりあなたのアカウントで OpenAI に送られ、magpie のモデルが /model に加わります。
  • サインインしていない、または API キーでサインインしている場合。 magpie が Codex のプロバイダになり、一覧は magpie が config.toml の隣に書くカタログファイル magpie-models.json から読まれます。

config.toml で変わること

magpie は ~/.codex/config.toml の必要なキーだけを変更します。コメント、並び順、他の設定はそのまま残ります。

キー設定される値
model選んだモデル
model_reasoning_effort推論レベル（設定した場合）
openai_base_urlゲートウェイのアドレス。自分で設定したベース URL は残ります
model_providermagpie がプロバイダのときは "magpie"
model_catalog_jsonmagpie がプロバイダのときは、カタログファイル magpie-models.json のパス
[model_providers.magpie]name、base_url（ゲートウェイの /v1）、wire_api = "responses"、ゲートウェイのキー。ベンダーのキーは magpie の中に残ります
~/.codex/config.toml
model = "deepseek/deepseek-v4-pro"
model_provider = "magpie"
model_catalog_json = "/Users/you/.codex/magpie-models.json"

[model_providers.magpie]
name = "magpie"
base_url = "http://127.0.0.1:3425/v1"
wire_api = "responses"

これは magpie がプロバイダのときの形で、テーブルにはゲートウェイのキーとヘッダーも入ります。ChatGPT にサインインしている場合は、トップレベルに openai_base_url と model だけが設定されます。[model_providers.magpie] テーブルは一度書かれると残ります。Codex のスレッドは開始時のプロバイダを保つので、magpie で始めたスレッドはそれがないと開き直せません。

OpenAI のモデルに戻す

Codex の行で Codex 自身のモデルを選ぶか、magpie codex default を実行します。magpie は model_provider、model_catalog_json、ベース URL を取り除き、元のプロバイダとモデルを戻します。トップレベルにある自分のプロバイダは残ります。magpie で始めたスレッドは Codex が今使っているプロバイダに移されるので Codex の一覧に表示され、コピーが magpie のゴミ箱に残ります。

Codex で Claude を使う

magpie で Claude のサブスクリプションにサインインします：＋ Add provider から Claude のタイルを選びます。そのモデルは Codex のピッカーに claude/… として並びます。magpie が Codex の Responses リクエストを Anthropic Messages に変換し、応答を戻します。

ターミナル
magpie accounts add claude     # Claude アカウントにサインイン
magpie models | grep '^claude/'
magpie codex claude/…

Claude サブスクリプションでのリクエストは、コンピューターにインストールされた Claude Code を通じて送られるので、Claude Code はインストールしたままにしてください。Anthropic の API キーでも使えます：Anthropic をベンダーとして追加し、anthropic/… のモデルを選びます。

複数のキーでルーティング

  • 1 つのベンダーに複数のキー。 すべてをプロバイダに追加し、それぞれにチェックを入れます。プロバイダの Routing でリクエストの分散方法を決め、Fallback にはクォータ切れや障害のときに使うモデルを並べます。
  • 複数のプロバイダから同じモデル。 2 つのプロバイダが同じモデルを提供すると、magpie はグループ auto/<model> を自動で作ります。それを Codex に選びます。
  • 自分のグループ。 Routing タブの New group で、任意のモデルを 1 つの名前 group/<id> にまとめられます。

ルーティングモードははじめにで説明しています。

プロバイダ別：DeepSeek · Kimi と Kimi Code · GLM Coding Plan · Qwen · MiniMax · Gemini · Grok · Mistral · OpenRouter · GitHub Copilot · Ollama

よくある質問

[model_providers] は自分で書きますか？

いいえ。モデルを選ぶと magpie が Codex の config.toml を書きます。OPENAI_BASE_URL を export する必要もありません。

ChatGPT のサインインはそのまま使えますか？

はい。ChatGPT にサインインしていれば、Codex は自身のプロバイダとサインインを保ちます。Codex 自身のモデルはあなたのアカウントで OpenAI に送られ、magpie のモデルはその隣に加わります。

モデルを選んだのに Codex の /model に表示されません。

Codex はモデル一覧を起動時に読みます。Codex アプリを再起動し、codex は新しいセッションを開いてください。

推論レベルは設定できますか？

はい。Codex の行の推論レベルのスライダー、magpie codex effort high、または各モデルの推論レベルが並ぶ Codex の /model で設定できます。

Codex で使える中国のモデルは？

追加したプロバイダが提供するものなら何でも使えます。magpie には DeepSeek、Kimi、Kimi Code、Zhipu GLM、Z.ai、MiniMax、Qwen のプリセットがあります。それ以外はカスタム URL として追加できます。

magpie を起動しておく必要がありますか？

はい。Codex が magpie 経由のモデルを使っている間は必要です。ゲートウェイはアプリと一緒に動きます。magpie daemon install を使うと、ウィンドウなしのサービスとして動き続けます。

元に戻すには？

magpie で Codex 自身のモデルを選ぶか、magpie codex default を実行します。magpie のキーが取り除かれ、元のプロバイダとモデルが戻ります。

Claude Code も使っていますか？ Claude Code で好きなモデルを使うを参照してください。困ったときは Discord で質問してください。
