プライバシー

プロンプト、返答、キー、アカウントは、使っているプロバイダーにだけ送られます。間に magpie 自身のサーバーはありません。このページは、それ以外に magpie が自分から送るものすべてと、それを止めるスイッチを挙げます。内容はコードから書いており、各節にコードへのリンクがあります。

更新確認、リリースノート、パートナー一覧、アイコンusemagpie.aiオン更新確認は noAutoUpdate。ほかはアプリの動作に必要

毎日のカウント

動いているリリース版の magpie（アプリ、または magpie serve）は、1 日（UTC）に 1 回 PostHog へイベントをまとめて送ります。何人が使っていて、どのエージェント、プロバイダー、モデルを優先して面倒を見るべきかを知るためです。起動時に送り、以後 1 時間ごとに確認し、その日すでに送っていれば何もしません。ソースからのビルドは送りません。

まとめの中には magpie active イベントが 1 つあり、次を含みます。

  • このコンピューターで作ったランダムな ID（16 進 32 文字。あなたやマシンとは無関係）。distinct_id として送ります。
  • magpie のバージョン、kind（app か serve）、システム（$os）とアーキテクチャ。
  • 使っているエージェント、プロバイダー、モデルの数とルーティンググループの数（使っているものの共有をオフにすると送りません）。

その部分をオフにしない限り、エージェント、プロバイダー、モデルごとに magpie uses イベントが続きます。magpie 自身の ID だけで、それぞれ最大 50 個です。

  • エージェント：magpie につないだもの（claude、codex）。WSL のディストリ名や omp のプロファイル名は外します（omp だけ）。
  • プロバイダー：オンのもの。プリセットの ID（deepseek）、サブスクリプションの ID（codex、copilot）、既知のコミュニティプラグインの ID（plugin:kiro）。自分で追加したプロバイダーは custom、それ以外のプラグインは plugin とだけ記録します。
  • モデル：つないだエージェントに設定されたモデルを、プロバイダー ID とベンダーのモデル ID で（deepseek/deepseek-v4）。キーのプロバイダーで models.dev に載っていないモデル ID（ローカルモデル、ファインチューン）は <プロバイダー>/other、自分のプロバイダーのモデルは custom、ルーティンググループは group です。

あわせて magpie partner イベントも送ります。プロバイダー追加シートの先頭に載る各パートナーについて、その ID で、終わった日にシートに表示された回数、行が開かれた回数、キーのページが開かれた回数、そこからプロバイダーが追加された回数です（what：shown、opened、keys、added。1 日にそれぞれ最大 20 回、追加は 5 回）。回数だけで、自分のプロバイダーは含みません。

この部分がオンのとき、magpie は同じ日に、Discover に載っているどのプラグインを入れて（オンにして）いるかを usemagpie.ai に伝え、Discover が各プラグインの利用者数を示せるようにします：POST /api/plugins/report に同じランダムな ID とプラグインの npm パッケージ名、magpie-plugin タグのリポジトリは github:owner/repo（最大 50 個）。フォルダーから入れたもの、非公開リポジトリ、Discover に載っていないパッケージのプラグインは送りません。プラグインのページでのいいねは POST /api/plugins/like で、ID、プラグイン、オンかオフかを送ります。いいねできるのはこのコンピューターに入っているプラグインだけで、いいねしたものは plugin-likes.json に残ります。サイトは直近 7 日に報告した ID の数を数え、報告は 30 日で消します。アドレスはハッシュだけを 1 時間、頻度の制限のために残します。Discover は ID を含まない GET /api/plugins/stats で数を読みます。コードは internal/stats/plugins.go と site/pluginstats.js です。

どのイベントにも $process_person_profile: false が付き、PostHog はこの ID の人物プロファイルを作りません。名前、Base URL、アカウント、キー、プロンプト、返答、使用量は送りません。まとめ全体はこのような形です。

オフにする

次のスイッチで、その一部または全部を止められます。

  • 設定 → プライバシー → ユーザー数に含める をオフ、または settings.json に "noStats": true：毎日のカウント全体。
  • magpie の環境に DO_NOT_TRACK=1 か MAGPIE_NO_STATS=1（空、0、false 以外の値）：設定にかかわらず、毎日のカウント全体。
  • 設定 → プライバシー → 使っているエージェント、プロバイダー、モデル、プラグインを共有 をオフ、または "noUsageStats": true：magpie uses と magpie partner イベント、magpie active の数、プラグインの報告。ID、バージョン、システムは送られます。パートナーの回数も記録しなくなります。
  • 設定 → 情報 → 自動アップデート をオフ、または "noAutoUpdate": true：magpie が自分から usemagpie.ai に新しいバージョンを尋ねること（そうでなければ 6 時間ごと）。カウントの一部ではありません。

設定の変更は次の 1 時間ごとの確認で反映され、再起動はいりません。settings.json は magpie のフォルダーにあります（下記）。

settings.json 
{
  "noStats": true,
  "noUsageStats": true,
  "noAutoUpdate": true
}

MAGPIE_STATS_HOST はカウントを別のホストへ送ります（テスト用で、設定するとソースからのビルドも送ります）。

コンピューター上のファイル

ファイル内容
install-idランダムな ID。初めてカウントを送るときに作られます
stats-sent最後に送った日（UTC）。1 日 1 回にするため
plugin-likes.jsonDiscover でいいねしたプラグイン
partner-counts.json（キャッシュフォルダー）まだ送っていないパートナーの回数。最大 14 日分

install-id と stats-sent は magpie のフォルダーにあります。macOS と Linux では ~/.config/magpie、Windows では %USERPROFILE%\.config\magpie、$XDG_CONFIG_HOME が設定されていれば $XDG_CONFIG_HOME/magpie、ポータブル版ではそのデータフォルダーです。partner-counts.json は ~/.cache/magpie（$XDG_CACHE_HOME/magpie、ポータブル版ではデータフォルダーの cache）にあります。どれも削除できます。install-id を消すと次の送信で新しいランダムな ID が作られ、新しいユーザーとして数えられます。カウントをオフにすれば、どれも再び書かれません。

リクエストアーカイブ（使用量ページのリクエスト一覧の上にあるリクエストアーカイブスイッチ）は既定でオフです。同期に S3 バケットがないときにオンにすると、ゲートウェイを通る各呼び出しのヘッダーと本文を、S3 アーカイブと同じようにシークレットを伏せて、magpie のフォルダーの request-archive に 1 呼び出し 1 ファイルで保存します。読めるのはあなたのユーザーだけです。上限は 1 GiB（settings.json の requestArchiveLocalMB）で、超えると古い呼び出しから削除します。このスイッチはこのコンピューターだけのもので、同期で別のコンピューターでオンになることはありません。S3 バケットがあるときはバケットに送られ、ここには何も書かれません。フォルダーはいつでも削除できます。

アプリは自分のしたことをログ app.log に書きます。macOS では ~/Library/Logs/magpie、Windows では %LOCALAPPDATA%\magpie\logs、Linux では ~/.local/state/magpie です（magpie のログはどこにありますか？）。読めるのはあなたのユーザーだけです。magpie がしたことと出会ったエラーを記録し、キー、プロンプト、返答は記録しません。あなたが送らない限り、このコンピューターから出ません。上限は 5 MiB で、古いもの 1 つ（app.old.log）を残します。いつでも削除できます。

usemagpie.ai に見えるもの

magpie はプライバシー設定にかかわらず、どのアプリも自分の更新サーバーに尋ねるのと同じように、自分のサイトにいくつか尋ねます。どのリクエストにもインストール ID やアカウントは付きません。

  • /api/latest：更新情報。noAutoUpdate がオンでなければ 6 時間ごと。?lang= であなたの言語のノートを取ります。設定 → 情報 → アップデートチャネルが安定版なら ?channel=stable も付けます。どちらもあなたが誰かは含みません。/api/notes は更新後の「新機能」です。
  • /files/<バージョン>/<ファイル>：更新とインストーラがダウンロードするリリースファイルで、Cloudflare R2 から配信されます。サイトにないファイルは github.com へ転送されます。何も計測しません。
  • /api/partners：プロバイダー追加シートのパートナー一覧。6 時間ごと。パートナーが載っている間、10 回に 1 回の取得を Cloudflare が示す国とともに magpie partners fetch として数えます。
  • /go/<パートナー>/site と /go/<パートナー>/keys：パートナーの公式サイトとキーのページへのリンクをブラウザーで開くと、移動の前に magpie partner go（どのパートナーか、どのリンクか、地域、国）として数えます。
  • /api/plugins/stats：Discover の各プラグインの利用者数といいねの数。多くて 1 時間に 1 回で、ID は含みません。プラグインの報告といいねは ID を含み、共有がオンのときだけ送ります。
  • /api/icon?url=…：プラグイン、インポートリンク、ライブラリが示すアイコンはここを経由して取得するので、アイコンのあるホストに見えるのはあなたではなく Cloudflare のアドレスです。画像を中継するだけで、数えることも記録することもしません。

サイト自身のページ（このドキュメント、ホーム）には Cloudflare Web Analytics と PostHog Web Analytics（us.i.posthog.com）が入っており、どちらも Cookie は使いません。PostHog はこのサイト用のランダムな訪問者 ID をブラウザのローカルストレージに保存し、再訪問を同じ訪問者として数えます。受け取るのは各ページのアドレス、参照元のページ、ページ上でクリックしたもの（入力内容は含みません）、ページとそのリクエストの読み込み速度、ページで起きたエラー、ブラウザ・OS・画面サイズ、IP アドレスの国と都市、そして訪問の録画（ページの表示、マウスの動き、クリック、スクロール、コンソールのメッセージ）で、入力欄はすべて伏せられます。ブラウザが Do Not Track か Global Privacy Control を送っていれば何も送りません。PostHog へのリクエストはこのサイトの usemagpie.ai/r/ を経由し、IP アドレスとともに PostHog へ渡されます。サイトの Cookie は渡しません。/download のリンクを開くか install.sh を取得すると、PostHog に別のカウントが 1 件送られます。どのファイルか、国、ブラウザかコマンドか、だけで、ID も IP アドレスも含みません。アプリはどちらも読み込みません。コードは site/worker.js です。

magpie が取得する公開リスト

モデルの価格と名前のために models.dev のカタログ（models.dev/api.json）を、あなたの通貨で価格を表示するために open.er-api.com から米ドルの為替レート（12 時間保持）を取得します。プラグインとその更新は npm レジストリから、ライブラリの項目は GitHub から取得します。どれも公開データの単なるダウンロードで、あなた、あなたのプロバイダー、使用量については何も送りません。ただし、どのリクエストとも同じく、これらのホストにはあなた（またはプロキシ）の IP アドレスが見えます。magpie は各プロバイダーにも、あなた自身のキーやサインインで残量とモデル一覧を尋ねます。設定 → 利用枠 → 利用枠の読み込み → 手動のみ で、頼んだときに限れます。

OTLP エクスポート

magpie はゲートウェイの各リクエストを、あなたの OpenTelemetry コレクター（Langfuse など）へエクスポートできます。既定ではオフで、送り先はあなたが設定したエンドポイントだけです。私たちには送りません。オンにすると、リクエストごとのスパン（エージェント、プロバイダー、モデル、リクエストに使われたゲートウェイキーの名前（あなたが付けた名前で、キーそのものは送りません）、トークン数、ステータス、時間、推定コスト）を送ります。別のスイッチで、メトリクス、ローカルのエージェント会話、リクエストと返答の本文（シークレットはマスク）を加えられます。設定 → オブザーバビリティ でオンにするか、magpie serve では MAGPIE_OTEL_ENABLED、MAGPIE_OTEL_ENDPOINT、MAGPIE_OTEL_HEADERS、MAGPIE_OTEL_METRICS、MAGPIE_OTEL_SESSIONS、MAGPIE_OTEL_BODIES、MAGPIE_OTEL_BODIES_WHOLE を使います。エンドポイントだけではオンになりません。Langfuse なら、そこで Langfuse を選び、ホストとプロジェクトの 2 つのキーを入力すると、magpie がエンドポイントと認証を作ります。各エクスポートの resource は service.name=magpie と、あなたが OTEL_RESOURCE_ATTRIBUTES と OTEL_SERVICE_NAME に自分で設定した値（サーバー名など）だけです。マシンの情報は調べません。詳しくはリファレンスを。

プロバイダに送る内容のマスク

ここまでの節は magpie が自分で送るものです。エージェントが送る内容は選んだプロバイダに届きますが、プライバシーマスクはその中の秘密をこのコンピュータに留めます。既定ではオフで、設定 → プライバシー でオンにします。

  • リクエストがこのコンピュータを出る前に、API キー、秘密鍵、トークン、メール、チェックサムの合うカード番号や ID 番号が {{API_KEY_k3v9x2mq}} のようなプレースホルダーになります。ローカルモデルで検出 をオンにすると、このコンピュータで動くモデルが、ルールでは見つからない名前、住所、パスワードも見つけます（1.6 GB のダウンロード、CPU で動作）。
  • 応答の中のプレースホルダーは、ストリームやツール呼び出しの引数も含めて元の値に戻るので、エージェントとファイルには本物の値が残ります。
  • 同じ値はいつも同じプレースホルダーになるので、会話とプロンプトキャッシュはそのまま有効です。
  • 値はメモリにだけ置かれ、ディスク上の記録は種類、長さ、先頭の数文字だけ。マスクがオンなのに動かないときは、リクエストは 503 になり、何も送られません。
  • モデルに見えるのはプレースホルダーで、値そのものではありません。そのまま使う必要のある値（チームのアドレス、テスト用のキー）は マスクしない に入れてください。

オンにする方法、各スイッチがマスクするもの、例、効いているかの確かめ方は プライバシーマスキング へ。

カウントが既定でオンの理由

magpie は何十ものエージェントとプロバイダーに対応し、少人数で保守しています。毎日のカウントは、実際に使われているものを知り、それを優先して動くように保つための手段です。リリース版で既定オンなのは、自分でオンにする人の数だけでは少なすぎて、それがわからないからです。その代わり、送るものは小さく保っています。ランダムな ID、組み込みの ID、数だけです。スイッチ 1 つか DO_NOT_TRACK=1 でオフにでき、ソースからのビルドは送らず、送るものはすべてこのページに挙げています。
