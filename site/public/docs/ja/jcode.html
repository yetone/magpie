jcode

ドキュメント · ガイド

jcode を任意のモデルで

jcode（1jehuang/jcode）は Rust 製のコーディングエージェントで、設定を config.toml に保存します。自分で追加したプロバイダーは jcode provider add が書くのと同じ名前付きプロファイル [providers.<名前>] です。magpie は magpie というプロファイルとして自分を追加し、ローカルゲートウェイを指して magpie の全モデルを並べ、選んだモデルで jcode を起動させます。そのため jcode で magpie のすべてのモデル（DeepSeek、GLM、Kimi、Qwen、OpenAI や Anthropic のキー、ChatGPT や Copilot のサブスクリプション）が使えます。

jcode の設定

  1. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  2. jcode の行でモデルを選ぶjcode が入っていれば magpie の エージェント ページに jcode の行があります。モデルを選びます。
  3. jcode を起動新しい jcode はそのモデルで起動します。開いているセッションは再起動してください。
ターミナル
magpie jcode deepseek/deepseek-v4-pro
jcode   # /model lists every magpie model, /effort its levels

書かれる内容

jcode のフォルダーは $JCODE_HOME、なければ ~/.jcode です。magpie はその config.toml に [providers.magpie] を書きます：type = "openai-compatible"（jcode の Chat Completions クライアント）、ゲートウェイの /v1 を指す base_url、jcode と分かる api_key、そして requires_api_key = true。最後のものは、jcode がループバック上のゲートウェイをキー不要とみなしてキーを送らなくなるためで、ゲートウェイはこのキーで jcode のリクエストだと分かります。そして [provider] の default_provider と default_model を magpie と選んだモデルにします。

ターミナル
# ~/.jcode/config.toml
[provider]
default_provider = "magpie"
default_model = "deepseek/deepseek-v4-pro"

[providers.magpie]
type = "openai-compatible"
base_url = "http://127.0.0.1:3425/v1"
api_key = "…"
requires_api_key = true
models = [
  { id = "deepseek/deepseek-v4-pro", context_window = …, input = ["text"], reasoning = true },
  …
]

/model と /effort

magpie の各モデルは models の一項目なので、jcode の /model ですべてを見て切り替えられます。各項目にはコンテキストウィンドウ（magpie が知らないときは 128K。書かないと jcode は 200K とみなします）と画像に対応するかが入り、思考の強さの段階があるモデルには reasoning = true が付くので、jcode の /effort でその段階を選べます。magpie のモデルに自分で付けた reasoning_effort は、モデルにその段階がある限り残ります。magpie のモデルが変わると magpie が一覧を更新します。

反映されるタイミング

jcode は起動時に設定を読むので、新しいモデルや一覧を使うには開いている jcode セッションを再起動してください。jcode が動いている間は magpie がそう知らせます。

自分の設定

以前 [provider] が指していたプロファイルとモデルは記録され、magpie を外すと戻ります。ファイルのほかのキーはすべて自分のもので、そのまま残ります。magpie のプロファイルに自分で加えたキー（headers、extra_body、モデルの reasoning_effort）も同じです。config.toml が読めないときはエラーにしてそのまま残し、空とみなして上書きすることはありません。jcode が自分で設定を保存するとモデルを [[providers.magpie.models]] のテーブルとして書きますが、magpie は次に書くときに一つの配列にまとめ直します。

元に戻す

magpie で行を既定に戻すと、jcode がまだ magpie で起動する場合は [provider] を以前の状態に戻します。その後 jcode で自分で選び直したものはそのままです。そして [providers.magpie] を、中の自分のキーごと丸ごと消します。jcode 自身のモデルを選ぶこともでき、そのとき magpie は default_model をそれにします。

ターミナル
magpie jcode default

よくある質問

jcode で DeepSeek、GLM、Kimi、Qwen は使えますか？

使えます。magpie が jcode の config.toml にローカルゲートウェイを指す openai-compatible の [providers.magpie] を書き、選んだモデルで jcode を起動させます。

jcode の /model で magpie のモデルを切り替えられますか？

できます。magpie の全モデルが magpie プロファイルの models にあるので、/model で一覧から切り替えられます。思考の段階があるモデルは /effort で選べます。

モデルを選んでも jcode が変わりません。

jcode は起動時に設定を読みます。開いている jcode セッションを再起動してください。

元に戻したあと自分の設定は残りますか？

残ります。magpie が消すのは [providers.magpie] だけで、jcode がまだ magpie で起動するときは [provider] を戻します。ほかのキーはそのままです。

同じモデルを他のエージェントでも：Crush を任意のモデルで、OpenCode で他のモデル、Goose を任意のモデルで、Reasonix Studio を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
