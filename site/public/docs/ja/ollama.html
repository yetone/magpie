Ollama を Claude Code・Codex・Gemini CLI・OpenCode で使う

Ollama は pull したモデルを http://localhost:11434 で OpenAI Chat Completions と Anthropic Messages の二つの API で提供します。Ollama Cloud はクラウドのモデルを ollama.com で同じように提供し、API キーで使います。どちらかを magpie に一度追加すれば、Claude Code・Codex・Gemini CLI・OpenCode などつないだすべてのツールが、magpie のゲートウェイ 127.0.0.1:3425 経由で使えます。ツールごとに別のモデルを選べます。

Ollama を追加する

  1. モデルを pull するOllama で qwen3 などのモデルを pull し、サーバーを動かしたままにします。
  2. プロバイダを追加するmagpie の プロバイダ タブで ＋ プロバイダを追加 を押し、このマシン上 から Ollama を選びます。キーは要りません。magpie がサーバーにモデルを問い合わせ、ollama/… として表示されます。
  3. ツールに割り当てるエージェント タブでツールの行のモデルをクリックし、Ollama のモデルを選びます。
ターミナル
ollama pull qwen3
magpie provider add ollama
magpie provider test ollama

magpie のモデル ID は プロバイダ/モデル の形なので、qwen3 として pull したモデルは ollama/qwen3 になります。タグも ID に残り、ollama/qwen3:8b のようになります。ターミナル UI で追加すると、サーバーのアドレスを聞かれます。LM Studio・oMLX・vLLM・llama.cpp のサーバーは ローカルモデル を見てください。

別のポート・別のマシン

Ollama が別のポートで待ち受けている場合や、GPU マシンや NAS など別のマシンで動いている場合は、プロバイダの編集画面で サーバーアドレス を変えます。変わるのはスキーム・ホスト・ポートだけで、各 API のパスはそのままです。スキームは省略でき、その場合は http になります。アドレスと一緒に貼ったパス（/v1 など）は取り除かれます。

ターミナル
magpie provider set ollama address=192.168.1.20:11434
magpie provider set ollama address=     # 既定に戻す
  • プロキシ。自分のネットワーク内のサーバーには、設定やシステムがどのプロキシを指定していても直接つなぎます。プロバイダ自体に設定したプロキシは使われます。
  • HTTPS。自己署名証明書の HTTPS の後ろにある Ollama には、編集画面の 証明書を検証しない でつなげます。そのプロバイダ自身のホストにだけ効きます。

Ollama Cloud

  1. キーを作るollama.com/settings/keys で作成します。
  2. プロバイダを追加するプロバイダ タブで ＋ プロバイダを追加 を押し、Ollama Cloud を選んでキーを貼り付け、保存します。magpie がそのキーで使えるモデルを Ollama Cloud に問い合わせます。
  3. ツールに割り当てるツールの行で deepseek-v4-pro などの Ollama Cloud のモデルを選びます。
ターミナル
magpie provider add ollama-cloud <key>
magpie claude ollama-cloud/deepseek-v4-pro

モデル名・推論レベル・価格は models.dev の ollama-cloud カタログから取ります。キーは magpie の設定に保存されます。

エンドポイント

プロバイダChat CompletionsAnthropic Messages
Ollamahttp://localhost:11434/v1http://localhost:11434
Ollama Cloudhttps://ollama.com/v1https://ollama.com

ツールが話す API を Ollama が提供していれば、リクエストはその API にそのまま渡ります。magpie はどちらにも Responses のエンドポイントを使わないので、変換が要るときは Chat Completions を使います。Responses を優先するのは OpenAI 自身のモデルだけ、Messages を優先するのは Claude のモデルだけです。

モデル一覧

magpie は Chat Completions のベース URL から一覧を取ります。http://localhost:11434/v1/models、Ollama Cloud なら https://ollama.com/v1/models です。Ollama にあるモデルが magpie に表示されます。新しく pull したら、プロバイダの編集画面で モデルを取得 を押すか、magpie provider refresh ollama を実行します。ツールに見せるモデルは、プロバイダのモデル一覧かターミナルで選べます。

ターミナル
magpie provider refresh ollama
magpie provider models ollama +qwen3

Ollama 0.35.0 以降（クラウドモデルは 0.40.5 以降）は、Nimble・Clef・Tev などの判定モデルも提供します。magpie は Ollama の /api/tags も読み、判定モデルと示されたものをそのプロバイダの インテントルーティング 用の判定モデルにします。ツールのモデルにはなりません。古い Ollama では一覧に出ません。

ツールごとの使い方

ターミナル
magpie claude ollama/qwen3
magpie codex ollama/qwen3
magpie gemini model ollama/qwen3
magpie opencode ollama/qwen3
  • Claude Code は Anthropic Messages を話し、Ollama も http://localhost:11434 で提供しているので、リクエストはそのまま届きます。Claude Code で他のモデル。
  • Codex は OpenAI Responses を話しますが、magpie はそれを Ollama には送りません。リクエストを Chat Completions に変換し、返答を元に戻します。ストリーミングとツール呼び出しも含みます。Codex で他のモデル。
  • Gemini CLI は Google の Gemini API を話します。magpie がリクエストを Chat Completions に変換し、返答を元に戻します。Gemini CLI で他のモデル。
  • OpenCode は Chat Completions を話すので、リクエストは Ollama の /v1 にそのまま届きます。OpenCode で他のモデル。

ツールの中でも、Claude Code と Codex の /model に magpie のモデルが並ぶので、ローカルモデルとクラウドのモデルをそこで切り替えられます。ツール本来のモデルに戻すには magpie claude default か magpie codex default を実行します。

コンテキストウィンドウと num_ctx

エージェントは、モデルが受け付けるリクエストの長さを前提に会話を組み立てます。Claude Code は知らないモデルを 200K とみなし、Codex は伝えられたウィンドウの 90% で会話を圧縮します。magpie は Ollama のチャットモデルのウィンドウを読まないので、実際の値を伝えてください。プロバイダの編集画面の 詳細設定 にある コンテキストウィンドウ で、全モデルにも個別のモデルにも設定できます。magpie がそれをエージェントに伝えます。

ターミナル
magpie provider set ollama context=32k
magpie provider set ollama context.qwen3=128k
  • num_ctx。クライアントによっては、Chat Completions のフィールドと並べて {"num_ctx": …} のような Ollama のリクエストごとのオプションを送ります。magpie は転送するすべてのリクエストからそれを外します。Ollama 自身の /v1 も含め、Chat Completions API はこれを読まないためです。モデルが実際に使うウィンドウは Ollama 側で決まるので、magpie にも同じ数を設定してください。
  • 長すぎる場合。会話がウィンドウを超えると、Ollama は “exceeded max context length” を返します。magpie はそれをツールが理解できる形、つまり context_length_exceeded か Anthropic の “prompt is too long” で伝えるので、ツールは圧縮してやり直します。

推論

  • 推論の強さ。ツールが求める強さは、カタログにあるそのモデルのレベルのうち最も近いものに合わせます。レベルがわからないモデルには、ツールの指定どおりに送ります。
  • 推論オフ。magpie が変換するツール（Codex や Gemini CLI）が推論をオフにし、モデルのレベルに none があれば、magpie は none を指定します。
  • レベルを自分で決める。magpie model efforts で、指定したレベルだけを出すことも、推論のフィールドをまったく送らないこともできます。
ターミナル
magpie model efforts ollama/qwen3 low,medium,high
magpie model efforts ollama/qwen3 off

ツール呼び出し

Claude Code と OpenCode のツール呼び出しは、ツールが書いたとおりに Ollama へ届きます。Codex と Gemini CLI では、ツールの定義、モデルからの呼び出し、その結果を magpie が Chat Completions に変換して戻します。ストリーミングの返答でも同じです。

プライバシーマスク

magpie の プライバシーマスク は、リクエストがゲートウェイを出る前にキーやトークンなどの秘密をプレースホルダーに置き換えます。ローカルの Ollama へのリクエストも同じです。モデルが自分のマシンやネットワーク内で動いているなら、編集画面で リクエストをマスクしない をオンにするか、magpie provider set ollama unmasked=yes を実行します。

  • クラウドモデル。Ollama のクラウドモデルは、アドレスに関係なくリクエストをベンダーへ送ります。判断はあなた次第です。ローカルでないプロバイダ（Ollama Cloud など）でオンにしている間は、編集画面に注意が出ます。
  • ツールの引数。Ollama 自身の形式のリクエストでも、ツール呼び出しの引数は他の API と同じくツールの引数としてマスクします。
  • 匿名の統計。magpie の日次統計は、models.dev が知っている Ollama のモデルだけを名前で記録し、それ以外は “other” とします。プライバシー を見てください。

使用量と費用

  • 使用量。使用量 タブは Ollama の呼び出しごとにトークンを数えます。価格は magpie がそのモデルの ID で見つけたもので、ローカルモデルではモデルの開発元の定価になることがあります。ローカルモデルを無料として数えるには、自分で価格を設定してください。
  • 無料優先。free=yes にすると、そのプロバイダのモデルはすべて無料として扱われ、無料優先 のルーティングは有料のものより先に使います。価格と使用量の費用は定価のまま表示されます。
  • Ollama Cloud の枠。magpie は Ollama Cloud からアカウントの残高を読みます。プランに含まれる枠はプランとして、使った金額（ドル）とリセットの時期つきで表示されます。古いプランではセッションの上限と週の上限が表示されます。購入したクレジットは残高として表示されます。枠を超えると Ollama Cloud はクレジットから引くので、枠を使い切ってもクレジットが残っていればキーは止まりません。
  • ピーク時間帯。Ollama Cloud の deepseek-v4.1-flash と deepseek-v4-pro（タグ付きのものも）は、月曜から金曜の UTC 12:00〜18:00 に 2 倍の料金になります。models.dev にあるのはオフピークの価格で、使用量タブはこの時間帯に 2 倍で計算し、最安優先 のルーティングもそれを考慮します。
  • 枠を使い切ったとき。Ollama Cloud がキーの枠切れを伝えても回復の時期を言わない場合（週の上限など）、magpie はそのキーを 15 分休ませます。quota-rest で最長 8 日まで変えられます。キーが複数あれば（別のキーを追加）次のキーが引き継ぎ、すべて使い切ったときはゲートウェイがすぐに Retry-After つきで返します。
ターミナル
magpie model price ollama/qwen3 0,0,0,0
magpie provider set ollama free=yes
magpie provider quota-rest ollama-cloud 7d
magpie provider fallback ollama-cloud ollama/qwen3

magpie を Ollama サーバーとして使う

カスタムモデルを Ollama サーバーとしてしか受け付けないアプリがあります。VS Code の Copilot の Ollama プロバイダ、Visual Studio の Copilot BYOK、Zed の Ollama プロバイダ、そして ollama CLI です。これらを magpie のゲートウェイ http://127.0.0.1:3425 に向ければ、Ollama のものだけでなく、すべてのプロバイダの magpie のモデルが見えます。

  • ルート。magpie は /api/version・/api/tags・/api/show・/api/chat・/api/generate に応答します。
  • 同じ経路。ここでのチャットは /v1/chat/completions と同じ処理を通るので、キーの制限・ルーティング・フォールバック・使用量の集計も同じです。一部のモデルに限ったゲートウェイキーには、そのモデルだけが表示されます。
  • 伝える情報。/api/tags と /api/show は、ツール、画像を読めるモデルなら vision、推論するモデルなら thinking を示します。/api/show はモデルのウィンドウも伝え、magpie が知らないモデルは 32768 とします。ollama CLI の name:latest は name という名前のモデルに当たります。

うまくいかないとき

  • pull したモデルが一覧にない。一覧はサーバーから取ります。モデルを取得 を押すか magpie provider refresh ollama を実行し、プロバイダのモデル一覧で選んでください。名前は Ollama が表示するとおり、タグ込みで指定します。
  • Ollama が動いていない。magpie provider test ollama は各エンドポイント、または指定したモデルに小さなリクエストを送ります。--as codex や --as claude-code をつけると、そのツールと同じ形で送ります。Ollama を起動するか、サーバーアドレス を確かめてください。止まっている間のリクエストの行き先は fallback で決められます。
  • “exceeded max context length”。会話がモデルを読み込んだときの長さを超えています。プロバイダに実際の コンテキストウィンドウ を設定すれば、ツールはそこに届く前に圧縮します。
  • 別のマシンにつながらない。サーバーアドレス のアドレスとポートを確かめてください。自己署名証明書の HTTPS なら 証明書を検証しない をオンにします。

よくある質問

Claude Code で Ollama のローカルモデルを使うには？

magpie に Ollama を追加し（プロバイダ → プロバイダを追加 → このマシン上の Ollama）、Claude Code の行でそのモデルを選ぶか、magpie claude ollama/qwen3 を実行します。Claude Code のリクエストは magpie のゲートウェイを通り、http://localhost:11434 にある Ollama の Anthropic Messages API へそのまま届きます。

Codex で Ollama は使えますか？

使えます。Codex は Responses API しか話さないので、magpie がリクエストを Chat Completions に変換して Ollama に送り、返答を元に戻します。ツール呼び出しも含みます。magpie codex ollama/qwen3 を実行してください。

Gemini CLI や OpenCode でも Ollama は使えますか？

使えます。Gemini CLI は Google の API を話すので、magpie がリクエストを Ollama の Chat Completions に変換し、返答を元に戻します。OpenCode は Chat Completions を話すので、リクエストはそのまま Ollama に届きます。magpie gemini model ollama/qwen3 か magpie opencode ollama/qwen3 を実行してください。

Ollama の qwen3-coder を Claude Code で使うには？

Ollama で pull してから、magpie のプロバイダ編集画面で「モデルを取得」を押し（または magpie provider refresh ollama を実行し）、Claude Code の行で選びます。magpie での ID は ollama/ に Ollama が表示する名前（タグ込み）を続けたものです。コンテキストウィンドウも設定してください。Claude Code は知らないモデルを 200K とみなします。

別のマシンの Ollama を使えますか？

使えます。プロバイダのサーバーアドレスをそのマシンに変えます。たとえば magpie provider set ollama address=192.168.1.20:11434 です。自分のネットワーク内のサーバーには、設定やシステムのプロキシを通さず直接つなぎます。

Ollama Cloud にも対応していますか？

対応しています。ollama.com/settings/keys で作ったキーで Ollama Cloud を追加すると、magpie はそのキーで使えるモデルを一覧にし、models.dev の価格で計算し、アカウントのプランに含まれる枠と購入したクレジットを表示します。

ローカルの Ollama に API キーは要りますか？

要りません。Ollama のプリセットはキーなしで使えます。Ollama Cloud にはキーが要ります。

LM Studio・oMLX・vLLM・llama.cpp など他のローカルサーバーは ローカルモデル を見てください。ローカルモデルにリクエストを分類させてルーティングを決めるには インテントルーティング を見てください。
