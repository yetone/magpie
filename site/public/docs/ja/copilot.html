GitHub Copilot を Claude Code・Codex・Gemini CLI・OpenCode で使う

Copilot のシートには Claude、GPT、Gemini などのモデルが含まれています。magpie で一度 Copilot にサインインすれば、Claude Code・Codex・Gemini CLI・OpenCode などつないだすべてのツールが、magpie のゲートウェイ 127.0.0.1:3425 経由でプランのモデルを使えます。API キーは要りません。

Copilot にサインインする

  1. プロバイダを追加を開くmagpie の プロバイダ で ＋ プロバイダを追加 を押し、Copilot のタイルをクリックします。
  2. GitHub でコードを入力magpie がコードを表示し、GitHub のデバイスページ github.com/login/device を開きます。コードを入力して承認すると、magpie が GitHub にどのアカウントか、どのプランかを確かめ、アカウントが Copilot の下に表示されます。
  3. ツールで選ぶエージェント タブで、ツールの行のモデルをクリックし、copilot/… のモデルを選びます。
ターミナル
magpie accounts add copilot                        # github.com
magpie accounts add copilot --host acme.ghe.com    # GHE.com の GitHub Enterprise
magpie accounts copilot                            # 各アカウントと使用量

magpie は次の 3 か所の Copilot サインインを使います。

  • Copilot のエディタプラグイン。~/.config/github-copilot（apps.json か hosts.json）にあるサインイン。
  • Copilot CLI。~/.copilot/config.json にあるサインインで、トークンはシステムのキーチェーンか、このファイルに平文で入っています。Windows の magpie は、起動中の WSL ディストリビューションにある Copilot CLI のサインインも config.json からだけ読みます。
  • magpie 自身のもの。magpie でコードを使ってサインインした各アカウント。トークンは magpie 自身の logins.json に保存されます。

エディタと CLI のサインインは読むだけで、magpie が書き換えることはありません。両方あるときは、エディタの github.com のサインイン、CLI のサインイン、エディタの GHE.com のサインインの順に使います。GitHub がエディタのトークンを拒否したときは、CLI にある同じアカウントのサインインに切り替え、別人のアカウントに替わることはありません。

GHE.com の GitHub Enterprise。データレジデンシーを使うエンタープライズは自社の <name>.ghe.com でサインインするので、アカウントは --host を付けて追加します（サインイン画面の「GHE.com のアカウント？」に答えても同じです）。magpie が受け付けるのは github.com か <name>.ghe.com のアドレスだけなので、GitHub のトークンが任意のホストに送られることはありません。このアカウントはエンタープライズの copilot-api.<name>.ghe.com で提供されます。同じログイン名でも github.com と GHE.com では別のアカウント（you と you@acme.ghe.com）になります。

シートで使えるモデル

magpie はアカウントごとに Copilot の /models に問い合わせ、返ってきたモデルを並べます。決まった表ではなく、プランに合わせた一覧になります。モデル名は copilot/ に Copilot 自身の ID を付けたもので、たとえば copilot/claude-opus-5.5、copilot/gpt-5.4、copilot/gpt-5.3-codex です。magpie models ですべて表示できます。

  • チャットモデルだけ。Copilot の内部用モデル、どのモデルピッカーにも出ないモデル、そのアカウントで有効にできないモデルは除きます。
  • 規約の同意が要るモデル。規約に未同意のモデルも一覧に出ます。最初のリクエストで magpie が同意し、Copilot のエディタで有効にしたのと同じ状態になります。
  • 推論レベルは Copilot がモデルごとに示すものを使い、各ツールのピッカーに表示されます。
  • Auto は必ず一覧にあります。Copilot Auto を参照してください。
  • 画像モデル（GPT Image 2.5 Flare など）は画像生成用として並び（設定 → モデル → 画像）、チャットモデルとしては出ません。
  • 古いモデル。学生プランの GPT-4.1 や GPT-4o のように Copilot が API を示さないモデルは、Chat Completions だけで問い合わせます。

Claude Code はバージョンにドットを含む Claude の名前を古いモデルとして読むので、magpie は Copilot の Claude モデルをハイフン表記（claude-opus-5-5）で渡し、Copilot に届く前に元の名前に戻します。他のツールには Copilot の表記のまま見えます。

ツールごとの使い方

エージェント タブで各ツールの行のモデルをクリックして選ぶか、ターミナルで選びます。各ガイドに、magpie がそのツールの設定に何を書くか、どう元に戻すかがあります。

ターミナル
magpie claude copilot/claude-opus-5.5
magpie codex copilot/gpt-5.4
magpie gemini model copilot/gpt-5.4-mini
magpie opencode copilot/claude-opus-5.5
  • Claude Code は Anthropic Messages を話します。Copilot の Claude モデルも Messages で提供されているので、リクエストはそのまま渡ります。GPT や Gemini のモデルには magpie が変換して渡します。Claude Code で他のモデル。
  • Codex が話すのは OpenAI Responses だけで、magpie も Copilot の OpenAI モデルには Responses で問い合わせるので、リクエストはそのまま渡ります。これらのモデルでは Codex の Web 検索を Copilot 側が実行し、Codex のネイティブなコンパクションも使えます。Copilot の Claude モデルではネイティブなコンパクションは使えません。Codex で他のモデル。
  • Gemini CLI は Gemini の API を話します。magpie がゲートウェイに向けて変換します。Gemini CLI で他のモデル。
  • OpenCode には、magpie が opencode.json にモデルを推論バリアントつきで書きます。OpenCode で他のモデル。

Copilot CLI も magpie がつなぐエージェントの一つです。その行では auto（Copilot が選ぶ）と Copilot 自身のモデルに加えて、magpie に追加した他のどのモデルも選べます。それらは Copilot CLI の providers.json を通じて届きます。

リクエストが Copilot に届くまで

Copilot はすべてのモデルをすべての API で提供しているわけではありません。最新の OpenAI モデルは Responses だけ、Claude モデルは Chat Completions と Anthropic Messages、Gemini モデルと古いモデルは Chat Completions だけです。magpie はリクエストをそのモデルが使える API に送り、ツールの API と違えば変換します。ストリーミングとツール呼び出しもそのままです。

  • API が違うとき。Copilot がそのモデルはこの API では提供していないと答えたら、magpie はリクエストを次の API 向けに組み直して送り、どれが通ったかを覚えます。
  • 自分で固定する。magpie model api copilot/<model> chat（または responses、anthropic）で、そのモデルをその API だけで問い合わせます。auto で magpie の選択に戻ります。
  • Gemini のツール定義。Copilot の Gemini モデルは、Codex のツール定義の一部を 400「invalid request body」で断っていました。magpie は安全に書き換えられると確かめられたものを書き換え、それらのツールが届くようにします。

Copilot Auto

copilot/auto は、Copilot があなたのアカウント向けに選ぶモデルです。Copilot の /models には出ないので、magpie が必ず追加します。学生プランで選べるのはこれだけです。

  • magpie はそのターンのプロンプトを付けて、Copilot Chat の既定の設定で Copilot に選択を求めます。選ばれたモデルは最長 1 時間使い回します。
  • Copilot がそのアカウントに Auto を提供していないか、アカウントが断られたモデルを選んだときは、アカウントが手動で選べるモデルが 10 分間代わりを務めます。順番は Copilot のベースモデル、その既定モデル、gpt-4.1、プレミアムでないモデル、残りのモデルです。
  • Auto が選んだモデルをその後 Copilot が断ったら、magpie は別のモデルを選んでリクエストを送り直します。
  • Auto が選んだモデルはリクエストのルートに記録されるので、どのモデルが答えたかがわかります。

プレミアムリクエスト、使用量、費用

Copilot の各アカウントには、GitHub が報告する 3 つの利用枠を示すカードがあります。プレミアムリクエスト、チャットリクエスト、補完 で、それぞれ「使用量 / 利用枠」の形です。magpie accounts copilot も同じ内容を表示します。

  • 毎月。利用枠は毎月、GitHub が示す日に更新されます。
  • 無制限の枠は 無制限 と表示されます。GitHub が数字を示さない枠はカードに出さず、無制限とはみなしません。
  • 1 ターン 1 リクエスト。入力した 1 ターンは 1 リクエストとして課金され、そのターンを続けるツールの結果は数えられません。
  • Business と Enterprise。利用枠を使い切ったシートは一時停止されるので、magpie はそのアカウントを使い切ったものとして次のアカウントに移ります。組織で共有するプレミアム利用枠も、使い切ると使い切りと表示されます。
  • その他のプラン。プレミアム利用枠を超えて支払えるプランなら、使い切ってもアカウントは止まりません。補完も数えますが、magpie を通るリクエストは補完を使いません。
  • 利用枠を使わないモデル。Copilot のベースモデル gpt-4.1 は、どのプランでも利用枠に計上されません。

使用量 タブは、magpie を通った各ツールとモデルのトークン、キャッシュヒット、費用を数えます。サブスクリプションの費用はモデル提供元の定価による見積もりで、モデルに価格を設定していればその価格を使います。Anthropic 自身の価格と違う点が一つあります。Copilot はキャッシュ書き込みを保持時間にかかわらず同じ価格で課金するので、magpie は 1 時間のキャッシュ書き込みを 5 分の価格で計算します。claude-opus-5.5 なら 100 万トークンあたり 5 ドルで、Anthropic の入力 2 倍なら 8 ドルになるところです。

複数アカウントとフォールバック

  • アカウントを追加する。Copilot のタイルをもう一度クリックするか、magpie accounts add copilot をもう一度実行します。使用中のアカウントが先頭に、残りは追加した順に並びます。
  • どれを先に使うか決める。magpie accounts switch copilot <login> で切り替え、magpie accounts forget copilot <login> で削除します。同じログイン名が github.com と GHE.com の両方にあるときは、フルネーム（you@acme.ghe.com）で指定するか --host を付けます。
  • リクエストを分散する。Copilot の行で使うアカウントにチェックを入れます。ルーティング で分散方法を決め、既定は スマート です。プロバイダの フォールバック には、すべてのアカウントがクォータ切れ、レート制限、障害のときに使うモデルを並べます。サブスクを任意のエージェントでを参照してください。
  • 2 つのサブスクリプションで同じモデル。Claude サブスクリプションの Claude Opus と Copilot の Claude Opus は、自動で 1 つのグループ auto/<model> になります。順番を自分で決めるなら magpie group add "Opus anywhere" models=claude/claude-opus-5-5,copilot/claude-opus-5.5 routing=order です。
  • エディタのサインインが切れたとき。Copilot のエディタが持つトークンを GitHub が拒否しても、同じログイン名で magpie にサインインしたアカウントは残り、そのまま使われます。

よくある質問

Claude Code で Copilot のサブスクリプションを使うには？

magpie で Copilot にサインインし（プロバイダ → プロバイダを追加 → Copilot。GitHub で入力するコードが表示されます）、Claude Code の行で copilot/claude-opus-5.5 などの copilot/… モデルを選ぶか、magpie claude copilot/claude-opus-5.5 を実行します。magpie が Claude Code の settings.json を書きます。Copilot の Claude モデルには Claude Code の Anthropic リクエストがそのまま届き、GPT と Gemini のモデルには magpie が変換して渡します。

Codex で Copilot のモデルを使えますか？

使えます。Codex は OpenAI Responses を話し、magpie も Copilot の OpenAI モデルには Responses で問い合わせるので、リクエストはそのまま渡り、Web 検索も使えます。Copilot の Claude と Gemini のモデルは magpie が変換します。Codex の行で選ぶか magpie codex copilot/gpt-5.4 を実行すると、Codex の /model に並びます。

Gemini CLI や OpenCode でも Copilot を使えますか？

使えます。magpie gemini model copilot/gpt-5.4-mini か magpie opencode copilot/claude-opus-5.5 を実行するか、そのツールの行でモデルを選びます。magpie が Gemini CLI のリクエストを変換し、OpenCode の opencode.json にモデルを書きます。

VS Code などのエディタで Copilot にサインインしておく必要はありますか？

ありません。magpie はデバイスコードで自分で GitHub にサインインします。このコンピュータで Copilot のエディタプラグインや Copilot CLI がすでにサインインしていれば、そのサインインも読みますが、書き換えることはありません。

プレミアムリクエストを消費しますか？

リクエストはあなたのアカウントで Copilot に送られるので、Copilot の数え方でプランに計上されます。入力した 1 ターンは 1 リクエストとして課金され、そのターンを続けるツールの結果は数えられません。magpie は各アカウントのプレミアムリクエスト、チャットリクエスト、補完の使用量を表示します。

Copilot Business・Enterprise・GHE.com でも使えますか？

使えます。magpie は GitHub からプラン（Free、Pro、Pro+、Max、Education、Business、Enterprise）を読みます。GHE.com のエンタープライズは magpie accounts add copilot --host <name>.ghe.com でサインインします。Business や Enterprise のシートは利用枠を使い切ると一時停止されるので、magpie は更新までそのアカウントを使い切ったものとして扱います。

Copilot のモデルが一覧にないのはなぜですか？

magpie が並べるのは、Copilot の /models がそのアカウントに返すモデルです。チャットモデルだけで、どのモデルピッカーにも出ないものと、そのアカウントで有効にできないものは除きます。Copilot が「The requested model is not supported.」で断ったモデルは 6 時間外し、プランが変わった場合に備えてその後もう一度試します。
