ドキュメント · ガイド

T3 Code を任意のモデルで

T3 Code（pingdotgg/t3code）は Claude Code、Codex、Cursor などを動かす GUI です。プロバイダーはそれぞれドライバーの「インスタンス」で、自分のインスタンスも追加できます。magpie は Claude Code で動く magpie と、Codex で動く magpie · Codex の二つを加えます。そのため T3 Code のモデル選択に magpie のすべてのモデル（DeepSeek、GLM、Kimi、Qwen、OpenAI や Anthropic のキー、ChatGPT や Copilot のサブスクリプション）が並び、動かすハーネスも選べます。

T3 Code の設定

  1. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  2. T3 Code の行で magpie を選ぶエージェント ページで magpie を選ぶと、二つのインスタンスが T3 Code の settings.json に書かれます。
  3. T3 Code でモデルを選ぶT3 Code のサーバーはファイルを監視し、外部の変更で再読み込みします。モデル選択で magpie の下のモデルは Claude Code で、magpie · Codex の下のモデルは Codex で動きます。
ターミナル
magpie t3code provider magpie

設定ファイルは ~/.t3/userdata/settings.json（T3CODE_HOME があれば $T3CODE_HOME/userdata）です。magpie が書く二つのインスタンス：

ターミナル
"providerInstances": {
  "magpie": {"driver": "claudeAgent", "displayName": "magpie",
    "environment": [{"name": "ANTHROPIC_BASE_URL", "value": "http://127.0.0.1:3425", …}, …],
    "config": {"customModels": [{"slug": "deepseek/deepseek-v4-pro", "name": …,
      "capabilities": {"optionDescriptors": […]}}, …]}},
  "magpie-codex": {"driver": "codex", "displayName": "magpie · Codex",
    "config": {"launchArgs": […]}}
}

magpie（Claude Code）

magpie インスタンスは claudeAgent インスタンスです。T3 Code は Anthropic の Agent SDK で Claude Code を動かし、~/.claude の設定を読み、インスタンスの環境変数を加えます。magpie は ANTHROPIC_BASE_URL をゲートウェイに、Claude Code が magpie 経由で使うトークンを設定するので、リクエストは Claude Code からゲートウェイへのものになります。magpie の各モデルはカスタムモデルになり、1M のモデルには Claude Code 向けと同じく [1m] が付きます。T3 自身の Claude に実行ファイルのパスや Claude のホームを指定していれば引き継ぐので、同じ Claude Code が動きます。

magpie · Codex（Codex）

T3 Code はスレッドを、モデルを選んだインスタンスのハーネスで動かします。Claude Code のインスタンスだけでは magpie のモデルはすべて Claude Code で動くため、magpie は codex インスタンス magpie · Codex も加えます。その launchArgs は T3 が codex app-server と codex exec に渡す Codex 自身の -c 上書きで、magpie をモデルプロバイダーに、settings.json の隣の magpie-codex-models.json をカタログにします。~/.codex/config.toml は書き換えず、T3 自身の Codex もそのままです。T3 でこのインスタンスを消すと同期では戻らず、magpie で行をもう一度オンにすると戻ります。

推論レベル

能力の記述がないと、T3 Code はカスタムモデルに選択肢を出さず、推論レベルも送りません。そこで magpie は各カスタムモデルに、そのモデルが受け付ける Claude Code のレベルの Reasoning 選択を付け、既定は medium（なければ最低）です。T3 は選んだレベルをそのまま Claude Code に渡します。思考するモデルには Thinking スイッチ（最初はオン）も付き、T3 はそれで Claude Code の alwaysThinkingEnabled を設定します。

自分の設定

インスタンスの名前、オンかどうか、magpie が書かないキー（autoCompactWindow、accentColor など）はあなたのもので、T3 Code で変えた値は保たれます。magpie のインスタンスに自分で加えた環境変数も残ります。自分のインスタンス、そのカスタムモデル、T3 のほかの設定には触れません。magpie のものはカスタムモデル、ゲートウェイの環境変数、Codex インスタンスの起動引数とカタログだけです。

Claude Code 自身のルーティング

~/.claude/settings.json の env はプロセスの環境変数より優先されます。Claude Code が自分の設定で別の場所へルーティングされていれば、magpie インスタンスのリクエストもそこへ行きます。magpie 経由かルーティングなしならゲートウェイへ行きます。CLAUDE_CODE_USE_BEDROCK などのクラウドのスイッチがオンならそのクラウドへ行き、magpie のチェックがそれを知らせます。

元に戻す

magpie で行をオフにすると、magpie は自分の二つのインスタンスだけを外し、ほかのインスタンスと設定はそのままです。

ターミナル
magpie t3code default

よくある質問

T3 Code で DeepSeek、GLM、Kimi、Qwen は使えますか？

使えます。magpie が T3 Code の settings.json に二つのプロバイダーインスタンスを加え、magpie のすべてのモデルが T3 のモデル選択に、Claude Code 用と Codex 用で並びます。

magpie と magpie · Codex の違いは？

モデルは同じでハーネスが違います。magpie の下は Claude Code、magpie · Codex の下は Codex で動きます。

~/.codex/config.toml や T3 自身の Claude、Codex は変わりますか？

いいえ。Codex の設定は magpie · Codex インスタンスの起動引数だけで、T3 自身のインスタンスやあなたのインスタンスはそのままです。

リクエストが magpie を通りません。

~/.claude/settings.json の env を確認してください。そこで別の場所にルーティングされているか、Bedrock などのスイッチがオンだと、magpie インスタンスのリクエストもそこへ行きます。

同じモデルを他のエージェントでも：Claude Code で他のモデル、Codex で他のモデル、CodeBuddy を任意のモデルで、Craft Agents を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
