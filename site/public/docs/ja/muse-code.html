Muse Code

ドキュメント · ガイド

Muse Code を任意のモデルで

Muse Code は Meta の muse コーディングエージェント CLI です。リクエストの送り先は settings.json の endpoint_transport、セッションのモデルはトップレベルの model で決まります。magpie が両方をゲートウェイに向けると、Muse Code が DeepSeek、GLM、Kimi、Qwen、Claude、ChatGPT サブスクリプションなど magpie の任意のモデルで動きます。

Muse Code の設定

  1. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  2. エージェント ページで Muse Code のモデルを選ぶvia magpie のモデルを選びます。
  3. 開いている muse セッションを再起動Muse Code は起動時に設定を読みます。
ターミナル
magpie muse deepseek/deepseek-v4-pro

settings.json

Muse Code の設定は ${XDG_CONFIG_HOME:-~/.config}/muse/settings.json にあり、"schema_version": 1 がないファイルは読みません。magpie が書くのは：

ターミナル
{
  "schema_version": 1,
  "endpoint_transport": {
    "base_url": "http://127.0.0.1:3425/v1",
    "auth": "none"
  },
  "model": "deepseek/deepseek-v4-pro"
}

Muse Code は base_url の下の /responses（OpenAI の Responses API）にストリーミングで送り、そこでゲートウェイが応えます。ファイルのほかのキーはそのままです。ファイルがなければ magpie が schema_version 付きで作ります。WSL のディストリビューションの Muse Code も同じように、そちらの ~/.config/muse に設定します。

auth が none の理由

auth が bearer なら Muse Code は Meta サインインのトークン（auth.json か META_API_KEY）を送り、none なら Authorization を付けずサインインも求めません。magpie は none を使うので、Meta のトークンは magpie に読まれず、ゲートウェイにも送られません。

モデル一覧

Muse Code は base_url のホストの /muse-code/models からモデル一覧を取り、ゲートウェイがそれを返すので、Muse Code のモデル選択に magpie のモデルが並びます。

元に戻す

最初に入るとき、magpie は元の endpoint_transport と model を控えます。元に戻すとそれを書き戻し、なかったものは外します。magpie が作ったファイルは、schema_version だけが残ればファイルごと消します。

ターミナル
magpie muse default

よくある質問

Muse Code で DeepSeek、GLM、ChatGPT サブスクリプションを使えますか？

使えます。magpie のエージェントページで Muse Code に via magpie のモデルを選び、muse セッションを再起動します。

magpie は Meta のサインイントークンを読みますか？

読みません。auth を none にするので Muse Code は Authorization を送らず、トークンは読まれずゲートウェイにも送られません。

Muse Code に変化がありません。

Muse Code は起動時に settings.json を読みます。開いている muse セッションを再起動してください。

元に戻すと設定も戻りますか？

戻ります。magpie が控えた endpoint_transport と model を書き戻し、ほかのキーには最初から触れていません。

同じモデルを他のエージェントでも：Prime Agent を任意のモデルで、Pi を任意のモデルで、Kimi Code を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
