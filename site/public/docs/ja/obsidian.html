Obsidian を任意のモデルで

Obsidian 自体に AI はなく、コミュニティプラグインが提供します。magpie が設定するのは、任意の OpenAI 互換エンドポイントを受け付ける Copilot for Obsidian（logancyang/obsidian-copilot）です。Copilot のある保管庫ごとに magpie というプロバイダーを加えるので、Obsidian の AI チャットで magpie のどのモデルも使えます：DeepSeek、GLM、Kimi、Qwen、OpenAI や Anthropic のキー、ChatGPT や Copilot のサブスクリプション。

Obsidian の設定

  1. Obsidian に Copilot を入れるObsidian の 設定 › コミュニティプラグイン で Copilot を入れて有効にします。Copilot のある保管庫があると magpie に Obsidian の行が出ます。
  2. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  3. Obsidian の行で magpie を選ぶエージェント ページで magpie を選び、Obsidian で Copilot を再読み込みすると、モデルメニューに magpie のモデルが並びます。
ターミナル
magpie obsidian provider magpie

保管庫

Obsidian は保管庫の一覧を設定フォルダーの obsidian.json に持ちます：Mac は ~/Library/Application Support/obsidian、Windows は %APPDATA%\obsidian、Linux は $XDG_CONFIG_HOME/obsidian、Flatpak と Snap はそれぞれのフォルダーです。Copilot の設定は各保管庫の .obsidian/plugins/copilot/data.json にあります。magpie は Copilot のある保管庫すべてを設定し、その後は設定済みの保管庫だけを更新します。

モデル一覧

magpie が data.json に書くのは次のキーだけで、ほかの設定はそのままです：

ターミナル
"providers": {"magpie": {
  "providerType": "openai-compatible", "displayName": "magpie",
  "baseUrl": "http://127.0.0.1:3425/agent/obsidian/v1",
  "requiresApiKey": false, …}},
"configuredModels": [{"providerId": "magpie", "info": {"id": "deepseek/deepseek-v4-pro", …}}, …],
"backends": {"chat": {"enabledModels": […]}},
"defaultModelKey": "…"

各モデルには magpie のカタログからコンテキスト長、出力上限、画像、思考レベルが付きます。magpie に新しく入ったモデルはチャットで有効になり、Copilot で無効にした magpie のモデルは無効のまま、magpie から消えたモデルはすべてのバックエンドから外れます。Copilot で自分で追加したモデルやプロバイダーには触れません。最初の設定時に Copilot の既定モデルは magpie の先頭のモデルになり、元の既定は戻すときのために保存されます。

キー入力不要

Copilot は API キーを Obsidian のキーチェーンに保存し、magpie はそこに書きません。そのため magpie のプロバイダーはキー不要（requiresApiKey: false）で、リクエストに Authorization は付かず、ゲートウェイはこのコンピューターからのキーなしの呼び出しを受け付けます。Copilot は Obsidian のウィンドウから fetch で呼ぶので返答はストリーミングされ、ゲートウェイはそのウィンドウの CORS にも応えます。アドレスの /agent/obsidian で magpie は Obsidian だと分かります（ウィンドウの User-Agent はブラウザーと同じです）。

Copilot の再読み込み

Obsidian の実行中、Copilot は設定をメモリに持ち、保存時に data.json を丸ごと書き戻します。設定後は Copilot の設定を変える前に 設定 › コミュニティプラグイン で Copilot を再読み込み（または Obsidian を再起動）してください。そうしないと古い設定が magpie の内容を上書きします。Obsidian の実行中は magpie がそう知らせます。

Copilot 3

magpie が書くのは Copilot 4 の形式（providers と configuredModels）だけです。Copilot 3 はモデルを activeModels に持つので、そうした保管庫には触れず、エラーで名前を示します。Copilot を 4 に上げると、初回の読み込みで設定が移行されます。

元に戻す

magpie で行をオフにすると、各保管庫の data.json から magpie のプロバイダー、モデル、各バックエンドでの位置を外し、既定が magpie のモデルのままなら元の既定モデルに戻します。magpie という名前で手動で追加したプロバイダー（アドレスが magpie の Obsidian 用ルートでないもの）はあなたのものとして残ります。

ターミナル
magpie obsidian default

よくある質問

Obsidian で DeepSeek、GLM、Kimi、Qwen は使えますか？

使えます。Copilot for Obsidian プラグイン経由で、magpie が Copilot のある保管庫ごとに magpie プロバイダーを加え、magpie のすべてのモデルが Copilot のモデルメニューに並びます。

Copilot に API キーを入れる必要は？

ありません。magpie のプロバイダーはキー不要で、リクエストはこのコンピューターの magpie ゲートウェイへ送られ、magpie があなたのキーやサブスクリプションでモデルを呼びます。

Copilot に magpie のモデルが出ません。

Obsidian の設定 › コミュニティプラグインで Copilot を再読み込みするか、Obsidian を再起動してください。Copilot 3 の保管庫は先に Copilot 4 へ。

Smart Connections は使えますか？

いいえ。無料版はローカルモデルでの埋め込みだけで、API プロバイダーは非公開の Pro プラグインにあり、キーは magpie が書けないキーチェーンにあります。

同じモデルを他のアプリでも：Raycast、Cherry Studio、CodeBuddy を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
