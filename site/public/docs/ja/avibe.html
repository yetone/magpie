Avibe を任意のモデルで

Avibe（avibe-bot/avibe、MIT、avibe-os パッケージと vibe CLI）はローカルのエージェント OS です。自身のエージェント Vibey と、それが動かす Claude Code、Codex、OpenCode は、どれも Model Hub からモデルを取ります。Model Hub は Avibe 自身のゲートウェイ（CLIProxyAPI）で、Models ページで追加したモデルソースの前に立ちます。magpie をそのソースの一つとして加えると、Avibe のすべてのエージェントが DeepSeek、GLM、Kimi、Qwen、Claude、ChatGPT サブスクリプションなど magpie の任意のモデルで動きます。

Avibe の設定

  1. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  2. Avibe を起動Avibe は動いている間だけモデルソースを追加・削除するので、先に vibe start で起動します。
  3. エージェント ページで Avibe に magpie を選ぶmagpie が Avibe の Models ページにモデルソースとして現れ、Vibey とそれが動かすエージェントで使えます。
ターミナル
vibe start
magpie avibe magpie

モデルソースとしての magpie

Avibe のホームは $AVIBE_HOME、なければ ~/.avibe（3.0 より前は ~/.vibe_remote）で、ソースはそこの config/config.json の model_hub.sources にあります。ソースは config.json に手で書けません。一つずつ全体が検証され、キーは Model Hub のストアに入り、追加時に Avibe が各エージェントのルートチェーンに加えるからです。そこで magpie は Avibe の Models ページと同じく、Avibe の内部 API で追加・削除します。macOS と Linux ではホームの state/dispatch.sock、Windows では runtime/control-ipc/endpoint.json にあるループバックのポートと bearer token を使います。magpie が送る内容：

ターミナル
POST /internal/model-hub
{
  "operation": "create_source",
  "payload": {
    "source": {
      "kind": "api_key",
      "vendor": "custom",
      "display_name": "magpie",
      "base_url": "http://127.0.0.1:3425/v1",
      "key": "",
      "protocol": "openai_chat",
      "supply_channel": "hub",
      "billing": "metered",
      "save_unverified": true
    }
  }
}

magpie はソースの id を控えるので、Avibe で名前を変えても magpie のものです。Models ページで手で追加した、ゲートウェイを指す custom ソースも magpie のものとみなします。ゲートウェイのポートが変わると、キーはアドレスと一緒に封じられているため、同期は古いソースを消して新しいアドレスで追加し直します。別のマシン、ローカルプロキシのパス、WSL から Windows への経路を指すものはそのままです。

chat completions を使う理由

ソースのプロトコルは Responses ではなく openai_chat です。Responses のソースでは Model Hub が Codex の実行器を使い、それが codex-tui と名乗るため Codex 本体と取り違えられます。chat なら各バックエンド自身のヘッダーをそのまま渡します。Hub のソースはすべてのバックエンドに使われ、Claude と Codex のリクエストは Model Hub が変換します。ゲートウェイはすべてのプロトコルを扱うので、見分けられない Avibe のプロトコル検査はせずに保存します。

モデル一覧

Avibe はゲートウェイの /v1/models から自分でモデルを読むので、選べるのは magpie のエージェントページで Avibe に選んだモデルです。Avibe 自身は一覧が 30 分より古いときだけ読み直すため、モデルを増減すると magpie がソースをすぐ更新させます。

削除

元に戻すと、magpie は同じ内部 API でソースを消し、控えた id を忘れます。削除でルートのホップが消えたり作業中の処理が中断されたりする場合、Avibe は Models ページと同じく確認を求めます。magpie で頼まれた操作なので、magpie は Avibe が挙げた内容を付けてもう一度確認します。

ターミナル
magpie avibe default

よくある質問

Avibe の中の Claude Code や Codex も magpie のモデルを使えますか？

使えます。magpie は Model Hub のソースで、Hub のソースは Vibey と Avibe が動かすすべてのバックエンド（Claude Code、Codex、OpenCode）に使われます。

先に Avibe を起動するよう言われるのはなぜですか？

Avibe は動いている間だけ内部 API でモデルソースを追加・削除し、config.json は直接編集できません。vibe start を実行してからもう一度試してください。

Avibe で選べるモデルは？

magpie のエージェントページで Avibe に選んだモデルです。Avibe はゲートウェイの /v1/models から読み、一覧が変わると magpie が更新させます。

magpie を外すには？

magpie で Avibe を既定に戻すか、magpie avibe default を実行します。magpie が加えたソースを消します。

同じモデルを他のエージェントでも：MothX を任意のモデルで、PenguinHarness を任意のモデルで、Paimon を任意のモデルで、StepCode を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
