ドキュメント · ガイド

OpenBot を任意のモデルで

OpenBot は Codex、Claude、OpenCode などのエージェントを動かす Electron のワークスペースです。モデル選択には、自分で追加した OpenAI 互換のエンドポイントが並びます。magpie が magpie という名前のエンドポイントを加えると、DeepSeek、GLM、Kimi、Qwen、GPT、ChatGPT サブスクリプションなど magpie のモデルが選べるようになります。

OpenBot の設定

  1. magpie にプロバイダーを追加プロバイダー ページで API キーを追加するか、サブスクリプションにサインインします。
  2. エージェント ページで OpenBot のプロバイダーを magpie にmagpie が OpenBot のカスタムエンドポイントのファイルに自分のエンドポイントを書きます。
  3. OpenBot を再起動し、そのモデル選択で選ぶmagpie のモデルは magpie/<id> と表示されます。
ターミナル
magpie openbot provider magpie

ファイルの場所

OpenBot はカスタムエンドポイントを Electron の userData フォルダーに置きます。

ターミナル
macOS:   ~/Library/Application Support/OpenBot/openbot-custom-providers-v1.json
Windows: %APPDATA%\OpenBot\openbot-custom-providers-v1.json
Linux:   ~/.config/OpenBot/openbot-custom-providers-v1.json

書き込まれる内容

ターミナル
{
  "version": 1,
  "providers": [
    …your own endpoints, left as they are…,
    {
      "id": "magpie",
      "name": "magpie",
      "baseUrl": "http://127.0.0.1:3425/agent/openbot/v1",
      "models": [
        {"id": "deepseek/deepseek-v4-pro", "name": "DeepSeek V4 Pro", "contextWindow": 1000000},
        …
      ],
      "secret": null
    }
  ]
}

version は 1 でなければなりません。OpenBot が読めないファイルがあると、エンドポイントが 1 つもなくなり、保存もできなくなります。そのため magpie も、読めないファイルには手を付けません。

OpenBot はエンドポイントごとのキーとヘッダーをまとめて secret に入れ、Electron の safeStorage（キーチェーン、DPAPI）で暗号化します。magpie はこれを開かないので、magpie のエンドポイントにはキーがありません（secret は null）。OpenBot はこれをキーなしで OpenCode に渡し、ゲートウェイはこのコンピューターからのキーなしのリクエストを受け付けます。

リクエストを送るのは OpenCode で、User-Agent も OpenCode のものです。アドレスの /agent/openbot によって、ゲートウェイは OpenBot のリクエストとして数えます。OpenBot で magpie のエンドポイントに付けた名前、harness、キーは残ります。自分の他のエンドポイントもそのままです。

表示されるモデル

OpenBot のリストの検査は厳格で、受け付けないエンドポイントやモデルが 1 つでもあるとリスト全体が空になります。そのため magpie は、magpie で OpenBot 用に選んだモデルだけを、次の条件で書きます。

  1. 最大 64 個1 つのエンドポイントの上限で、超えるとすべて表示されなくなります。
  2. 受け付けられる id英数字と ._:/[],=- だけで、magpie/ を付けて 160 文字以内です。
  3. 範囲内のコンテキストウィンドウcontextWindow は 1,024 から 100,000,000 の間のときだけ書きます。

反映されるタイミング

OpenBot はこのファイルを起動時に一度だけ読みます。書き戻すのは OpenBot でエンドポイントを保存、編集、削除したときだけで、そのとき手元の内容でファイル全体を書き直します。そのため変更は再起動後に表示されます。再起動前に OpenBot でエンドポイントを保存すると、magpie のエンドポイントが消えます。OpenBot の動作中は、エンドポイントを追加・編集する前に再起動するよう magpie が促します。

MCP サーバーは OpenBot の SQLite データベースにあり、magpie は書きません。magpie の MCP サーバー（/mcp/magpie/…）は、OpenBot で HTTP サーバーとして手動で追加します。

元に戻す

既定に戻すと、magpie は自分のエンドポイントだけを消します。ファイルに何も残らなければファイルごと消します。ファイルがないときも、OpenBot は空のリストから始まるからです。

ターミナル
magpie openbot default

よくある質問

OpenBot で DeepSeek、GLM、ChatGPT サブスクリプションを使うには？

magpie のエージェントページで OpenBot のプロバイダーを magpie にし、OpenBot を再起動してから、モデル選択で magpie/ で始まるモデルを選びます。

なぜ magpie のエンドポイントに API キーがないのですか？

OpenBot はエンドポイントのキーをシステムのキーチェーンで暗号化し、magpie はそれを開きません。ゲートウェイはこのコンピューターからのキーなしのリクエストを受け付け、アドレスの /agent/openbot で OpenBot のものと分かります。

なぜ magpie のモデルがすべて表示されないのですか？

magpie は OpenBot 用に選んだモデルだけを最大 64 個まで書き、OpenBot が受け付けない id は飛ばします。不正なモデルが 1 つあると OpenBot はリスト全体を空にするからです。

変更が反映されないのはなぜですか？

OpenBot はカスタムエンドポイントを起動時にしか読まないので、再起動してください。その前に OpenBot でエンドポイントを保存すると、magpie のエンドポイントが消えます。

同じモデルを他のデスクトップアプリでも：Lody を任意のモデルで、Cindy を任意のモデルで、miniQ を任意のモデルで、Tuanjie Cowork を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
