Privacy

Your prompts, replies, keys and accounts go only to the providers you use; magpie has no server of its own in that path. This page lists everything magpie sends by itself, beside those requests, and every switch that stops it. It is written from the code, which is linked in each section.

The daily count

Once a day (UTC), a running release of magpie (the app, or magpie serve) sends one batch to PostHog, so we know how many people use it and which agents, providers and models to look after first. It is sent at start and then looked at every hour; a day already sent is skipped. Builds from source never send it.

The batch has one magpie active event with:

  • a random id made up on your computer (32 hex characters, tied to nothing about you or the machine), sent as distinct_id;
  • magpie’s version, kind (app or serve), your system ($os) and architecture;
  • how many agents, providers and models it is used with, and how many routing groups (left out when you turn off sharing what you use).

Unless you turn that part off, one magpie uses event follows for each agent, provider and model, by magpie’s own ids only (at most 50 of each):

  • agents connected to magpie: claude, codex. A WSL distro or an omp profile name is cut off (omp).
  • providers that are on: a preset’s id (deepseek), a subscription’s (codex, copilot), a known community plugin’s (plugin:kiro). A provider you added yourself is only custom; any other plugin only plugin.
  • models the connected agents are set to, as provider id and vendor model id (deepseek/deepseek-v4). On a key’s provider, a model id that models.dev doesn’t list (a local model, a fine-tune) is only <provider>/other; a model on your own provider is custom; a routing group is group.

With them go magpie partner events: for each partner listed first in the add sheet, by its id, how many times on a day that has ended the sheet showed it, its row was opened, its key page was opened, and a provider was added from it (what: shown, opened, keys, added; at most 20 a day each, 5 adds). Counts only, never a provider of your own.

With that part on, magpie also tells usemagpie.ai, on the same day, which of the plugins Discover lists are installed and on, so Discover can say how many use each one: POST /api/plugins/report with the same random id and the plugins’ npm names, or github:owner/repo for a repository tagged magpie-plugin (at most 50). A plugin from a folder, a private repository or a package Discover doesn’t list is never named. A like on a plugin’s page goes as POST /api/plugins/like with the id, the plugin and whether it is on, and only for a plugin installed here; the plugins you liked are kept in plugin-likes.json. The site counts the ids that reported a plugin in the last 7 days, drops a report after 30 days, and keeps your address only hashed, for an hour, to limit how often it is asked. Discover reads the counts from GET /api/plugins/stats, which carries no id. The code is internal/stats/plugins.go and site/pluginstats.js.

Every event carries $process_person_profile: false, so PostHog keeps no person profile for the id. No names, base URLs, accounts, keys, prompts, replies or usage are sent. A whole batch looks like this:

Turning it off

Each of these switches stops part or all of it:

  • Settings → Privacy → Count me as a user off, or "noStats": true in settings.json stops the whole daily count.
  • DO_NOT_TRACK=1 or MAGPIE_NO_STATS=1 in magpie’s environment (any value but empty, 0 or false) stops the whole daily count, whatever the settings say.
  • Settings → Privacy → Share the agents, providers, models and plugins I use off, or "noUsageStats": true leaves out the magpie uses and magpie partner events, the counts in magpie active and the plugin report; the id, version and system are still sent. Partner counts stop being kept too.
  • Settings → About → Automatic updates off, or "noAutoUpdate": true stops magpie asking usemagpie.ai for a newer version by itself (it asks every 6 hours otherwise). This is not part of the count.

A change in Settings takes effect at the next hourly look; no restart is needed. settings.json sits in magpie’s folder (see below):

settings.json 
{
  "noStats": true,
  "noUsageStats": true,
  "noAutoUpdate": true
}

MAGPIE_STATS_HOST sends the count to another host instead (it is for testing, and also makes a build from source send).

Files on your computer

FileWhat it is
install-idThe random id, made the first time the count is sent
stats-sentThe last day (UTC) the count went, so a day is sent once
plugin-likes.jsonThe plugins you liked in Discover
partner-counts.json (in the cache folder)Partner counts not yet sent, at most 14 days

install-id and stats-sent are in magpie’s folder: ~/.config/magpie on macOS and Linux, %USERPROFILE%\.config\magpie on Windows, $XDG_CONFIG_HOME/magpie when that is set, and the data folder of a portable magpie. partner-counts.json is in ~/.cache/magpie ($XDG_CACHE_HOME/magpie, or cache in a portable magpie’s data folder). You can delete any of them: a deleted install-id is replaced by a new random one at the next send, so you are counted as a new user; with the count off, none of them is written again.

The request archive (the Request archive switch on the Usage page, above the list of requests) is off by default. Turned on while sync has no S3 bucket, it keeps each gateway call’s headers and bodies, secrets masked as for the S3 archive, in request-archive in magpie’s folder, one file per call, readable by your user only. It grows to 1 GiB (requestArchiveLocalMB in settings.json) and the oldest calls are removed past that. The switch is this computer’s own: sync never turns it on at another computer. With an S3 bucket the calls go to the bucket instead, and nothing is written here. Delete the folder whenever you like.

The app writes a log of what it did, app.log, in ~/Library/Logs/magpie on macOS, %LOCALAPPDATA%\magpie\logs on Windows and ~/.local/state/magpie on Linux (see Where is magpie’s log?), readable by your user only. It names what magpie did and the errors it met, never keys, prompts or replies, and stays on your computer unless you send it. It is kept to 5 MiB, with one older file, app.old.log. Delete them whenever you like.

What usemagpie.ai sees

magpie asks its own site for a few things, whatever the privacy settings say, as any app asks its update server. None of these requests carries the install id or an account.

  • /api/latest: the update feed, every 6 hours unless noAutoUpdate is on, with ?lang= for the notes in your language, and ?channel=stable when Settings → About → Update channel is Stable. Neither says who you are. /api/notes gives What’s new after an update.
  • /files/<version>/<file>: the release files an update and the installer download, served from Cloudflare R2. A file the site doesn’t hold is sent on to github.com. Nothing is counted.
  • /api/partners: the add sheet’s partner list, every 6 hours. One fetch in ten is counted as a magpie partners fetch event, with the country Cloudflare gives, while a partner is listed.
  • /go/<partner>/site and /go/<partner>/keys: a partner’s website and key-page links, opened in your browser, are counted (the partner, which link, a region, a country) as magpie partner go before you are sent on.
  • /api/plugins/stats: Discover’s counts of how many use and like each plugin, at most once an hour. It carries no id; the plugin report and likes do, and go only with sharing what you use on.
  • /api/icon?url=…: icons named by a plugin, an import link or the library are fetched through it, so their hosts see Cloudflare’s address, not yours. The worker passes the picture on and counts and keeps nothing.

The site’s own pages (these docs, the home page) carry Cloudflare Web Analytics and PostHog Web Analytics (us.i.posthog.com), without cookies. PostHog keeps a random visitor id in your browser’s local storage for this site, so a return visit counts as the same visitor. It gets each page’s address, the page that sent you, what you click on the page (not what you type), how fast the page and its requests loaded, errors the page hit, your browser, system and screen size, the country and city your address is in, and a recording of the visit (what the page showed, mouse moves, clicks and scrolls, its console messages) with every input box masked; nothing at all when your browser sends Do Not Track or Global Privacy Control. PostHog’s requests go through this site, under usemagpie.ai/r/, which passes them and your address on to PostHog and keeps the site’s cookies. Following a /download link, or fetching install.sh, sends PostHog a count of its own: which file, your country, and whether a browser or a command asked; no id and no address. The app doesn’t load either. The code is site/worker.js.

Public lists magpie fetches

To price and name models magpie fetches the models.dev catalog (models.dev/api.json), and for prices in your currency the USD exchange rate from open.er-api.com (kept 12 hours). Plugins and their updates come from the npm registry, and the library’s items from GitHub. These are plain downloads of public data: nothing about you, your providers or your usage is sent, though, as with any request, those hosts see your IP address (or your proxy’s). magpie also asks each of your providers for your allowance and model list, with your own key or sign-in; Settings → Allowances → Allowance reads → When I ask limits those to when you ask.

OTLP export

magpie can export each gateway request to an OpenTelemetry collector of yours (Langfuse, for example). It is off by default, and goes only to the endpoint you set, never to us. When on, it sends per-request spans: agent, provider, model, the name you gave the gateway key it came with (never the key itself), token counts, status, timing and estimated cost. Optional switches add metrics, local agent conversations, and the request and reply bodies (secrets masked). Turn it on in Settings → Observability, or for magpie serve with MAGPIE_OTEL_ENABLED, MAGPIE_OTEL_ENDPOINT, MAGPIE_OTEL_HEADERS, MAGPIE_OTEL_METRICS, MAGPIE_OTEL_SESSIONS, MAGPIE_OTEL_BODIES and MAGPIE_OTEL_BODIES_WHOLE. An endpoint alone doesn’t turn it on. For Langfuse, pick Langfuse there and give its host and your project’s two keys; magpie makes the endpoint and sign-in from them. Each export’s resource is service.name=magpie, plus only what you set yourself in OTEL_RESOURCE_ATTRIBUTES and OTEL_SERVICE_NAME (a server name, for example); nothing about your machine is looked up. The reference has the details.

Masking what goes to providers

The sections above are what magpie sends by itself. What your agents send goes to the providers you chose, and privacy masking keeps the secrets in it on this computer. It is off by default; turn it on in Settings → Privacy.

  • Before a request leaves this computer, API keys, private keys, tokens, emails, and card and ID numbers whose checksum adds up become placeholders such as {{API_KEY_k3v9x2mq}}. Find with a local model adds the names, addresses and passwords no rule can find, with a model that runs on this computer (a 1.6 GB download, on the CPU).
  • Every placeholder in the reply, streamed text and tool-call arguments included, turns back into its value, so your agent and your files keep the real values.
  • A value gets the same placeholder every time, so the conversation and the prompt cache stay valid.
  • Values are held in memory only; the record on disk keeps each value’s kind, length and first characters. If masking is on and can’t run, the request gets a 503 and nothing is sent.
  • The model sees the placeholder, not the value. A value a task needs as it is (a team address, a test key) goes under Never mask.

How to turn it on, what each switch masks, an example and how to check it: Privacy masking.

Why the count is on

magpie works with dozens of agents and providers, and is maintained by a small team. The daily count is how we know which of them people actually use, so they are kept working first. It is on in releases because counts from those who turn it on would be too few to tell that. In exchange it is kept small: a random id, built-in ids, numbers; one switch or DO_NOT_TRACK=1 turns it off, builds from source never send it, and this page lists everything that goes.
