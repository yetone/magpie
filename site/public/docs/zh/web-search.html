Web search

工作原理 设置 代搜供应商 搜索 API 自带联网搜索的模型 作为 MCP 服务器 谁搜的

文档 · 指南

让任意模型联网搜索

Claude Code 有 WebSearch，Codex 有 web_search，但这些工具要模型的供应商自己会搜索才有用。DeepSeek、GLM、Qwen 等很多模型的 API 并不联网，通过 magpie 用它们时，magpie 会代为搜索：模型拿到 magpie 的 web_search 工具，调用时 magpie 去搜，把找到的网页交回给模型，回复里的搜索结果和来源也按 Agent 认识的格式返回。所以在 Claude Code 或 Codex 里换成任何模型，联网搜索都照常可用。

设置

搜索的来源有两类：能搜索的供应商（代搜供应商），和你配置的搜索 API。都在 设置 › 模型 › 联网搜索。

  1. 有能搜索的供应商就不用设置magpie 会自己挑一个代搜供应商，比如 Google 登录、ChatGPT 账号（Codex 登录）、Kimi Code、GLM Coding Plan 或 WorkBuddy 的计划。
  2. 或者添加一个搜索 API在 搜索 API 里加上 Tavily、Brave Search 等的 Key。没有能搜索的供应商时，就由这些 API 来搜。
  3. 用 优先使用 选先用哪一类另一类在前一类失败时再用。

代搜可能消耗所用服务的额度或产生费用。

代搜供应商

代搜供应商是自带联网搜索的供应商，由它替不能搜索的模型去搜。在 代搜供应商 里可以选一个，不选就由 magpie 挑：

  • magpie 挑的：它失败或没找到结果时，magpie 换下一个能搜索的供应商，最多试三个。
  • 你选的：它失败时，只换成你在 失败时依次换用 里排在它后面的供应商，按顺序。只有它完全搜不了（额度用完或被限流）时，才再试其他可用的来源，最后用你的搜索 API。
  • 所有来源都失败时，错误作为工具结果交回模型，这一轮继续。

有几个供应商会先给自己的模型搜索：Kimi Code 计划用它自己的搜索服务，GLM Coding Plan 用计划自带的 Web Search MCP 服务器（用同一个 Key，不用另外配置），WorkBuddy 计划用它的搜索服务，Google 登录用 Google 搜索。ChatGPT 账号用 ChatGPT 后台自己的搜索，也就是 Codex 的 web.run 发的那个请求。

想只用搜索 API，可以把供应商代搜关掉：这时所有模型都只用已配置的搜索 API，一个都没有时 magpie 不添加搜索工具。供应商自带的联网搜索不受影响。

搜索 API

可以添加的搜索 API：Tavily、Brave Search、Exa、Firecrawl、You.com、DeepSeek、Doubao Search (Volcengine)、Yuanbao Search (Tencent Cloud)、TinyFish、SearXNG，以及插件提供的。它们按列表顺序调用，可以拖动排序，也可以单独关闭（保留它和它的密钥，但不再调用）。命令行也能设置：

终端
magpie search add tavily 
magpie search add you              # You.com: free with no key (100 searches a day)
magpie search add searxng url=

magpie search                      # the search APIs, in the order they are asked
magpie search move  
magpie search count 10             # results per search, 1 to 20, 6 by default
  • 一个 API 可以填多个 Key，用逗号隔开，搜索时轮流使用；加 pick=order 则一直用第一个，直到它被拒绝。
  • SearXNG 必须填地址。其他 API 也可以用 url= 指向你自己的、和该 API 接口一致的端点，Key 只发给那个地址。
  • 每次搜索的结果条数：客户端没指定条数时（Claude Code 的 WebSearch、Codex 的 web_search）用这个值，1 到 20，默认 6。每条最多带 1500 字节的网页正文，条数越多模型要读的越多。
  • magpie search mix <api>,<api> 让几个 API 同时搜，合并后最多给 12 个网页。这会消耗每个 API 的额度。

自带联网搜索的模型

Grok、Gemini 等供应商的模型自己会搜索，客户端的联网搜索默认按原样交给它们。自带联网搜索的模型 一项可以改成 magpie 代搜，让它们也像其他模型一样用 magpie 的代搜供应商和搜索 API；选 自带搜索 则保持原样。

作为 MCP 服务器

同样的搜索也是一个 MCP 服务器，Cursor、Claude Desktop 或任何 Agent 都能添加。它提供 web_search 工具，还有按 URL 读取网页的 web_fetch 工具，给没有自带抓取工具的 Agent 用。地址在 联网搜索 页的 MCP 服务器 一行，默认是：

终端
http://127.0.0.1:3425/mcp/magpie/web-search

它只支持 Streamable HTTP。只支持 stdio 的客户端可以通过 mcp-remote 挂载。从其他电脑访问时（magpie 开着局域网共享），以 Authorization: Bearer <key> 发送网关密钥。web_fetch 只读公网地址，单次最多 30 秒、5 MiB。

谁搜的

每次代搜都会出现在 路由 页。换了来源时，会写明是谁替它搜的。

让任意模型识图，并在 Agent 里生成图片：不能看图的模型也能用截图，Agent 也能生成图片和视频。

常见问题

DeepSeek 能联网搜索吗？

DeepSeek 的 API 本身不联网。通过 magpie 用它时，Claude Code 的 WebSearch 或 Codex 的 web_search 会由 magpie 代搜：用能搜索的供应商，或你添加的搜索 API。

没有能搜索的供应商怎么办？

在 设置 › 模型 › 联网搜索 里添加一个搜索 API，比如 Tavily 或 Brave Search。You.com 不填 Key 也能用，每天 100 次；也可以填自建 SearXNG 的地址。

代搜要花钱吗？

代搜用的是所选服务的额度：代搜供应商会消耗它的额度或产生费用，搜索 API 按各自的价格计费。

Cursor 能用 magpie 的联网搜索吗？

能。把 /mcp/magpie/web-search 作为 MCP 服务器（Streamable HTTP）添加到 Cursor，就有 web_search 和 web_fetch 两个工具。
