文档 · 指南

Gemini CLI 接入 DeepSeek、Kimi、GLM、Claude 等第三方模型

Gemini CLI 只会说 Google 自己的 Gemini API。magpie 在你电脑上跑一个本地网关，替你添加的每个供应商提供 Gemini API，再把 Gemini CLI 指向它。模型在 magpie 里 Gemini CLI 那一行选。

网关地址是 127.0.0.1:3425，除了 OpenAI 和 Anthropic API，也提供 Gemini API 的 generateContent、streamGenerateContent、countTokens 和模型列表。供应商本身说 Gemini API 时请求原样转发；不说的，比如 DeepSeek、Kimi、智谱 GLM、Claude 或 ChatGPT 订阅，magpie 负责双向转换请求和回复，流式输出、工具调用、图片和推理都包括在内。

国产模型

DeepSeek、Kimi 与 Kimi Code、智谱 GLM（按量付费或 Coding Plan）、Z.ai、MiniMax、通义千问。

订阅

在 magpie 里登录的 Claude、ChatGPT、Copilot、Antigravity 账号，它们的模型都能用。

其他

任何 OpenAI 或 Anthropic 兼容的地址和 Key，以及 Ollama、LM Studio。

接入步骤

  1. 添加供应商在 magpie 的 供应商 页点 ＋ 添加供应商，选 DeepSeek、Kimi、智谱 GLM、MiniMax 或通义千问，粘贴 API Key 保存。magpie 会去问供应商有哪些模型。
  2. 给 Gemini CLI 选模型在 Agent 页点 Gemini CLI 那一行的模型，选一个，比如 deepseek/deepseek-v4-pro。magpie 会把它写进 ~/.gemini/settings.json，把网关地址写进 ~/.gemini/.env。
  3. 重启 geminiGemini CLI 启动时读取配置，已经打开的会话继续用原来的设置。

命令行也一样：

终端
magpie provider add deepseek sk-…
magpie models                              # 列出所有模型，格式为 provider/model
magpie gemini model deepseek/deepseek-v4-pro

模型 ID 用的是 magpie 的格式 provider/model。gemini 命令在 PATH 里时，magpie 才会显示 Gemini CLI 这一行。

智谱 GLM Coding Plan。添加智谱 GLM 或 Z.ai 时，选你的 Key 对应的套餐。Coding Plan 的 Key 有自己的接口地址，发到按量付费的接口会提示余额不足。

~/.gemini 里改了什么

Gemini CLI 会加载 ~/.gemini/.env，并读取 ~/.gemini/settings.json。magpie 在这两个文件里一共改四个键：

文件键写入的值
.envGOOGLE_GEMINI_BASE_URL网关地址
.envGEMINI_API_KEY网关的 Key（不是你的供应商 Key，那个留在 magpie 里）
settings.jsonsecurity.auth.selectedTypegemini-api-key，让 Gemini CLI 用这个 Key，而不是 Google 登录
settings.jsonmodel.name模型，格式为 provider/model

第一次改动时，magpie 会记下这几个键原来的值：你自己的 base URL、API Key、登录方式和模型。模型是 magpie 的、登录方式却被改成 API Key 以外的方式时，Gemini CLI 会直接请求 Google，magpie 里 Gemini CLI 那一行会提示。

切回 Google

在 Gemini CLI 那一行选一个它自己的 Gemini 模型，或者运行 magpie gemini default。magpie 会从 .env 里删掉 GOOGLE_GEMINI_BASE_URL 和 GEMINI_API_KEY，再还原你原来的 base URL、Key、登录方式和模型。不用手动改文件。

这一行的 auth 设置决定 Gemini CLI 自己怎么登录：Google（你的 Google 账号）、API key 或 Vertex AI。在 magpie 里添加了 Google Gemini 供应商时，选 API key 会把那个 Key 写进 .env 给 Gemini CLI 用。

终端
magpie gemini default   # 去掉 magpie 的接入，还原原来的设置
magpie gemini google    # 用 Google 账号登录

Claude、ChatGPT 订阅里的模型

在 magpie 里登录订阅：＋ 添加供应商，选 Claude、ChatGPT 或 Copilot。magpie 会打开厂商自己的登录页。登录后，账号的模型以 claude/…、codex/… 或 copilot/… 出现在 Gemini CLI 那一行。

终端
magpie accounts add codex           # 登录一个 ChatGPT 账号
magpie gemini model codex/gpt-5.5

Gemini CLI 说的仍然是 Gemini API，magpie 把每个请求转成模型需要的格式，再把回复转回来。Claude 订阅的请求通过你电脑上安装的 Claude Code 发出，所以要保留 Claude Code。详见 在任意 Agent 中使用订阅。

多个 Key 轮换

  • 同一家的多个 Key。都加到这个供应商里并勾选。供应商的 路由 决定怎么分摊，备用 列出额度用完或服务挂掉时改用的模型。
  • 同一个模型来自多个供应商。magpie 会自动建一个组 auto/<model>，给 Gemini CLI 选它即可。
  • 压缩上下文用便宜的模型。路由组的 压缩上下文时 规则能匹配 Gemini CLI 压缩对话的请求，让更便宜、更快的模型来写摘要。

路由方式和规则详见 快速上手。

常见问题

Gemini CLI 能用 Gemini 以外的模型吗？

能，需要一个提供 Gemini API 的网关。magpie 在你电脑上跑一个，并把 Gemini CLI 指向它，所以你添加的供应商的任何模型都能用：DeepSeek、Kimi、GLM、通义千问、MiniMax，或者 Claude、ChatGPT、Copilot 订阅。

需要自己设置 GOOGLE_GEMINI_BASE_URL 吗？

不需要。magpie 会把它和 GEMINI_API_KEY 写进 ~/.gemini/.env，并在 ~/.gemini/settings.json 里把 Gemini CLI 设为 API Key 认证。原来的值会被记下，切回时还原。

为什么 Gemini CLI 还是请求 Google？

它的登录方式不是 API Key：用 Google 登录或 Vertex AI 时，Gemini CLI 会直接请求 Google。在 magpie 里重新选一次模型，就会改回 API Key；出现这种情况时 magpie 里 Gemini CLI 那一行会提示。改完重启已经打开的 gemini 会话。

Gemini CLI 能用 ChatGPT 或 Claude 订阅吗？

能。在 magpie 里登录订阅，在 Gemini CLI 那一行选 codex/… 或 claude/… 模型即可。Claude 订阅的请求通过你电脑上安装的 Claude Code 发出。

为什么 magpie 里没有 Gemini CLI？

gemini 命令在 PATH 里时 magpie 才会显示它。只有 ~/.gemini 文件夹不算，因为卸载 Gemini CLI 后它还在，Antigravity 也会在里面放文件夹。

WSL 里的 Gemini CLI 能用吗？

能。magpie 用同样的方式配置 WSL 发行版里的 Gemini CLI，写入的是那个发行版访问网关用的地址。

怎么把 Gemini CLI 切回 Google？

在 magpie 里选一个 Gemini CLI 自己的模型，或者运行 magpie gemini default。magpie 写入的内容会被删掉，你原来的 Key、登录方式和模型会还原。

也在用 Claude Code 或 Codex？见 Claude Code 接入其他模型 和 Codex 接入其他模型。遇到问题可以到 Discord 提问。
