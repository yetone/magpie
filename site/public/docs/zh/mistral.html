Mistral 接入 Claude Code、Codex、Gemini CLI 和 OpenCode

Mistral 的模型只通过一种接口提供：api.mistral.ai 上的 OpenAI 风格 Chat Completions。把 Mistral 的 API Key 添加到 magpie 一次，Claude Code、Codex、Gemini CLI、OpenCode 以及你接入的其他工具，都能通过 magpie 的本地网关 127.0.0.1:3425 使用 Mistral，每个工具各用各的模型。说其他接口的工具，magpie 会在路上替它转换。

添加 Mistral

  1. 拿到 Key在 console.mistral.ai 创建。Le Chat 套餐的 Vibe Key 也加在同一个供应商里。
  2. 添加供应商在 magpie 的 供应商 页点 ＋ 添加供应商，选 Mistral，粘贴 Key 并保存。magpie 会向 Mistral 查询这个 Key 能用哪些模型。
  3. 给工具选上在 Agent 页点工具那一行的模型，选一个 Mistral 模型，比如 mistral-large-4。
终端
magpie provider add mistral <key>
magpie provider test mistral

magpie 里的模型 id 是 供应商/模型，所以 Mistral 的模型写作 mistral/mistral-large-4：前面是供应商，后面是 Mistral 自己的 id。Key 保存在 magpie 的设置里，magpie 不会从 shell 里读取它。

已经在 OpenCode 或 Alma 里配好了 Mistral？magpie 从这些应用导入时，会把它变成 Mistral 供应商。有的应用一个 Key 存一条（“Mistral #0001”“Mistral #0002”……），导入后会合并成一个 Mistral 供应商，里面放着同样多的 Key，在每个工具的模型选择器里只出现一次。

接口地址

接口地址用途
Chat Completionshttps://api.mistral.ai/v1模型列表和所有工具的请求：OpenCode 的原样发送，Claude Code、Codex 和 Gemini CLI 的转换后发送
计费https://api.mistral.ai/v1/billing/budget、/v1/billing/subscriptionKey 当月的 Vibe 或 API 额度，以及所在的套餐

magpie 的 Mistral 供应商没有 Anthropic Messages 或 Responses 地址，所以说这两种接口的工具，请求都会转换成 Chat Completions，回复再转换回去，流式输出和工具调用都包括在内。

模型列表

magpie 从 Mistral 的 https://api.mistral.ai/v1/models 拉取列表，所以工具里看到的就是这个 Key 能用的模型。名称、推理档位和价格来自 models.dev 的 mistral 目录；Devstral、Codestral 和 Magistral 模型在每个选择器里都带着 Mistral 的图标。Mistral 也提供其他厂商的模型，比如 GLM 和 DeepSeek 的 deepseek-v4.1-flash-1017，它们走同一个 Key，下面的修正对它们同样有效。工具能看到哪些模型，可以在供应商的模型列表里挑，也可以在终端里设置：

终端
magpie provider models mistral +mistral-large-4 +mistral-medium-3.5
magpie provider refresh-every mistral 1d

在各个工具里用

终端
magpie claude mistral/mistral-large-4
magpie codex mistral/mistral-large-4
magpie gemini model mistral/mistral-large-4
magpie opencode mistral/mistral-large-4
  • Claude Code 说的是 Anthropic Messages，Mistral 不提供这个接口。magpie 把每个请求转换成 Chat Completions，再把回复转换回来；推理模型的思考会先以思考内容出现在 Claude Code 里，然后才是正文。Claude Code 接入其他模型。
  • Codex 说的是 OpenAI Responses，Mistral 同样不提供，所以它的请求也要转换。apply_patch 这类 Codex 自定义工具会以函数的形式交给模型，模型的调用再以 Codex 能执行的自定义工具调用还回去。Codex 接入其他模型。
  • Gemini CLI 说的是 Google 的 Gemini 接口。magpie 把每个请求转换成 Chat Completions，再把回复转换回来。Gemini CLI 接入其他模型。
  • OpenCode 说的是 Chat Completions，所以请求原样发给 Mistral，只做下面这些修正。OpenCode 接入其他模型。

magpie 替你修正的请求

Mistral 的接口对收到的内容很严格，推理模型的思考也用它自己的格式返回。magpie 在路上把两边都调整好，原样转发的请求和转换过的请求都一样：

  • 分段的思考内容。Mistral 把推理模型的思考放进 content，写成带类型的分段，思考和正文有时还挤在同一个 chunk 里，而 Chat 接口约定这里是字符串。OpenCode 收到第一个这样的 chunk 就报错（“Invalid … stream event”）。magpie 把思考移到 reasoning_content，正文改成普通字符串，流式和非流式回复都一样。
  • 回传的思考。OpenCode 会把上一轮的思考放在 reasoning_content 里传回去，Mistral 对此回 422 extra_forbidden。magpie 把它改成 Mistral 自己返回时用的思考片段，放在这一轮正文前面，思考就还留在上下文里。转换过的请求也这样处理，所以在 Mistral 上跑 DeepSeek 模型时，Codex 的工具调用循环能一直走下去。
  • Mistral 不认识的字段。OpenCode 的 store 和 Kimi Code 的思考开关都会换来 422 extra_forbidden。magpie 去掉 Mistral 点名的可选字段重新请求，成功之后就不再给它发这些字段。
  • Ollama 参数。有的工具把网关当成了 Ollama 服务器（比如 Hermes Agent），会在 Chat 字段旁边带上 Ollama 的 options（其中的 num_ctx）。magpie 会把它们去掉，Mistral 根本看不到。

推理

  • 推理强度。工具要求的推理强度，会按目录里列出的档位，换成这个模型最接近的一档。不知道档位的模型，按工具的原始要求发送。
  • 关闭推理。需要 magpie 转换请求的工具（比如 Gemini CLI）关掉推理时，如果模型的档位里有 none，magpie 就请求 none。
  • 跨轮次的思考。每个工具都以自己的格式看到推理模型的思考：OpenCode 是 reasoning_content，Claude Code 是思考块，Codex 是推理内容。下一轮传回来时，Mistral 收到的是思考片段，见 magpie 替你修正的请求。

联网搜索

Mistral 的 Chat Completions 接口不会替 magpie 联网搜索，所以在每个工具里，magpie 都给模型提供自己的搜索工具，由设置里指定的搜索服务回答；没指定时，由 magpie 自己挑一个。

Vibe、费用与用量

  • Vibe 月度额度。Le Chat 套餐（Pro、Student 或 Team）附带一个月的 Mistral Vibe。它的 Vibe Key 那一行会显示本月额度用了多少（按 Mistral 计费的币种）、什么时候重置，以及套餐名称。
  • API 月度额度。在控制台创建的 Studio Key 显示组织的 API 额度，名为 “API · Month”，和 Vibe 的额度分开。额度是整个组织的，所以同一个组织的每个 Key 显示的数字都一样。没有额度的 Key 不显示卡片。
  • 按量付费。开了按量付费时，超出额度的部分照常计费而不会被停掉，所以用完当月额度也不会让这个 Key 的模型停用。
  • 缓存 token。回复里报告了缓存命中的提示 token 时，用量 页会把它们和其余的提示分开统计。
  • 保住缓存。有多个 Key 时，只要一段对话的缓存值得保留（1,024 个 token 以上），而且还热着（五分钟内读过），它就一直用同一个 Key。
  • 费用。用量页按 models.dev 上 Mistral 的价格给每次调用计价。magpie 不会从 Mistral 读取余额；可以用 key-balance 自己填上，用量页会显示它减去 magpie 此后给这个 Key 的调用算出的费用。

多个 Key 与故障切换

一个 Mistral 供应商可以放多个 Key：在它下面点 添加另一个密钥，也可以一次粘贴好几个。请求先走第一个开着的 Key，它用完或被限流时由下一个接替。

  • 花费上限。spend-cap 给某个 Key 设一个每天、每月或总计的美元上限，按用量页的计价算；到了上限，路由就转去其他 Key 和备用模型。
  • 备用模型。fallback 指定 Mistral 额度用完或挂掉时请求去哪：另一个供应商的模型，或一个路由分组。
终端
magpie provider spend-cap mistral <key> 20 month
magpie provider key-balance mistral <key> 25
magpie provider fallback mistral deepseek/deepseek-v4-pro

常见报错

  • 422 extra_forbidden，“Extra inputs are not permitted”。Mistral 拒绝了它不认识的字段。工具常发的那些 magpie 已经处理好了；遇到 Mistral 点名的可选字段，magpie 会去掉它重新请求，见 magpie 替你修正的请求。
  • OpenCode 里出现 “Invalid … stream event”。这是 Mistral 分段返回的思考内容造成的。magpie 会把思考放进 reasoning_content、正文改成字符串再交给 OpenCode。
  • 没有 Vibe 卡片。只有 Mistral 认定为 Vibe Key 或 Studio Key、并且额度大于零的 Key，magpie 才显示当月额度。
  • 检查 Key。magpie provider test mistral 会向每个接口发一个很小的请求，或者发给你指定的每个模型。加上 --as codex 或 --as claude-code，就按那个工具的方式发送。

常见问题

怎么在 Claude Code 里用 Mistral？

在 magpie 里添加 Mistral API Key（供应商、添加供应商、Mistral），然后在 Claude Code 那一行选一个 Mistral 模型，比如 mistral-large-4，或者运行 magpie claude mistral/mistral-large-4。Mistral 只提供 Chat Completions 接口，所以 magpie 把 Claude Code 的 Anthropic Messages 请求转换后发到 https://api.mistral.ai/v1，再把回复转换回来，思考内容也一样。

Codex 能用 Devstral 等 Mistral 模型吗？

能。你的 Mistral Key 列出的模型，包括 Devstral，Codex 都能用。Codex 说的是 OpenAI Responses 接口，Mistral 不提供，所以 magpie 把每个请求转换成 Chat Completions，把 apply_patch 这类 Codex 自定义工具当作函数交给模型，再把调用按 Codex 能执行的方式还回去。

怎么在 OpenCode 里用 Codestral 等 Mistral 模型？

在 magpie 里选好模型，或者运行 magpie opencode mistral/mistral-large-4；只要你的 Key 列出了 Codestral 或 Devstral，用法完全一样。OpenCode 说的是 Chat Completions，请求原样发给 Mistral，只在路上修掉 Mistral 会拒绝的内容：OpenCode 的 store 字段，以及放在 reasoning_content 里回传的上一轮思考。

Gemini CLI 能用 Mistral 吗？

能。Gemini CLI 说的是 Google 的 Gemini 接口，magpie 会把它的请求转换成 Mistral 的 Chat Completions，再把回复转换回来，流式输出和工具调用都包括在内。运行 magpie gemini model mistral/mistral-large-4 即可。

Mistral 为什么回 422 extra_forbidden？

Mistral 会拒绝它不认识的任何字段。magpie 会把上一轮的思考改成 Mistral 接受的思考片段，去掉部分工具附带的 Ollama 参数；遇到 Mistral 点名的可选字段（比如 OpenCode 的 store），就去掉它重新请求，之后也不再发送。

magpie 能显示 Le Chat 套餐的 Vibe 额度吗？

能。Le Chat 套餐（Pro、Student 或 Team）的 Vibe Key 会显示本月 Vibe 额度用了多少、按 Mistral 计费的币种计、什么时候重置，以及套餐名称。在控制台创建的 Studio Key 则显示组织的 API 额度，名为 “API · Month”。
