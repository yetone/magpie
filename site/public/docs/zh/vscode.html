文档 · 指南

让 VS Code 用任意模型

VS Code 自带的 Chat（GitHub Copilot Chat）从 VS Code Stable 1.122 起有 Custom Endpoint 供应商，可以接入别的厂商的模型，不需要登录 GitHub，也不需要 Copilot 订阅。模型分组写在 settings.json 旁边的 chatLanguageModels.json 里，VS Code 会监视这个文件，改动后自动重新读取。magpie 在里面加一个自己的模型组，VS Code 的 Chat 就能用 DeepSeek、GLM、Kimi、Qwen、Claude 或 ChatGPT 订阅等 magpie 里的任意模型。

接入 VS Code

  1. 在 magpie 里添加供应商在 供应商 页添加 API Key，或登录一个订阅。
  2. 在 Agent 页给 VS Code 选模型选一个 via magpie 的模型。
  3. 在 VS Code 的 Chat 里选模型magpie 的模型在 Chat 模型选择器的 magpie 分组下。没看到的话，在 VS Code 里运行 Developer: Reload Window。

chatLanguageModels.json

magpie 写入一个 {"vendor": "customendpoint", "name": "magpie"} 的模型组，列出 magpie 目录里的模型：每个模型都指向网关的 /v1/chat/completions，并打开工具调用，因为 Agent 模式只列出能调用工具的模型。

终端
// chatLanguageModels.json (beside settings.json)
[
  {
    "name": "magpie",
    "vendor": "customendpoint",
    "apiType": "chat-completions",
    "models": [
      {
        "id": "deepseek/deepseek-v4-pro",
        "name": "…",
        "url": "http://127.0.0.1:3425/v1/chat/completions",
        "toolCalling": true,
        "vision": …,
        "contextWindow": …,
        "maxOutputTokens": …,
        "requestHeaders": { "Authorization": "Bearer " }
      }
    ]
  }
]

模型组的 apiKey 不能写在这个文件里，VS Code 只从自己的密钥存储里读它。所以每个模型在 requestHeaders 里带上 magpie 的令牌作为 Authorization，Custom Endpoint 模型会用它代替 Key，VS Code 不会再向你要 Key。你在 VS Code 里自己加的模型组保持不动。

新对话的模型

新对话用哪个模型由 chat.defaultModel 设置决定，magpie 把它设成目录里的模型 ID。在 Chat 的模型选择器里选的模型保存在 VS Code 自己的存储里，不在这个设置里。

终端
// settings.json
"chat.defaultModel": "deepseek/deepseek-v4-pro"

配置文件和 Insiders

默认配置文件的 chatLanguageModels.json 在 User 文件夹里，其他配置文件各有自己的一份。magpie 在每个配置文件里都写入模型组，之后新建的配置文件也会补上。VS Code Insiders 有自己的 User 文件夹和自己的一行，接入方式完全一样。便携版 VS Code 的文件在它的数据文件夹里，magpie 也会找到。

VSCodium

VSCodium 没有自带的 Copilot Chat，要从 Marketplace 安装。Marketplace 上它的最后一个版本（0.48.1）没有 Custom Endpoint，只有 OpenAI Compatible 供应商（customoai）。magpie 按已安装扩展的 package.json 判断写哪一种：OpenAI Compatible 用同一个文件里的同一个模型组，令牌放在 x-api-key 里，因为它会去掉 requestHeaders 里的 Authorization。这个供应商只在 Copilot Chat 用带个人 Copilot 订阅的 GitHub 账号登录时才出现。

此外 VSCodium 的 Chat 功能要打开（chat.disableAIFeatures=false），它的 product.json 里要有 GitHub.copilot-chat 的 defaultChatAgent 和 trustedExtensionAuthAccess，然后运行 Developer: Reload Window。magpie 会在 Agent 页提示这些。

切回

在 magpie 里给 VS Code 选它自己的模型（比如 Copilot 的 Auto）时，magpie 把 chat.defaultModel 设成这个模型，其他配置文件恢复成各自原来的值，模型组留在 Chat 的选择器里。在 magpie 里关掉 VS Code 时，每个配置文件的 chat.defaultModel 恢复成接入前的值，模型组也被移除。

常见问题

VS Code 的 Chat 不订阅 Copilot 也能用 DeepSeek 或 GLM 吗？

能。VS Code 1.122 起的 Custom Endpoint 供应商不需要 GitHub 登录和 Copilot 订阅，magpie 把模型组写进 chatLanguageModels.json 即可。

为什么 Chat 里看不到 magpie 的模型？

需要 VS Code 1.122 或更高版本。版本没问题的话，在 VS Code 里运行 Developer: Reload Window。

magpie 的 Key 写在哪里？

VS Code 只从密钥存储读 apiKey，所以 magpie 把令牌放在每个模型的 requestHeaders 里，VS Code 不会向你要 Key。

VSCodium 能用吗？

能，但要装 Marketplace 的 Copilot Chat，它的 OpenAI Compatible 供应商只在用带个人 Copilot 订阅的 GitHub 账号登录时出现。

更多 Agent 用同样的模型：让 Claude Science 用任意模型、让 Claude Desktop 用任意模型、让 mu 用任意模型、让 WorkBuddy 用任意模型。遇到报错？见 常见错误排查，或到 Discord 提问。
