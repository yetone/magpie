让 mu 用任意模型

mu（qybaihe/mu，npm 包 mu-agent，mu 命令和 mu 桌面应用）是在 Pi 上加了一个判断内核扩展的 Agent：它启动的就是 Pi，只是把 Pi 的 settings.json 和 models.json 放在自己的 ~/.mu/agent 文件夹里，桌面应用也用同一个文件夹。所以 magpie 像接入 Pi 一样接入 mu，mu 就能用 DeepSeek、GLM、Kimi、Qwen、Claude 或 ChatGPT 订阅等 magpie 里的任意模型。

接入 mu

  1. 在 magpie 里添加供应商在 供应商 页添加 API Key，或登录一个订阅。
  2. 在 Agent 页给 mu 选模型选一个 via magpie 的模型，需要的话再选思考强度。命令行和桌面应用都会用上它。
  3. 开始新会话新的 mu 会话就用这个模型。
终端
magpie mu deepseek/deepseek-v4-pro

settings.json 和 models.json

magpie 在 settings.json 里写 defaultProvider、defaultModel 和 defaultThinkingLevel，在 models.json 里把 magpie 加成名为 magpie 的供应商，和 Pi 的写法一样。

终端
// ~/.mu/agent/settings.json
{
  "defaultProvider": "magpie",
  "defaultModel": "deepseek/deepseek-v4-pro",
  "defaultThinkingLevel": "…"
}
终端
// ~/.mu/agent/models.json
{
  "providers": {
    "magpie": { "apiKey": "", … }
  }
}

mu 第一次运行时会检查是否要先跑 mu setup：只有 models.json 里没有任何供应商、settings.json 里也没有 defaultProvider 时才会要求。magpie 写好这两项之后，mu 就当作已经设置过，不用再跑 mu setup。

mu 自己的 Key

mu 发出的请求和 Pi 一样，User-Agent 写的是 pi/ 加版本号。为了分清哪些请求来自 mu，magpie 给 mu 一个单独的 Key（magpie-mu），网关就把这些请求算在 mu 名下，不算成 Pi 的。

mu 的文件夹

magpie 按 mu 自己的规则找它的文件夹：先看下面这几个环境变量，按顺序用第一个有值的，里面的 ~ 当作主目录。

终端
MU_AGENT_DIR
KYRN_AGENT_DIR
MU_CODING_AGENT_DIR
KYRN_CODING_AGENT_DIR

都没设时用 ~/.mu/agent；如果只有旧名字 ~/.kyrn 而没有 ~/.mu，就用 ~/.kyrn/agent。在 WSL 里装的 mu 也一样接入，只是那里的环境变量 magpie 读不到。

mu 这个命令名并不唯一：PATH 上的 mu 如果是 maildir-utils 的 mu（djcb/mu），magpie 不会把它当成 mu-agent。mu-agent 也可以用别名 mu-agent 认出。

判断模型

mu 的判断内核有自己的设置（mu.json 和 MU_JUDGE），那是 mu 自己的，magpie 不碰。

切回

magpie 第一次写入前会记下 settings.json 和 models.json 原来的样子。切回时，如果这两个文件之后没被改过，就逐字节放回原样。

终端
magpie mu default

常见问题

mu 能用 DeepSeek、GLM 或 ChatGPT 订阅吗？

能。在 magpie 的 Agent 页给 mu 选一个 via magpie 的模型，magpie 会写好 ~/.mu/agent 里的 settings.json 和 models.json。

接入 magpie 后还要跑 mu setup 吗？

不用。mu 只在 models.json 没有供应商、settings.json 没有 defaultProvider 时才要求 mu setup，magpie 已经写好了这两项。

mu 和 Pi 的用量会混在一起吗？

不会。两者的请求都写 pi/ 的 User-Agent，所以 magpie 给 mu 一个单独的 Key（magpie-mu），用量算在 mu 名下。

mu 的判断模型会被改吗？

不会。mu.json 和 MU_JUDGE 是 mu 自己的设置，magpie 不碰。
