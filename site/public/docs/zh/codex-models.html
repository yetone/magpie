Codex 接入其他模型

文档 · 指南

Codex 接入 DeepSeek、Kimi、GLM、Claude 等第三方模型

Codex 只会说一种协议：OpenAI Responses。magpie 在你电脑上跑一个本地网关，替你添加的每个供应商说这种协议，并替你写好 Codex 的 config.toml。之后这些模型会出现在 Codex 的 /model 里，带着各自的推理强度。

网关地址是 127.0.0.1:3425。DeepSeek 和智谱 GLM Coding Plan 本身提供 Responses 接口，Codex 的请求会原样转发；Kimi、MiniMax、通义千问只提供 Chat Completions 或 Anthropic 接口，Claude 订阅也一样，这些由 magpie 双向转换请求和回复，流式输出和工具调用都包括在内。

国产模型

DeepSeek、Kimi 与 Kimi Code、智谱 GLM（按量付费或 Coding Plan）、Z.ai、MiniMax、通义千问，有国内节点的都单独列出。

Claude

你的 Claude 订阅里的模型，或者 Anthropic API Key。

其他

任何 OpenAI 或 Anthropic 兼容的地址和 Key，Copilot、Antigravity 账号，以及 Ollama、LM Studio。

接入步骤

  1. 添加供应商在 magpie 的 供应商 页点 ＋ 添加供应商，选 DeepSeek、Kimi、智谱 GLM、MiniMax 或通义千问，粘贴 API Key 保存。magpie 会去问供应商有哪些模型。
  2. 给 Codex 选模型在 Agent 页点 Codex 那一行的模型，选一个，比如 deepseek/deepseek-v4-pro。列表下方的滑块设置推理强度。magpie 会把两者都写进 ~/.codex/config.toml。
  3. 重启 CodexCodex 启动时生成模型列表。切换后重启 Codex 应用，并新开 codex 会话。

命令行也一样：

终端
magpie provider add deepseek sk-…
magpie models                        # 列出所有模型，格式为 provider/model
magpie codex deepseek/deepseek-v4-pro
magpie codex effort high
智谱 GLM Coding Plan。添加智谱 GLM 或 Z.ai 时，选你的 Key 对应的套餐。Coding Plan 的 Key 有自己的接口地址，发到按量付费的接口会提示余额不足。

Codex /model 里的模型

magpie 的模型会和 Codex 自带的模型一起列在 /model 里，可以直接在里面切。每个模型都带着 Codex 运行它所需的信息：支持的推理强度和默认强度、上下文窗口，以及 Codex 随它发送的基础指令。

具体怎么出现，取决于 Codex 的登录方式：

  • 登录了 ChatGPT。Codex 保留自己的 OpenAI 供应商和登录。magpie 只用 openai_base_url 把它指向网关；Codex 自带的模型仍然用你的账号发给 OpenAI，magpie 的模型加在旁边。
  • 没登录，或用 API Key 登录。magpie 成为 Codex 的供应商，模型列表来自 magpie 写的目录文件 magpie-models.json，和 config.toml 放在一起。

config.toml 里改了什么

magpie 只改 ~/.codex/config.toml 里它需要的键，注释、顺序和你的其他设置都保留。

键写入的值
model你选的模型
model_reasoning_effort推理强度（设置了才写）
openai_base_url网关地址。你自己设的地址保持不变
model_providermagpie 作为供应商时为 "magpie"
model_catalog_jsonmagpie 作为供应商时，目录文件 magpie-models.json 的路径
[model_providers.magpie]name、base_url（网关的 /v1）、wire_api = "responses" 和网关的 Key。你的供应商 Key 留在 magpie 里
~/.codex/config.toml
model = "deepseek/deepseek-v4-pro"
model_provider = "magpie"
model_catalog_json = "/Users/you/.codex/magpie-models.json"

[model_providers.magpie]
name = "magpie"
base_url = "http://127.0.0.1:3425/v1"
wire_api = "responses"

这是 magpie 作为供应商时的样子，表里还有网关的 Key 和一个请求头。登录了 ChatGPT 时，顶层只设 openai_base_url 和 model。[model_providers.magpie] 表写入后会一直保留：Codex 的会话记着它开始时用的供应商，在 magpie 上开始的会话没有这个表就打不开。

切回 OpenAI 自己的模型

在那一行选 Codex 自己的模型，或者运行 magpie codex default。magpie 去掉 model_provider、model_catalog_json 和网关地址，恢复你原来的供应商和模型。你自己在顶层设的供应商保持不变。在 magpie 上开始的会话会移回 Codex 当前的供应商下，Codex 才列得出来；magpie 的回收站里留一份副本。

在 Codex 里用 Claude

在 magpie 里登录 Claude 订阅：＋ 添加供应商，选 Claude。它的模型以 claude/… 出现在 Codex 的模型列表里。magpie 把 Codex 的 Responses 请求转成 Anthropic Messages，再把回复转回来。

终端
magpie accounts add claude     # 登录一个 Claude 账号
magpie models | grep '^claude/'
magpie codex claude/…

Claude 订阅的请求通过你电脑上安装的 Claude Code 发出，所以要保留 Claude Code。Anthropic API Key 也可以：添加 Anthropic 供应商，选 anthropic/… 模型。

多个 Key 轮换

  • 同一家的多个 Key。都加到这个供应商里并勾选。供应商的 路由 决定怎么分摊，备用 列出额度用完或服务挂掉时改用的模型。
  • 同一个模型来自多个供应商。magpie 会自动建一个组 auto/<model>，给 Codex 选它即可。
  • 自己建组。在 路由 页新建一个组，把任意模型放在一个名字下，group/<id>。

各种路由方式见 快速上手。

常见问题

需要自己写 [model_providers] 吗？

不需要。选模型时 magpie 会写好 Codex 的 config.toml，也不用导出 OPENAI_BASE_URL。

ChatGPT 登录还能用吗？

能。登录了 ChatGPT 时，Codex 保留自己的供应商和登录，自带的模型仍然用你的账号发给 OpenAI，magpie 的模型加在旁边。

选了模型，Codex 的 /model 里却没有？

Codex 启动时读取模型列表。重启 Codex 应用，新开一个 codex 会话。

能设置推理强度吗？

能。在 Codex 那一行的滑块上调，或者运行 magpie codex effort high，也可以在 Codex 的 /model 里选，它会列出每个模型支持的强度。

Codex 能用哪些国产模型？

你添加的供应商有的都能用。magpie 内置了 DeepSeek、Kimi、Kimi Code、智谱 GLM、Z.ai、MiniMax、通义千问的预设。其他的可以用自定义地址添加。

magpie 必须一直开着吗？

Codex 用的是经过 magpie 的模型时，需要：网关跟着应用运行。magpie daemon install 可以把它装成后台服务，不开窗口。

怎么撤销？

在 magpie 里选 Codex 自己的模型，或者运行 magpie codex default。magpie 写的键会去掉，你原来的供应商和模型会恢复。
