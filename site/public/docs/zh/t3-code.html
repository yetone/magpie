文档 · 指南

让 T3 Code 用任意模型

T3 Code（pingdotgg/t3code）是一个图形界面，驱动 Claude Code、Codex、Cursor 等 Agent。它的每个供应商都是某个驱动的“实例”，也接受你自己加的实例。magpie 加两个实例：在 Claude Code 上运行的 magpie，和在 Codex 上运行的 magpie · Codex。于是 T3 Code 的模型选择器里能选你在 magpie 里的任何模型：DeepSeek、GLM、Kimi、Qwen、OpenAI 或 Anthropic Key，或 ChatGPT、Copilot 订阅，并且可以自己决定用哪个 harness 跑。

接入 T3 Code

  1. 在 magpie 里添加供应商在 供应商 页添加 API Key，或登录一个订阅。
  2. 在 T3 Code 那一行选 magpie在 Agent 页选 magpie。magpie 把两个实例写进 T3 Code 的 settings.json。
  3. 在 T3 Code 里选模型T3 Code 的服务监视这个文件，外部修改后自动重新加载。在模型选择器里，magpie 下的模型在 Claude Code 上跑，magpie · Codex 下的在 Codex 上跑。
终端
magpie t3code provider magpie

设置文件是 ~/.t3/userdata/settings.json（设了 T3CODE_HOME 时是 $T3CODE_HOME/userdata）。magpie 写入的是这两个实例：

终端
"providerInstances": {
  "magpie": {"driver": "claudeAgent", "displayName": "magpie",
    "environment": [{"name": "ANTHROPIC_BASE_URL", "value": "http://127.0.0.1:3425", …}, …],
    "config": {"customModels": [{"slug": "deepseek/deepseek-v4-pro", "name": …,
      "capabilities": {"optionDescriptors": […]}}, …]}},
  "magpie-codex": {"driver": "codex", "displayName": "magpie · Codex",
    "config": {"launchArgs": […]}}
}

magpie：在 Claude Code 上

magpie 实例是一个 claudeAgent 实例：T3 Code 用 Anthropic 的 Agent SDK 运行 Claude Code，读取你的 ~/.claude 设置，再加上实例的环境变量。magpie 在这里设 ANTHROPIC_BASE_URL 指向网关，以及 Claude Code 走 magpie 时用的 token，所以这些请求就是 Claude Code 发给网关的请求。每个 magpie 模型都是它的一个自定义模型，上下文为 1M 的模型标上 [1m]，和 magpie 给 Claude Code 的标法一样。如果你给 T3 自带的 Claude 设过可执行文件路径或 Claude 主目录，magpie 实例沿用它们，跑的是同一个 Claude Code。

magpie · Codex：在 Codex 上

T3 Code 用模型所属实例的 harness 运行线程。只有 Claude Code 实例时，所有 magpie 模型都只能在 Claude Code 上跑，所以 magpie 还加了一个 codex 实例 magpie · Codex。它的 launchArgs 是 Codex 自己的 -c 覆盖参数，T3 会传给 codex app-server 和 codex exec：把 magpie 设为模型供应商，并把 settings.json 旁边的 magpie-codex-models.json 设为模型目录，于是 T3 从 Codex 的模型列表里列出每个 magpie 模型。你的 ~/.codex/config.toml 不会被改，T3 自带的 Codex 也照旧。如果你在 T3 里删了这个实例，同步不会把它加回来，只有在 magpie 里重新打开 T3 Code 那一行才会。

思考强度

没有能力描述时，T3 Code 不显示任何选项，也不发思考强度。所以 magpie 给每个自定义模型加上 Reasoning 选择，列出这个模型支持的 Claude Code 强度，默认 medium（没有 medium 就用最低的），T3 把选中的强度原样交给 Claude Code。会思考的模型还有一个 Thinking 开关，默认打开；T3 用它设置 Claude Code 的 alwaysThinkingEnabled，关掉时请求不带思考。

你自己的设置

两个实例的名字、是否启用，以及 magpie 不写的键（如 autoCompactWindow、accentColor）都归你，你在 T3 Code 里改过的不会被改回去。magpie 实例上你自己加的环境变量也保留。你自己的实例、它们的自定义模型和 T3 的其他设置都不受影响。属于 magpie 的只有：自定义模型、网关的环境变量，以及 Codex 实例的启动参数和模型目录。

Claude Code 自己的路由

~/.claude/settings.json 里的 env 会覆盖进程的环境变量。所以如果你的 Claude Code 在自己的设置里路由到了别处，magpie 实例的请求也会去那里；路由到 magpie 或没有路由的，请求发到网关。如果那里开了 CLAUDE_CODE_USE_BEDROCK 这类云厂商开关，请求会去那个云，magpie 的检查会提示这一点。

切回

在 magpie 里把那一行取消，magpie 只拿掉它自己的两个实例，你的其他实例和设置不变。

终端
magpie t3code default

常见问题

T3 Code 能用 DeepSeek、GLM、Kimi 或 Qwen 吗？

能。magpie 在 T3 Code 的 settings.json 里加两个供应商实例，你在 magpie 里的所有模型都在 T3 的模型选择器里，可以选在 Claude Code 还是 Codex 上运行。

magpie 和 magpie · Codex 有什么区别？

模型一样，harness 不同：magpie 下的模型在 Claude Code 上运行，magpie · Codex 下的在 Codex 上运行。

会改我的 ~/.codex/config.toml 或 T3 自带的 Claude、Codex 吗？

不会。Codex 的设置以启动参数的形式只用在 magpie · Codex 实例上，T3 自带的实例和你的其他实例都不变。

为什么请求没走 magpie？

检查 ~/.claude/settings.json 的 env：如果 Claude Code 在那里路由到别处，或开了 Bedrock 等云厂商开关，magpie 实例的请求会去那里。

更多 Agent 用同样的模型：Claude Code 接入其他模型、Codex 接入其他模型、让 CodeBuddy 用任意模型、让 Craft Agents 用任意模型。遇到报错？见 常见错误排查，或到 Discord 提问。
