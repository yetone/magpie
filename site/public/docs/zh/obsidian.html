文档 · 指南

让 Obsidian 用任意模型

Obsidian 本身没有 AI，AI 功能来自社区插件。magpie 接入的是 Copilot for Obsidian（logancyang/obsidian-copilot），它接受自定义的 OpenAI 兼容地址。magpie 在每个装了 Copilot 的仓库里加一个名为 magpie 的供应商，于是 Obsidian 里的 AI 对话能用你在 magpie 里的任何模型：DeepSeek、GLM、Kimi、Qwen、OpenAI 或 Anthropic Key，或 ChatGPT、Copilot 订阅。

接入 Obsidian

  1. 在 Obsidian 里安装 Copilot在 Obsidian 的 设置 › 第三方插件 里安装并启用 Copilot。magpie 只在有仓库装了 Copilot 时才显示 Obsidian 这一行。
  2. 在 magpie 里添加供应商在 供应商 页添加 API Key，或登录一个订阅。
  3. 在 Obsidian 那一行选 magpie在 Agent 页选 magpie。然后在 Obsidian 里重新加载 Copilot，magpie 的模型就在它的模型菜单里。
终端
magpie obsidian provider magpie

仓库

Obsidian 把仓库列表记在配置目录的 obsidian.json 里：macOS 是 ~/Library/Application Support/obsidian，Windows 是 %APPDATA%\obsidian，Linux 是 $XDG_CONFIG_HOME/obsidian，Flatpak 和 Snap 版用它们自己的配置目录。Copilot 的设置在每个仓库的 .obsidian/plugins/copilot/data.json 里。magpie 接入每个装了 Copilot 的仓库；之后只更新已经接入的仓库，不会去动你没让它接入的仓库。

模型列表

magpie 写进 data.json 的内容如下，只改这几个键，文件里其他设置原样保留：

终端
"providers": {"magpie": {
  "providerType": "openai-compatible", "displayName": "magpie",
  "baseUrl": "http://127.0.0.1:3425/agent/obsidian/v1",
  "requiresApiKey": false, …}},
"configuredModels": [{"providerId": "magpie", "info": {"id": "deepseek/deepseek-v4-pro", …}}, …],
"backends": {"chat": {"enabledModels": […]}},
"defaultModelKey": "…"

每个模型带上 magpie 模型目录里的上下文长度、输出上限、是否支持图片和思考强度。新加到 magpie 的模型在对话里默认启用；你在 Copilot 里关掉的 magpie 模型保持关闭；从 magpie 删掉的模型从每个后端里一起拿掉。你自己在 Copilot 里加的模型和供应商不受影响。第一次接入时，Copilot 的默认模型换成 magpie 的第一个模型，原来的默认模型会记下来，切回时放回去。

不用填 Key

Copilot 的 API Key 存在 Obsidian 的钥匙串里，magpie 不往那里写。所以 magpie 的供应商设为不需要 Key（requiresApiKey: false），请求不带 Authorization，网关接受本机发来的无 Key 请求。Copilot 从 Obsidian 窗口里用 fetch 调用，回复会流式显示；网关也处理了这个窗口的 CORS。地址里的 /agent/obsidian 让 magpie 认出是 Obsidian，因为这个窗口的 User-Agent 和浏览器一样。

重新加载 Copilot

Obsidian 运行时，Copilot 把设置放在内存里，保存时会整个写回 data.json。所以接入之后，先在 设置 › 第三方插件 里重新加载 Copilot（或重启 Obsidian），再去改 Copilot 的设置，否则旧设置会把 magpie 写进去的内容盖掉。magpie 会在 Obsidian 运行时提示这一点。

Copilot 3

magpie 只写 Copilot 4 的格式（providers 和 configuredModels）。Copilot 3 把模型放在 activeModels 里，magpie 不会改这样的仓库，会在报错里指出它。把 Copilot 升级到 4，它第一次加载时会自己迁移设置。

切回

在 magpie 里把那一行取消。magpie 从每个仓库的 data.json 里拿掉它的供应商、模型以及它们在各个后端里的位置；如果默认模型还是 magpie 的，就放回你原来的默认模型。你自己手动加的名为 magpie 的供应商（地址不是 magpie 的 Obsidian 路由）不算 magpie 的，不会被拿掉。

终端
magpie obsidian default

常见问题

Obsidian 能用 DeepSeek、GLM、Kimi 或 Qwen 吗？

能，通过 Copilot for Obsidian 插件。magpie 在每个装了 Copilot 的仓库里加一个 magpie 供应商，你在 magpie 里的所有模型都在 Copilot 的模型菜单里。

需要在 Copilot 里填 API Key 吗？

不需要。magpie 的供应商设为不需要 Key，请求发到本机的 magpie 网关，由 magpie 用你的 Key 或订阅去请求模型。

为什么 Copilot 里看不到 magpie 的模型？

在 Obsidian 的设置 › 第三方插件里重新加载 Copilot，或重启 Obsidian。如果仓库用的是 Copilot 3，先升级到 Copilot 4。

Smart Connections 能接入吗？

不能。它的免费版只用本地模型做嵌入，接 API 供应商的功能在闭源的 Pro 插件里，Key 存在钥匙串中，magpie 写不进去。

更多 Agent 用同样的模型：Raycast、Cherry Studio、让 CodeBuddy 用任意模型。遇到报错？见 常见错误排查，或到 Discord 提问。
