MCP 路由

你在 magpie 资源库 里添加的 MCP 服务器，平时会写进每个 Agent 自己的配置，一个服务器一条。打开 MCP 路由 后，每个 Agent 只拿到一个名为 magpie 的服务器，magpie 再把每次调用转给后面对应的资源库服务器。默认关闭。

  • 配一次。资源库里写好一次的服务器，通过一个条目给所有 Agent 和应用使用。
  • 只运行一份。命令型服务器（以程序启动的，比如 npx …）在 magpie 里只运行一份，而不是每个 Agent 各起一份。10 分钟没有调用的服务器会被停掉，下次调用时再启动。
  • 其他应用一个地址。Cursor、VS Code、Windsurf 或另一台电脑上的应用，连上 magpie 就能用资源库里的所有服务器。

工具在 Agent 里显示为 服务器__工具。只提供工具（不含 resources 和 prompts），在资源库里关掉的工具既不会列出也不会运行。

打开

  1. 打开页面进入 资源库 → MCP。
  2. 打开开关在服务器列表下方打开 MCP 路由。每个勾选了资源库服务器、且能通过 HTTP（Streamable HTTP）连接服务器的 Agent，会得到一个 magpie 条目，地址是 magpie 网关上的 /mcp/magpie/hub/<agent>，那些服务器原来的条目会从它的配置里移除。
  3. 重启 AgentAgent 重新启动后才会读到改动。

关闭后，每个服务器自己的条目会写回去，只移除 magpie 写入的那个 magpie 条目，MCP 路由启动的服务器也会全部停掉。命令行：

终端 
magpie library mcp router on
magpie library mcp router off

magpie library 会列出哪些 Agent 用上了 MCP 路由、哪些保留各自的条目，以及原因。

其他应用

MCP 路由打开后，其他应用 一行显示一个以 /mcp/magpie/hub 结尾的地址，它提供资源库里的所有服务器。连接… 会打开一个面板，里面有给 Cursor、VS Code、Windsurf 或任何接受 JSON MCP 配置的应用准备好的条目，可直接复制；在应用窗口里，Cursor 和 VS Code 还有 添加，会打开对应应用让你确认。另一台电脑上的应用需要网关密钥，和局域网里的其他请求一样（见 远程 magpie）。

命令型服务器运行在这台电脑上。局域网里持有网关密钥的人都能通过 MCP 路由调用它们，权限就是你在这台电脑上的权限。密钥只给信任的人。

保留各自条目的 Agent

以下 Agent 会保留每个服务器自己的条目，资源库页面会写明是哪些、为什么：

  • 不支持远程服务器。Agent 不能通过 HTTP 连接 MCP 服务器，比如 Claude Desktop。
  • 有服务器叫 magpie。你资源库里有个服务器本身就叫 magpie，名字会冲突。
  • 自己有 magpie 条目。Agent 已经有一个不是 magpie 写入的 magpie 条目，会原样保留。

什么时候用

  • 适合打开：多个 Agent 用同一批服务器；命令型服务器被每个 Agent 各起一份；想让编辑器或其他电脑也用你的资源库。
  • 可以不开：只用一个 Agent；希望每个 Agent 直接连自己的服务器；不想让局域网里的其他人碰到你的命令型服务器。所有调用都经过 magpie，所以 magpie 需要在运行。
