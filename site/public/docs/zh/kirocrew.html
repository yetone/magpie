让 Kiro Crew 用任意模型

Kiro Crew（kirodotdev/KiroCrew）是一个常驻的 Agent，有 KiroCrew.app 桌面应用、kirocrew 命令行、网页面板和它们共用的 Gateway。它把每个会话交给一个 harness 运行，也就是它启动并通过 ACP 对话的另一个 Agent。Kiro Crew 自己没有可以指向 magpie 的模型供应商，模型都是 harness 的。所以 magpie 设置的是它用哪个 harness：一个已经接入 magpie 的 Agent，它自己的配置会把请求发到 magpie 网关，于是 DeepSeek、GLM、Kimi、Qwen、Claude 或 ChatGPT 订阅等 magpie 里的模型都能用。

接入 Kiro Crew

  1. 在 magpie 里添加供应商在 供应商 页添加 API Key，或登录一个订阅。
  2. 在 Agent 页把 Kiro Crew 的供应商设为 magpieKiro Crew 已经设成 magpie 支持的 harness 时，magpie 保留这个 harness，它还没接入 magpie 的话就一并接入。设成 magpie 不接管的 harness（KAS、kiro-cli、deepseek）时，magpie 选第一个已接入 magpie 的 harness，优先选本机有适配器的。
  3. 在 Kiro Crew 里开一个新会话Gateway 会在文件变化时重新读取，新会话用新的 harness，已经打开的会话保留原来的。

想换 harness，可以在 Kiro Crew 那一行的 harness 里选另一个已接入 magpie 的 Agent。一个都没接入时，magpie 会提示先把 Codex、Claude Code、OpenCode、Pi 或 Goose 接入 magpie，再接入 Kiro Crew。

可选的 harness

magpie 提供的是它自己接管的 harness，这些 harness 在 Kiro Crew 下面读的也是同样的文件：

  • Codex：通过 codex-acp 适配器（npm 包 @agentclientprotocol/codex-acp），读 ~/.codex 或 $CODEX_HOME
  • Claude Code：通过 claude-agent-acp 适配器（npm 包 @agentclientprotocol/claude-agent-acp），运行你的 claude，读 ~/.claude
  • OpenCode：opencode acp
  • Pi：通过 pi-acp 适配器（npm 包 pi-acp）
  • Goose：goose acp

不包括 deepseek：Kiro Crew 用 dsh --profile acp 运行它，这是 Kiro Crew 自己的 profile，magpie 对 dsh 的接入管不到。

config.json

Kiro Crew 的设置是它主目录里的 config.json。主目录在设置了 $KIROCREW_HOME 时是那里（会转成绝对路径；根目录、/usr、/System 和 /etc 会被拒绝，改用默认值），否则是 ~/.kiro/crew，桌面应用也用这里。magpie 写两个键：

终端
// ~/.kiro/crew/config.json
{
  "agent": {
    "acp_backend": "codex",
    "member_acp_backend": "codex"
  },
  …
}

acp_backend 是会话的 harness，留空就是默认的 kiro-cli。member_acp_backend 是 crew 成员的 harness，默认是 kas，只有能派发成员的 harness（Codex、Claude Code、OpenCode、Goose）才写这个键，Pi 不写。magpie 记下这两个键原来的值，切回时放回去。

ACP 适配器

Codex、Claude Code 和 Pi 要通过 Kiro Crew 不自带的 npm 适配器运行。magpie 在 Kiro Crew 会找的地方找它：适配器变量（CODEX_ACP_BIN、CLAUDE_AGENT_ACP_BIN、PI_ACP_BIN）指向的路径、PATH、~/.local/bin、npm、mise、Volta 和 Homebrew 的目录，以及 mise、asdf、nvm 和 fnm 管理的每个 Node 版本。找不到时，Agent 页会提示用 npm i -g 安装对应的包，然后开一个新会话。magpie 自己什么也不装。

config.local.json 归你

同目录的 config.local.json 会逐键覆盖 config.json，而且优先。如果你在那里设置了 harness（agent.acp_backend），magpie 一个键也不写，会提示你在那里改成已接入 magpie 的 harness，或者删掉它再接入。

切回

在 magpie 里关掉 Kiro Crew 时，magpie 把两个键放回原来的值；你之后自己改过的键保持你的设置。如果当初是这次接入顺便把 harness 那个 Agent 接入了 magpie，而你之后没有自己断开过它，magpie 也会把它断开；否则它保持接入。

常见问题

Kiro Crew 能用 DeepSeek 或 GLM 吗？

能。Kiro Crew 的模型来自它的 harness，magpie 把 harness 设为已接入 magpie 的 Codex、Claude Code、OpenCode、Pi 或 Goose，在 harness 里选模型即可。

为什么已经打开的会话没有变？

已经打开的会话保留原来的 harness，新的 harness 只对新会话生效。

提示找不到 codex-acp 怎么办？

Codex、Claude Code 和 Pi 要通过 npm 适配器运行，按提示用 npm i -g 安装对应的包，再开一个新会话。

为什么 magpie 没有改我的 harness？

你在 config.local.json 里设置了 agent.acp_backend，它优先于 config.json，magpie 不会覆盖你的设置。
