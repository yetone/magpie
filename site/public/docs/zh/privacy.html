隐私

你的提示词、回复、密钥和账号只发给你用的供应商，中间没有 magpie 自己的服务器。这一页列出 magpie 在这些请求之外自己发出的所有内容，以及关掉它们的每个开关。内容按代码写成，每一节都附了代码链接。

内容发往默认怎么关
每日计数PostHog（us.i.posthog.com）正式版开启；源码构建从不发送设置 → 隐私，DO_NOT_TRACK=1
更新检查、更新说明、合作伙伴列表、图标usemagpie.ai开启更新检查用 noAutoUpdate；其余是应用运行所需
模型目录和汇率models.dev、open.er-api.com开启不可关；不发送任何你的信息
OTLP 导出你指定的收集器关闭保持关闭即可

每日计数

正在运行的正式版 magpie（应用或 magpie serve）每天（UTC）向 PostHog 发送一批事件，好让我们知道有多少人在用、该先照顾哪些 agent、供应商和模型。启动时发送，之后每小时看一次，当天已发过就跳过。从源码构建的版本从不发送。

这批事件里有一个 magpie active，包含：

  • 本机随机生成的 ID（32 位十六进制，与你和这台电脑无关），作为 distinct_id；
  • magpie 版本、kind（app 或 serve）、系统（$os）和架构；
  • 用了几个 agent、供应商和模型，以及几个路由组（关掉“分享我用的”后不发送）。

除非你关掉这一部分，后面还有每个 agent、供应商和模型各一个 magpie uses 事件，只用 magpie 自己的 ID（每类最多 50 个）：

  • agent：接入 magpie 的 agent，如 claude、codex。WSL 发行版名和 omp 配置名会去掉（只记 omp）。
  • 供应商：开启的供应商。预设的 ID（deepseek）、订阅的（codex、copilot）、已知社区插件的（plugin:kiro）。你自己添加的供应商只记作 custom，其他插件只记作 plugin。
  • 模型：接入的 agent 设定的模型，记为供应商 ID 加厂商模型 ID（deepseek/deepseek-v4）。密钥类供应商上 models.dev 没收录的模型 ID（本地模型、微调模型）只记作 <供应商>/other；你自己供应商上的模型记作 custom；路由组记作 group。

同时发送 magpie partner 事件：添加供应商页里排在最前的每个合作伙伴，按它的 ID，在已结束的某一天里被展示、行被打开、Key 页面被打开、从它添加供应商的次数（what：shown、opened、keys、added；每天每项最多 20 次，添加最多 5 次）。只有次数，从不包含你自己的供应商。

每个事件都带 $process_person_profile: false，PostHog 不为这个 ID 建用户档案。不发送名称、Base URL、账号、密钥、提示词、回复和用量。一整批大致如下：

POST https://us.i.posthog.com/batch/ 
{
  "api_key": "phc_nyDyYyrUTRGvNq5U7FBesCyM2j4GdKeqGp8ko7DBerTC",
  "batch": [
    {
      "event": "magpie active",
      "distinct_id": "3f9c…(32 hex)",
      "timestamp": "2026-10-13T08:00:00Z",
      "properties": {
        "version": "0.1.1190", "kind": "app", "$os": "Mac OS X", "arch": "arm64",
        "agents": 2, "providers": 3, "models": 2, "groups": 1,
        "$process_person_profile": false, "distinct_id": "3f9c…"
      }
    },
    { "event": "magpie uses", "distinct_id": "3f9c…", "timestamp": "2026-10-13T08:00:00Z",
      "properties": { "kind": "agent", "id": "claude", "$process_person_profile": false, "distinct_id": "3f9c…" } },
    { "event": "magpie uses", "properties": { "kind": "provider", "id": "custom", … } },
    { "event": "magpie uses", "properties": { "kind": "model", "id": "deepseek/deepseek-v4", … } },
    { "event": "magpie partner", "timestamp": "2026-10-12T12:00:00Z",

关闭

下面每个开关关掉其中一部分或全部：

  • 关掉 设置 → 隐私 → 计入用户数，或在 settings.json 里写 "noStats": true：整个每日计数。
  • 在 magpie 的环境变量里设 DO_NOT_TRACK=1 或 MAGPIE_NO_STATS=1（除空、0、false 之外的任何值）：整个每日计数，不管设置里怎么选。
  • 关掉 设置 → 隐私 → 分享我用的 agent、provider 和模型，或 "noUsageStats": true：magpie uses、magpie partner 事件和 magpie active 里的数量；ID、版本和系统仍会发送。合作伙伴次数也不再记录。
  • 关掉 设置 → 关于 → 自动更新，或 "noAutoUpdate": true：magpie 自己向 usemagpie.ai 询问新版本（否则每 6 小时一次）。这不属于计数。

设置里的改动在下一次每小时检查时生效，不用重启。settings.json 在 magpie 的文件夹里（见下文）：

settings.json 
{
  "noStats": true,
  "noUsageStats": true,
  "noAutoUpdate": true
}

MAGPIE_STATS_HOST 会把计数发到另一个主机（用于测试，设置后源码构建也会发送）。

本机上的文件

文件用途
install-id随机 ID，第一次发送计数时生成
stats-sent上次发送的日期（UTC），保证每天只发一次
partner-counts.json（缓存文件夹）还没发送的合作伙伴次数，最多保留 14 天

install-id 和 stats-sent 在 magpie 的文件夹里：macOS 和 Linux 上是 ~/.config/magpie，Windows 上是 %USERPROFILE%\.config\magpie，设置了 $XDG_CONFIG_HOME 时是 $XDG_CONFIG_HOME/magpie，便携版则在它的数据文件夹里。partner-counts.json 在 ~/.cache/magpie（或 $XDG_CACHE_HOME/magpie，便携版数据文件夹里的 cache）。这些文件都可以删：删掉 install-id 后，下次发送会生成新的随机 ID，你会被算作新用户；关掉计数后，它们都不会再写入。

请求存档（用量页请求列表上方的请求存档开关）默认关闭。同步没有 S3 存储桶时打开它，每次经过网关的调用的请求头和正文会存到 magpie 文件夹里的 request-archive，一次调用一个文件，只有你的用户能读，密钥按 S3 存档同样的方式遮掉。它最多占 1 GiB（settings.json 里的 requestArchiveLocalMB），超过后先删最早的调用。这个开关只属于这台电脑，同步不会在别的电脑上把它打开。有 S3 存储桶时调用存到桶里，这里不写任何东西。这个文件夹随时可以删。

应用会把它做了什么写进日志 app.log：macOS 上在 ~/Library/Logs/magpie，Windows 上在 %LOCALAPPDATA%\magpie\logs，Linux 上在 ~/.local/state/magpie（见 magpie 的日志在哪里？），只有你的用户能读。它记下 magpie 做了什么和遇到的错误，从不记密钥、提示词或回复，除非你发出去，否则只留在你的电脑上。它最多 5 MiB，另留一个更早的 app.old.log。随时可以删。

usemagpie.ai 能看到什么

magpie 会向自己的网站请求几样东西，不受隐私设置影响，就像任何应用访问自己的更新服务器。这些请求都不带安装 ID 或账号。

  • /api/latest：更新信息，每 6 小时一次（开了 noAutoUpdate 则不请求），带 ?lang= 取对应语言的说明；设置 → 关于 → 更新渠道选了稳定版时还带 ?channel=stable。两者都不含你是谁。/api/notes 在更新后给出“新功能”。
  • /files/<版本>/<文件>：更新和安装脚本下载的发布文件，由 Cloudflare R2 提供；站点上没有的文件会转到 github.com。不做任何统计。
  • /api/partners：添加供应商页的合作伙伴列表，每 6 小时一次。在有合作伙伴上架时，每十次拉取记一次 magpie partners fetch 事件，附 Cloudflare 给出的国家。
  • /go/<合作伙伴>/site 和 /go/<合作伙伴>/keys：在浏览器里打开合作伙伴的官网和 Key 页面链接时，先记一次 magpie partner go（哪个合作伙伴、哪个链接、地区、国家），再跳转。
  • /api/icon?url=…：插件、导入链接和库里的图标经它获取，图标所在的服务器只看到 Cloudflare 的地址，看不到你的。它只转发图片，不计数也不记录。

网站自己的页面（这些文档、首页）带 Cloudflare Web Analytics 和 PostHog Web Analytics（us.i.posthog.com），都不用 Cookie。PostHog 在浏览器的本地存储里为本站记一个随机访客 id，再次访问算同一位访客。它收到每个页面的地址、来源页面、你在页面上点了什么（不含输入的内容）、页面及其请求的加载速度、页面遇到的报错、浏览器、系统和屏幕尺寸、IP 所在的国家和城市，以及这次访问的录屏（页面显示的内容、鼠标移动、点击、滚动和控制台消息），所有输入框都被遮住；浏览器开了 Do Not Track 或 Global Privacy Control 就什么都不发。PostHog 的请求经由本站的 usemagpie.ai/r/ 转给 PostHog，连同你的 IP 一起转发，本站的 Cookie 不转发。打开 /download 下载链接或获取 install.sh 时，会另外向 PostHog 发一次计数：哪个文件、你所在的国家、是浏览器还是命令发起的；不带 id，也不带 IP。应用两者都不加载。代码见 site/worker.js。

magpie 拉取的公开列表

为了给模型定价和命名，magpie 会拉取 models.dev 的模型目录（models.dev/api.json）；为了用你的货币显示价格，会从 open.er-api.com 拉取美元汇率（缓存 12 小时）。插件及其更新来自 npm 仓库，库里的内容来自 GitHub。这些都是公开数据的普通下载，不发送任何关于你、你的供应商或用量的信息；和任何请求一样，这些主机能看到你的 IP（或代理的 IP）。magpie 还会用你自己的密钥或登录向各个供应商读取额度和模型列表；设置 → 额度 → 额度刷新 → 仅手动 可以只在你要求时才读。

OTLP 导出

magpie 可以把每个网关请求导出到你自己的 OpenTelemetry 收集器（比如 Langfuse）。它默认关闭，只发到你设置的地址，从不发给我们。开启后发送每个请求的 span：agent、供应商、模型、token 数、状态、耗时和估算费用。另有开关可以加上指标、本地 agent 对话，以及请求和回复正文（密钥已遮盖）。在 设置 → 可观测性 里开启，magpie serve 也可以用 MAGPIE_OTEL_ENABLED、MAGPIE_OTEL_ENDPOINT、MAGPIE_OTEL_HEADERS、MAGPIE_OTEL_METRICS、MAGPIE_OTEL_SESSIONS、MAGPIE_OTEL_BODIES 和 MAGPIE_OTEL_BODIES_WHOLE。只设地址不会开启导出。用 Langfuse 的话，在那里选 Langfuse，填上地址和项目的两个密钥，magpie 会据此生成地址和认证头。每次导出的 resource 是 service.name=magpie，再加上你自己在 OTEL_RESOURCE_ATTRIBUTES 和 OTEL_SERVICE_NAME 里设置的值（比如服务器名），不会读取你机器上的任何信息。细节见参考文档。

发给供应商的内容脱敏

上面几节讲的是 magpie 自己发出的东西。你的 Agent 发出的内容会去往你选的供应商，隐私脱敏让其中的密钥留在这台电脑上。它默认关闭，在 设置 → 隐私 里打开。

  • 请求离开这台电脑前，API key、私钥、token、邮箱，以及校验位对得上的银行卡号和证件号，会换成 {{API_KEY_k3v9x2mq}} 这样的占位符。打开 用本地模型查找，还会用一个在这台电脑上运行的模型找出规则找不到的人名、地址和密码（下载 1.6 GB，用 CPU 跑）。
  • 回复里的每个占位符，包括流式文本和工具调用参数里的，都会换回原值，所以 Agent 和你的文件里始终是真值。
  • 同一个值每次的占位符都一样，对话上下文和提示词缓存都不受影响。
  • 原值只在内存里；磁盘上的记录只留每个值的类型、长度和开头几个字符。脱敏打开却运行不了时，请求返回 503，什么都不发。
  • 模型看到的是占位符，不是值本身。任务需要原样使用的值（团队邮箱、测试用的 key）可以加进 从不脱敏。

怎么打开、每个开关遮掉什么、例子以及怎么确认生效，见 本地脱敏。

为什么计数默认开启

magpie 支持几十个 agent 和供应商，维护的人不多。每日计数让我们知道大家实际在用哪些，好先保证它们能用。正式版默认开启，是因为只靠主动开启的人，数量太少，看不出这些。作为交换，它尽量少：一个随机 ID、内置 ID 和数字；一个开关或 DO_NOT_TRACK=1 就能关掉，源码构建从不发送，发送的全部内容都列在这一页。
