Ollama 接入 Claude Code、Codex、Gemini CLI 和 OpenCode

Ollama 在 http://localhost:11434 上用两种接口提供你拉取的模型：OpenAI Chat Completions 和 Anthropic Messages。Ollama Cloud 在 ollama.com 上以同样的方式提供云端模型，需要 API Key。把其中任意一个添加到 magpie 一次，Claude Code、Codex、Gemini CLI、OpenCode 以及你接入的其他工具，就都能通过 magpie 的本地网关 127.0.0.1:3425 使用它们，每个工具各用各的模型。

添加 Ollama

  1. 拉取模型在 Ollama 里拉取一个模型，比如 qwen3，并保持服务运行。
  2. 添加供应商在 magpie 的 供应商 页点 ＋ 添加供应商，在 本机 下选 Ollama。不需要 Key。magpie 会向服务询问有哪些模型，它们显示为 ollama/…。
  3. 给工具选模型在 Agent 页点工具那一行的模型，选一个 Ollama 模型。
终端
ollama pull qwen3
magpie provider add ollama
magpie provider test ollama

magpie 里的模型 ID 写作 供应商/模型，所以拉取的 qwen3 就是 ollama/qwen3。标签也留在 ID 里，比如 ollama/qwen3:8b。在终端界面里添加时，magpie 会问你服务器地址。LM Studio、oMLX、vLLM 和 llama.cpp 的服务见 本地模型。

换端口或换电脑

如果 Ollama 监听的是别的端口，或者跑在另一台电脑上（比如 GPU 主机或 NAS），在供应商编辑页修改 服务器地址。只有协议、主机和端口会变，每个接口的路径保持不变。协议可以省略，默认按 http；地址后面带的路径（比如 /v1）会被去掉。

终端
magpie provider set ollama address=192.168.1.20:11434
magpie provider set ollama address=     # 恢复默认地址
  • 代理。局域网里的服务器会直接连接，不管设置或系统里指定了什么代理。给这个供应商单独设的代理仍然有效。
  • HTTPS。Ollama 放在自签名证书的 HTTPS 后面时，在编辑页打开 不校验它的证书 即可连上。它只对这个供应商自己的主机生效。

Ollama Cloud

  1. 创建 Key在 ollama.com/settings/keys 创建一个。
  2. 添加供应商在 供应商 页点 ＋ 添加供应商，选 Ollama Cloud，粘贴 Key 并保存。magpie 会向 Ollama Cloud 询问这个 Key 能用哪些模型。
  3. 给工具选模型在工具那一行选一个 Ollama Cloud 模型，比如 deepseek-v4-pro。
终端
magpie provider add ollama-cloud <key>
magpie claude ollama-cloud/deepseek-v4-pro

模型名称、推理档位和价格来自 models.dev 的 ollama-cloud 目录。Key 保存在 magpie 的设置里。

接口地址

供应商Chat CompletionsAnthropic Messages
Ollamahttp://localhost:11434/v1http://localhost:11434
Ollama Cloudhttps://ollama.com/v1https://ollama.com

工具说的接口 Ollama 本身就支持时，请求直接交给那个接口。两者在 magpie 里都没有 Responses 接口，所以需要翻译时，magpie 用 Chat Completions：只有 OpenAI 自家的模型优先用 Responses，只有 Claude 模型优先用 Messages。

模型列表

magpie 从 Chat Completions 的地址获取模型列表：http://localhost:11434/v1/models，Ollama Cloud 则是 https://ollama.com/v1/models。Ollama 里有了某个模型，magpie 里才会出现它。拉取新模型后，在供应商编辑页点 获取模型，或运行 magpie provider refresh ollama。工具能看到哪些模型，可以在供应商的模型列表里勾选，也可以在终端里设置：

终端
magpie provider refresh ollama
magpie provider models ollama +qwen3

Ollama 0.35.0 及以后的版本（云端模型要 0.40.5）还提供决策模型，比如 Nimble、Clef 和 Tev。magpie 也会读取 Ollama 的 /api/tags，其中标为决策模型的，会成为这个供应商用于 意图路由 的决策模型，不会作为工具的模型。更早的 Ollama 不会列出这类模型。

在各个工具里用

终端
magpie claude ollama/qwen3
magpie codex ollama/qwen3
magpie gemini model ollama/qwen3
magpie opencode ollama/qwen3
  • Claude Code 说的是 Anthropic Messages，Ollama 在 http://localhost:11434 也支持，所以请求原样发过去。见 Claude Code 接入其他模型。
  • Codex 说的是 OpenAI Responses，magpie 不会把它发给 Ollama，而是把每个请求转成 Chat Completions，再把回复转回来，流式输出和工具调用都包括在内。见 Codex 接入其他模型。
  • Gemini CLI 说的是 Google 的 Gemini 接口。magpie 把每个请求翻译成 Chat Completions，再把回复翻译回去。见 Gemini CLI 接入其他模型。
  • OpenCode 说的是 Chat Completions，请求原样发到 Ollama 的 /v1。见 OpenCode 接入其他模型。

在工具里面，Claude Code 和 Codex 的 /model 也会列出 magpie 的模型，可以在本地模型和云端模型之间切换。想换回工具自带的模型，运行 magpie claude default 或 magpie codex default。

上下文窗口与 num_ctx

工具会按模型能接受多长的请求来安排对话。Claude Code 把不认识的模型当作 200K，Codex 在被告知的窗口用到 90% 时压缩对话。magpie 不会读取 Ollama 聊天模型的窗口，所以要把真实的窗口告诉它：供应商编辑页 高级 里的 上下文窗口，可以给全部模型设，也可以单独给某个模型设。magpie 会告知各个工具。

终端
magpie provider set ollama context=32k
magpie provider set ollama context.qwen3=128k
  • num_ctx。有些客户端会在 Chat Completions 字段旁边带上 Ollama 的单次请求选项，比如 {"num_ctx": …}。magpie 转发任何请求前都会去掉它们：没有哪个 Chat Completions 接口会读它们，Ollama 自己的 /v1 也不读。模型实际用多大的窗口由 Ollama 决定，在 magpie 里填同一个数即可。
  • 超长。对话超出窗口时，Ollama 会回 “exceeded max context length”。magpie 用工具能理解的方式转告它，即 context_length_exceeded 或 Anthropic 的 “prompt is too long”，工具就会压缩后重试。

推理

  • 思考强度。工具要求的强度会对到模型已有档位里最接近的一档，档位以目录为准。magpie 不知道档位的模型，就按工具的原样请求。
  • 关闭推理。由 magpie 翻译请求的工具（比如 Codex、Gemini CLI）关闭推理，而模型的档位里有 none 时，magpie 会请求 none。
  • 自己定档位。magpie model efforts 可以只开放你指定的档位，或者完全不给模型发推理字段。
终端
magpie model efforts ollama/qwen3 low,medium,high
magpie model efforts ollama/qwen3 off

工具调用

Claude Code 和 OpenCode 的工具调用按工具写的原样到达 Ollama。Codex 和 Gemini CLI 的工具定义、模型发起的调用和调用结果，magpie 都会翻译成 Chat Completions 再翻译回来，流式回复也一样。

脱敏

magpie 的 本地脱敏 会在请求离开网关前把 Key、Token 等敏感信息换成占位符，发给本地 Ollama 的请求也一样。模型就跑在你自己的电脑或局域网里时，可以在编辑页打开 请求不脱敏，或运行 magpie provider set ollama unmasked=yes。

  • 云端模型。Ollama 的云端模型不管地址是什么，都会把请求转给厂商，所以这由你决定。给非本地的供应商（比如 Ollama Cloud）打开时，编辑页会提醒你。
  • 工具参数。Ollama 自己格式的请求里，工具调用的参数和其他接口一样，按工具参数脱敏。
  • 匿名统计。magpie 的每日统计只有在 models.dev 认识某个 Ollama 模型时才写出它的名字，其他一律记为 “other”。见 隐私。

用量与费用

  • 用量。用量 页会统计每次 Ollama 调用的 token。模型按 magpie 为它的 ID 找到的价格计价，本地模型可能用的是模型厂商的标价。想让本地模型不计费，给它设一个你自己的价格。
  • 免费优先。free=yes 让这个供应商的所有模型都算作免费，免费优先 的路由会先用它再用付费的。价格和用量页的费用仍按标价显示。
  • Ollama Cloud 的额度。magpie 会从 Ollama Cloud 读取账户余额。套餐内的额度显示为套餐，写明已用多少美元和何时重置；早期套餐则显示会话限额和每周限额。你购买的额度显示为余额。超出套餐额度后 Ollama Cloud 会扣购买的额度，所以套餐额度用完但还有余额时，Key 不会停用。
  • 高峰时段。在 Ollama Cloud 上，deepseek-v4.1-flash 和 deepseek-v4-pro（及其带标签的版本）在 UTC 时间周一至周五 12:00 到 18:00 按两倍计费。models.dev 列的是非高峰价格，用量页在这些时段会按两倍计算，最便宜优先 的路由也会算进去。
  • 额度用完。Ollama Cloud 说某个 Key 额度用完、却没说何时恢复时（比如每周限额），magpie 会让这个 Key 休息 15 分钟。quota-rest 可以设休息多久，最长 8 天。有多个 Key 时（添加另一个密钥）由下一个接替；所有 Key 都用完时，网关会立即带上 Retry-After 回复。
终端
magpie model price ollama/qwen3 0,0,0,0
magpie provider set ollama free=yes
magpie provider quota-rest ollama-cloud 7d
magpie provider fallback ollama-cloud ollama/qwen3

把 magpie 当作 Ollama 服务

有些应用只能以 Ollama 服务的形式接入自定义模型：VS Code Copilot 的 Ollama 供应商、Visual Studio Copilot 的 BYOK、Zed 的 Ollama 供应商，还有 ollama 命令行。把它们指向 magpie 的网关 http://127.0.0.1:3425，就能看到 magpie 的模型，而且是所有供应商的，不只是 Ollama 的。

  • 路由。magpie 响应 /api/version、/api/tags、/api/show、/api/chat 和 /api/generate。
  • 同一条路径。这里的对话和 /v1/chat/completions 走同一套处理，所以 Key 限制、路由、备用模型和用量统计都一样。只允许用部分模型的网关 Key，只会列出那些模型。
  • 告诉客户端的信息。/api/tags 和 /api/show 会标明工具调用、读图（模型能读图片时）和思考（模型会推理时）。/api/show 还会给出模型的窗口，magpie 不认识的模型给 32768。ollama 命令行的 name:latest 会找到名为 name 的模型。

常见报错

  • 拉取的模型不在列表里。列表来自服务本身。点 获取模型 或运行 magpie provider refresh ollama，再在供应商的模型列表里勾选它。名字要和 Ollama 列出的一致，标签也算在内。
  • Ollama 没在运行。magpie provider test ollama 会通过每个接口发一个很小的请求，也可以指定模型；加上 --as codex 或 --as claude-code 就按那个工具的方式发。启动 Ollama，或检查 服务器地址。fallback 可以指定它挂掉时请求去哪。
  • “exceeded max context length”。对话超出了模型加载时的长度。在供应商上设好真实的 上下文窗口，工具会在到达之前压缩。
  • 连不上另一台电脑。检查 服务器地址 里的地址和端口；自签名证书的 HTTPS 要打开 不校验它的证书。

常见问题

Claude Code 怎么用 Ollama 的本地模型？

在 magpie 里添加 Ollama（供应商 → 添加供应商 → 本机下的 Ollama），然后在 Claude Code 那一行选它的模型，或者运行 magpie claude ollama/qwen3。Claude Code 的请求经过 magpie 网关，原样发到 Ollama 在 http://localhost:11434 的 Anthropic Messages 接口。

Codex 能用 Ollama 吗？

能。Codex 只会说 Responses 接口，magpie 会把它的请求转成 Chat Completions 发给 Ollama，再把回复转回来，工具调用也一样。运行 magpie codex ollama/qwen3 即可。

Gemini CLI 和 OpenCode 能用 Ollama 吗？

能。Gemini CLI 说的是 Google 的接口，magpie 把它的请求翻译成 Ollama 的 Chat Completions，再把回复翻译回去。OpenCode 本身说 Chat Completions，请求原样发给 Ollama。运行 magpie gemini model ollama/qwen3 或 magpie opencode ollama/qwen3。

怎么在 Claude Code 里用 Ollama 的 qwen3-coder？

先在 Ollama 里拉取它，再在 magpie 的供应商编辑页点「获取模型」（或运行 magpie provider refresh ollama），然后在 Claude Code 那一行选中它。它在 magpie 里的 ID 是 ollama/ 加上 Ollama 列出的名字，标签也算在内。记得同时设好它的上下文窗口：Claude Code 会把不认识的模型当作 200K。

magpie 能用另一台电脑上的 Ollama 吗？

能。把供应商的服务器地址改成那台电脑，比如 magpie provider set ollama address=192.168.1.20:11434。局域网里的服务器会直接连接，不走设置或系统里的代理。

magpie 支持 Ollama Cloud 吗？

支持。用 ollama.com/settings/keys 上创建的 Key 添加 Ollama Cloud，magpie 会列出这个 Key 能用的模型，按 models.dev 的价格计费，并显示账户套餐内的额度和你购买的余额。

本地 Ollama 需要 API Key 吗？

不需要，Ollama 预设不用 Key。Ollama Cloud 需要。

LM Studio、oMLX、vLLM、llama.cpp 等其他本地服务见 本地模型。想让本地模型给每个请求分类、决定路由，见 意图路由。
