文档 · 指南

让 JetBrains Air 用任意模型

JetBrains Air 用设置里登录的账号运行自带的 Agent（Claude Agent、Codex、Gemini CLI、Junie），没有可改的 base URL。但它也接受任何支持 Agent Client Protocol 的 Agent。magpie 添加一个名为 Magpie 的 Agent，于是 Air 能用你在 magpie 里的任何模型：DeepSeek、GLM、Qwen、OpenAI 或 Anthropic Key，或 ChatGPT、Copilot 订阅。

Air 从配置目录里的 acp.json 读取自定义 ACP Agent：macOS 是 ~/Library/Application Support/JetBrains/Air，Linux 是 $XDG_CONFIG_HOME/JetBrains/Air，Windows 是 %APPDATA%\JetBrains\Air。magpie 在那里加一个名为 Magpie 的条目，启动 OpenCode 的 ACP 服务 opencode acp，并把 OPENCODE_CONFIG 设为 magpie 放在 acp.json 旁边的 magpie-opencode.json。这个文件包含 magpie 的供应商、它的模型、任务启动时用的模型，以及只留 magpie 的 enabled_providers。OpenCode 把它合并到你自己的配置之上，你的插件、Agent 和 MCP 服务器保持不变。Air 自带的 Agent 和它们所用的账号都不受影响。

接入 Air

  1. 在 magpie 里添加供应商在 供应商 页添加 API Key，或登录一个订阅。
  2. 在 JetBrains Air 那一行选模型在 Agent 页，选 magpie 下的一个模型。
  3. 在 Air 里新建任务在 Agent 菜单里选 Magpie，magpie 的模型和路由组就在它的模型菜单里。
终端
magpie air deepseek/deepseek-v4-pro        # Air 应用
magpie air-ide deepseek/deepseek-v4-pro    # JetBrains IDE 里的 Air

OpenCode

Magpie Agent 就是 OpenCode，所以需要装好 OpenCode。应用不一定有 shell 的 PATH，所以 magpie 给 Air 的是完整路径：先找 PATH 上的，再找 ~/.opencode/bin，再找 JetBrains IDE 或 Zed 从 ACP registry 安装的。都找不到时，那一行会提示安装：

终端
npm i -g --allow-scripts=@opencode/cli @opencode/cli

模型菜单

Air 里 Magpie Agent 的模型菜单就是 OpenCode 报给它的列表：magpie 的模型和路由组，没有 OpenCode 自己的。那一行选的模型是新任务启动时用的模型，也是 OpenCode 生成标题和摘要用的小模型。每个任务都可以在 Air 的菜单里另选。

JetBrains IDE 里的 Air

Air 也是 JetBrains IDE 的插件：2026.3 自带，2026.2 从 JetBrains Marketplace 安装。插件在所有系统上都从 ~/.jetbrains/acp.json 读取自定义 Agent，所以它有自己的一行 Air (JetBrains IDEs)，在那里添加同样的 Magpie Agent。如果还没看到 Magpie，重启 IDE。在 IDE 里，Air 自带的 Codex 和 Claude Agent 用它们自己的登录时，运行的是本机的 codex 和 claude，所以只要 Codex 和 Claude Code 已接入 magpie，它们也走 magpie。Air 那一行的模型只对 Magpie Agent 生效。

WSL 项目

Windows 上的 IDE 打开位于 WSL 发行版里的项目时，会在该发行版里启动 Agent，并拒绝 Windows 命令。所以每个装了 OpenCode 且正在运行的发行版都有自己的条目，比如 Magpie (WSL Ubuntu)，使用发行版里 OpenCode 的路径，配置里写的是发行版能访问到的网关地址。

环境变量里的供应商 Key

有一个 OpenCode 自身的限制：如果 Air 启动它时的环境里设了某个供应商的 Key（OPENAI_API_KEY、DEEPSEEK_API_KEY 等，且不为空），它的 ACP 服务只列出那个供应商，配置里的一个都不列，于是看不到 magpie 的模型。取消这个变量，或改把 Key 放在 OpenCode 的 auth.json 里。

切回

把那一行从 magpie 取消。magpie 从 acp.json 删除 Magpie 条目，并删掉 magpie-opencode.json。Air 自带的 Agent 从未被改动。如果 Magpie 条目被手动删除，那一行会提示 Air 已连不到 magpie。

常见问题

JetBrains Air 能用 DeepSeek、GLM 或 Qwen 吗？

能。在 Air 新建任务时选 Magpie Agent，你在 magpie 里的所有模型都在它的模型菜单里：DeepSeek、GLM、Qwen、GPT、Claude 等。

magpie 会改 Air 自带的 Agent 或账号吗？

不会。它只在 acp.json 里加一个 ACP Agent，Magpie。Claude Agent、Codex、Gemini CLI 和 Junie 继续用它们自己的账号。

为什么 Magpie Agent 里看不到 magpie 的模型？

通常是 Air 启动时的环境里设了 OPENAI_API_KEY 这类供应商 Key，OpenCode 就只列出那个供应商。取消它，或把 Key 放进 OpenCode 的 auth.json。

IntelliJ IDEA、PyCharm 等 JetBrains IDE 能用吗？

能，通过 Air 插件（2026.3 自带，2026.2 从 Marketplace 安装）。接入 Air (JetBrains IDEs) 那一行，然后重启 IDE。

更多 Agent 用同样的模型：OpenCode 接入其他模型、让 Antigravity 用任意模型、让 CodeBuddy 用任意模型、让 Snow CLI 用任意模型。遇到报错？见 常见错误排查，或到 Discord 提问。
