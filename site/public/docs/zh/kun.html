让 Kun 用任意模型

Kun（KunAgent）是本地优先的 AI 工作台：桌面应用（Code、Work、对话和 Agent）和 kun TUI 都是同一个运行时 kun serve 的客户端。它的模型来自运行时里的模型连接。magpie 加一个自己的连接并设成默认，Kun 就能用 DeepSeek、GLM、Kimi、Qwen、Claude 或 ChatGPT 订阅等 magpie 里的任意模型，桌面应用和 TUI 都一样。

接入 Kun

  1. 在 magpie 里添加供应商在 供应商 页添加 API Key，或登录一个订阅。
  2. 打开 Kunmagpie 通过运行中的 Kun 添加连接，见下文。
  3. 在 Agent 页给 Kun 选模型选一个 via magpie 的模型，它就成为 Kun 的默认模型。
终端
magpie kun deepseek/deepseek-v4-pro

通过 Kun 自己的 API

Kun 的模型连接登记在数据目录（$KUN_DATA_DIR，默认 ~/.kun/data）的 model-connections.v2.json，连接的 Key 存在 Kun 受保护的凭据库里，所以不能手动写进文件。magpie 和 Kun 自己的 设置 › 供应商 以及 kun provider 命令一样，通过运行时的管理 API 操作：

终端
GET    /v1/model-connections              连接列表和版本号
POST   /v1/model-connections/connect      magpie 的连接
PATCH  /v1/model-connections/magpie       它的模型列表
POST   /v1/model-connections/select       Kun 的默认模型
DELETE /v1/model-connections/magpie       切回

API 地址和令牌取自数据目录里的 runtime.json。magpie 的连接名为 magpie，是指向网关 /v1 的 HTTP 连接，走 Chat Completions，用 magpie 给 Kun 的专用 Key。如果你在 Kun 里把它改名成 magpie-2，magpie 记着它的 id，仍认得出来。

模型列表

连接里的模型，就是你在 magpie 的 Agent 页为 Kun 勾选的模型，最多 500 个。在 magpie 里增删模型，或者网关换了端口，都会同步到这个连接。

Kun 要在运行

Kun 只在运行时才能添加或修改模型供应商。Kun 没运行时，magpie 会提示：打开 Kun，再试一次。

切回

magpie 第一次接入时记下 Kun 原来的默认模型。切回时先把默认改回去，再删掉 magpie 的连接。如果 Kun 没有你自己的供应商可用，magpie 会提示先在 Kun 的 设置 › 供应商 里添加一个。

终端
magpie kun default

常见问题

Kun 能用 DeepSeek、GLM 或 ChatGPT 订阅吗？

能。打开 Kun，在 magpie 的 Agent 页给 Kun 选一个 via magpie 的模型，magpie 会加一个 magpie 模型连接并设成默认。

提示“open Kun, then try again”怎么办？

Kun 只在运行时才接受模型供应商的改动。打开 Kun 桌面应用或 kun serve，再试一次。

kun TUI 也能用吗？

能。桌面应用和 kun TUI 都是 kun serve 的客户端，用的是同一组模型连接。

切回后默认模型会变回原来的吗？

会。magpie 记下了原来的默认模型，切回时先改回去，再删除 magpie 的连接。

更多桌面应用用同样的模型：让 OpenHanako 用任意模型、让 DS Bot 用任意模型、让团结 Cowork 用任意模型。遇到报错？见 常见错误排查，或到 Discord 提问。
