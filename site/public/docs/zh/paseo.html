文档 · 指南

Paseo 用上 magpie 的所有模型

Paseo（getpaseo/paseo）是一个替你运行 Claude Code、Codex 等 Agent 的应用。它启动的是同一个 Claude Code，所以 Claude Code 接入 magpie 后，在 Paseo 里也走 magpie。但 Paseo 的模型选择器是它自己列的，看不到 magpie 提供的大部分模型。magpie 把这些模型写进 Paseo 自己的 additionalModels，于是 Paseo 的 Claude 模型列表里能直接选 DeepSeek、GLM、Kimi、Qwen、GPT 或 ChatGPT 订阅等 magpie 里的所有模型。

接入 Paseo

  1. 先把 Claude Code 接入 magpie在 magpie 的 Agent 页给 Claude Code 选一个 magpie 模型。Paseo 列出的 id 要由接入了 magpie 的 Claude Code 来跑。
  2. 打开 Paseo 那一行有 ~/.paseo 文件夹，magpie 就有 Paseo 一行。选 magpie：把 magpie 的每个模型放进 Paseo 的 Claude 模型选择器。
  3. 重启 Paseo 的守护进程Paseo 在守护进程启动时读模型列表，重启后就能看到 magpie 的模型。
终端
magpie claude deepseek/deepseek-v4-pro   # Claude Code on magpie first
magpie paseo magpie                      # every magpie model in Paseo's picker

为什么要单独接

Claude Code 自己的 /model 读的是 ~/.claude/settings.json 里的 modelPicker，magpie 接入 Claude Code 时会把所有模型写在那里。Paseo 不读 modelPicker：它的列表是自己的官方模型，加上 settings.json 的 model 和几个 ANTHROPIC_*_MODEL 分级变量。所以只接 Claude Code 时，除了主模型和分级模型，magpie 的其他模型都不在 Paseo 的选择器里。Paseo 另外会把自己配置里的 agents.providers.claude.additionalModels 追加到列表后面，每个 id 原样交给 Claude Code，magpie 就写在这里。

写了哪些内容

Paseo 的文件夹是 PASEO_HOME，没设时是 ~/.paseo。magpie 在 config.json 的 agents.providers.claude.additionalModels 里为每个模型加一项 {id, label, description}：id、[1m] 标记和名字都和 Claude Code 的 /model 里一样，description 以 via magpie 结尾，magpie 就靠它认出自己的条目。

终端
// ~/.paseo/config.json
{"agents": {"providers": {"claude": {"additionalModels": [
  {"id": "my-own-model", "label": "…", "description": "…"},
  {"id": "…", "label": "…", "description": "via magpie"},
  {"id": "…", "label": "…", "description": "1M context · via magpie"}
]}}}}

你自己加的条目放在前面，位置不变。你自己列过的 id 算你的，magpie 不再重复加。列表读不了时 magpie 原样不动。magpie 的模型变了，magpie 会更新自己的条目。

什么时候生效

Paseo 只在守护进程启动时读模型列表，所以要重启 Paseo 的守护进程才能看到 magpie 的模型，magpie 在 Paseo 运行时会提示这一点。另外 Claude Code 本身也必须接入 magpie，这些 id 才有人提供。

切回

在 magpie 里把 Paseo 那一行切回默认：magpie 只删掉描述以 via magpie 结尾的条目，你自己的都留着；没有条目剩下时删掉整个 additionalModels。

终端
magpie paseo default

常见问题

为什么 Paseo 的模型列表里看不到 magpie 的模型？

Paseo 不读 Claude Code 的 modelPicker，只列自己的模型、settings.json 的 model 和几个 ANTHROPIC_*_MODEL 变量。在 magpie 里打开 Paseo 那一行，magpie 会把所有模型写进 Paseo 的 additionalModels。

要先接入 Claude Code 吗？

要。Paseo 把这些 id 原样交给它启动的 Claude Code，Claude Code 接入 magpie 后才会由 magpie 提供。

接入后还是看不到怎么办？

Paseo 在守护进程启动时读模型列表。重启 Paseo 的守护进程即可。

我自己加的 additionalModels 会被改掉吗？

不会。magpie 只增删描述以 via magpie 结尾的条目，你的条目排在前面，位置不变。

更多 Agent 用同样的模型：Claude Code 接入其他模型、让 T3 Code 用任意模型、让 Craft Agents 用任意模型。遇到报错？见 常见错误排查，或到 Discord 提问。
