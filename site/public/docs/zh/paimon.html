Paimon

工作原理 接入 Paimon config.json 为什么用 litellm 上下文窗口和压缩 切回

文档 · 指南

让 Paimon 用任意模型

Paimon（aisk/paimon，用 uv tool install paimon 安装）是一个基于 pydantic-ai 的终端编程 Agent。它的设置是一个 JSON 文件，模型写成 供应商:模型名，每个供应商有自己的地址和 Key。magpie 在里面加一个指向网关的供应商，Paimon 就能用 DeepSeek、GLM、Kimi、Qwen、Claude 或 ChatGPT 订阅等 magpie 里的任意模型。

接入 Paimon

  1. 在 magpie 里添加供应商在 供应商 页添加 API Key，或登录一个订阅。
  2. 在 Agent 页给 Paimon 选模型选一个 via magpie 的模型。
  3. 重启 PaimonPaimon 只在启动时读设置，正在运行的 Paimon 要重新启动才换模型。
终端
magpie paimon deepseek/deepseek-v4-pro

config.json

设置文件是 $PAIMON_CONFIG_HOME/config.json，没有设置这个变量时是 ~/.config/paimon/config.json（Windows 也一样）。magpie 只改三项：

终端
{
  "model": "litellm:deepseek/deepseek-v4-pro",
  "providers": {
    "litellm": {
      "api_base": "http://127.0.0.1:3425/v1",
      "api_key": ""
    }
  },
  "compaction": { "context_window": 1000000 }
}

模型只会带上它自己供应商的 Key 发出去。文件里的其他内容原样保留；文件不存在时 magpie 新建一个，权限只给你自己（里面有 Key），和 Paimon 自己建的一样。WSL 发行版里的 Paimon 也一样设置。

为什么用 litellm

magpie 用的是 pydantic-ai 的 litellm 供应商：一个 OpenAI 兼容的代理，按 厂商/模型 名里的厂商判断模型特性，正好是 magpie 的模型 id 写法。Paimon 的登录流程不提供 litellm，所以它几乎不会和你自己的供应商冲突。网关靠 magpie 给 Paimon 的专用 Key 认出这个供应商是 magpie 的。

上下文窗口和压缩

Paimon 对 genai-prices 不认识的模型名（magpie 的 id 就是这样），只按 compaction.context_window 做上下文压缩，没有这个值就完全不压缩。所以 magpie 写入它知道的模型上下文窗口；magpie 不知道窗口的模型，就用你原来设的值，绝不沿用上一个模型的。

切回

第一次接入时，magpie 记下你原来的 model、providers.litellm 和 compaction.context_window。切回时全部写回去；magpie 留下的空对象删掉；如果文件是 magpie 新建的、最后什么都没剩，就把文件也删掉。接入后你在 Paimon 里自己换到别的供应商的模型，magpie 会把那个当作你的，切回时用它。

终端
magpie paimon default

常见问题

Paimon 能用 DeepSeek、GLM 或 ChatGPT 订阅吗？

能。在 magpie 的 Agent 页给 Paimon 选一个 via magpie 的模型，然后重启 Paimon。

为什么 config.json 里的模型是 litellm: 开头？

magpie 通过 pydantic-ai 的 litellm 供应商接入，它是 OpenAI 兼容代理，认得 magpie 的「厂商/模型」写法。

Paimon 会自动压缩上下文吗？

会。magpie 写入模型的上下文窗口，Paimon 按它压缩；没有这个值时 Paimon 不压缩。

切回后原来的设置会恢复吗？

会。magpie 记下了原来的 model、litellm 供应商和上下文窗口，切回时写回去，其他内容一直没动。
