Vercel AI Gateway 接入 Claude Code、Codex 等 Agent

Vercel AI Gateway 用一把 Key 提供各家厂商的模型，模型 id 写成 厂商/模型。magpie 的 vercel 预设把它接到 Claude Code、Codex、OpenCode 等 Agent，三个接口都已配好，不用自己填地址。

添加

  1. 拿一把 Key。在 Vercel 控制台的 AI Gateway → API Keys 里创建一把。
  2. 添加。在应用里选 Vercel AI Gateway，把 Key 填进 API 密钥，或者在命令行：
终端
magpie provider add vercel 
magpie provider test vercel

预设里 Chat Completions 和 Responses 指向 https://ai-gateway.vercel.sh/v1，Anthropic Messages 指向 https://ai-gateway.vercel.sh。按 Vercel 的文档，三个接口都能用每一个模型。

给 Agent 用

模型 id 写成 vercel/<Vercel 的模型 id>，Vercel 的 id 本身就带着厂商：

终端
magpie claude vercel/anthropic/claude-sonnet-4.6
magpie codex vercel/openai/gpt-5.5

Claude 模型无论 Agent 说的是哪种协议，magpie 都发到 Vercel 的 Anthropic Messages 接口：同时提供两种接口的中转站在 Chat 上会丢掉 cache_control，每一轮都按没命中缓存计费，思考也一样受影响。其他模型按 Agent 自己的协议走：Codex 走 Responses，Chat 客户端走 Chat Completions。

模型列表

Vercel 的 /v1/models 会写出每一行是什么类型，magpie 按它来分：

  • 聊天模型出现在 Agent 的模型选择里；上下文长度取自 Vercel 给的 context_window。
  • 生图和视频模型给 magpie 的生图、生成视频用，向量和重排模型走 /v1/embeddings 和 /v1/rerank，语音合成和转写模型走 /v1/audio。
  • 评估模型（如 typesafe-ai/jev）和实时语音模型不回答聊天，不放进列表。
  • 带 -batch 的 id 只给 Vercel 的批量接口用，同步请求不接受，也不放进列表。

几点说明

  • Vercel AI Gateway 是中转站：它可以和 OpenRouter、厂商自己的账号一起放进路由组，一个失败了，组里的下一个接着回答。
  • Vercel 的计费和额度在 Vercel 控制台查看；magpie 的用量页记录每次请求的 Token。

常见问题

magpie 支持 Vercel AI Gateway 吗？

支持，用 vercel 预设。填一把 AI Gateway 的 Key，Chat Completions、Responses 和 Anthropic Messages 三个接口都已配好，模型 id 写成 vercel/<厂商>/<模型>。

Claude Code 用 Vercel 上的 Claude 会命中缓存吗？

会。Claude 模型一律发到 Vercel 的 Anthropic Messages 接口，cache_control 原样保留，不会因为走 Chat 而丢掉缓存。

Codex 能用 Vercel AI Gateway 吗？

能。Codex 说 Responses，magpie 把它发到 Vercel 的 /v1 Responses 接口，模型写 vercel/<厂商>/<模型>。

为什么列表里没有某些模型？

magpie 按 Vercel 标的类型分：评估模型、实时语音和 -batch 的 id 不回答同步聊天，不放进 Agent 的列表；生图、视频、向量和语音模型去它们自己的接口。
