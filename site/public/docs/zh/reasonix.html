让 Reasonix Studio 用任意模型

Reasonix Studio 2.x 和它的命令行共用同一份 config.toml 和 .env。magpie 在里面加一个名为 magpie 的 provider，指向本机的 magpie 网关，于是 Reasonix 的执行模型和规划模型都可以选 DeepSeek、GLM、Kimi、Qwen、GPT 或 ChatGPT 订阅等 magpie 里的任意模型。你自己的其他 provider、密钥和项目/会话设置都不动。

接入 Reasonix

  1. 打开 magpie 的 Agent 页找到 Reasonix Studio 一行。它的模型字段叫 executor，即执行模型。
  2. 选一个 magpie 模型列表里分两组：Reasonix Studio 自己的模型，以及 via magpie 的模型。选后者，magpie 写好 provider 和密钥，再把 default_model 设成 magpie/<模型>。
  3. 按需选推理强度和规划模型支持推理强度的模型可以选 effort；规划模型 planner 可以另选一个，或设为 off 关掉单独的规划模型。
终端
magpie reasonix magpie/deepseek/deepseek-v4-pro   # executor
magpie reasonix effort high
magpie reasonix planner magpie/deepseek/deepseek-v4-flash # a separate planner, or: off

写了哪些内容

Reasonix 的文件夹是 REASONIX_HOME；没设时，Windows 上是 %APPDATA%\reasonix，其他系统是 ~/.reasonix。WSL 里的 Reasonix 用 Linux 的 ~/.reasonix，并按发行版能连到的地址写网关。magpie 写入：

终端
# ~/.reasonix/config.toml
default_model = "magpie/deepseek/deepseek-v4-pro"

[[providers]]
name = "magpie"
kind = "openai"
base_url = "http://127.0.0.1:3425/v1"
api_key_env = "MAGPIE_REASONIX_API_KEY"
models = ["…", "…"]
default = "deepseek/deepseek-v4-pro"
reasoning_protocol = "openai"
no_proxy = true

[providers.model_overrides."deepseek/deepseek-v4-pro"]
supported_efforts = ["…"]
context_window = …
max_output_tokens = …

# ~/.reasonix/.env
MAGPIE_REASONIX_API_KEY=…

每个模型带上上下文窗口、最大输出、是否支持图片和支持的推理强度；不支持推理的模型 reasoning_protocol 设为 none。magpie 的模型变了，magpie 会更新这个 provider。Studio 设了 [desktop] provider_access 时，magpie 把 magpie 加进去。密钥只写进 .env，config.toml 只写变量名。

magpie 只管自己的这一项：已经有一个不是 magpie 建的 magpie provider、MAGPIE_REASONIX_API_KEY 已被别的 provider 用、或 .env 里这个变量出现两次时，magpie 会报错而不是覆盖。magpie 另在自己的配置目录里存一份恢复记录（只有设置，没有上游凭据），用来切回时还原你原来的 default_model。

执行模型和规划模型

执行模型是 default_model，规划模型是 [agent] planner_model，两者可以分别来自 magpie 或 Reasonix 自己的 provider。只要规划模型还在用 magpie，即使执行模型切回了你自己的模型，magpie 的 provider 也会保留。

什么时候生效

Reasonix Studio 2.x 和原生 1.39.x/2.x CLI 只在启动时读全局设置，改完要开一个新进程。项目或会话里指定的模型会覆盖执行模型和规划模型。

切回

切回默认时，magpie 只撤销自己加的内容：删掉 magpie provider、把 default_model 还原成接入前的值（原来没有就删掉）、从 provider_access 里去掉 magpie、删掉 .env 里 magpie 的密钥；magpie 新建的文件变空时一并删除。你之后自己选的模型、改过的其他 provider 和密钥都保留。也可以直接选回列表里 Reasonix Studio 组的某个模型。

终端
magpie reasonix default

常见问题

Reasonix Studio 怎么用 DeepSeek、GLM 或 ChatGPT 订阅？

在 magpie 的 Agent 页给 Reasonix Studio 的 executor 选一个 via magpie 的模型。magpie 在 config.toml 加 magpie provider，在 .env 写密钥，并把 default_model 设成 magpie/<模型>。

规划模型能单独选吗？

能。planner 字段写 [agent] planner_model，可以选另一个 magpie 模型、Reasonix 自己的模型，或 off。

改完 Reasonix 没反应？

Reasonix 只在启动时读全局设置。开一个新的 Studio 或 CLI 进程；另外项目或会话里指定的模型会覆盖全局设置。

会动我自己的 provider 和密钥吗？

不会。magpie 只增删名为 magpie 的 provider 和 MAGPIE_REASONIX_API_KEY，遇到不是自己建的同名项会报错而不覆盖。

更多 Agent 用同样的模型：让 jcode 用任意模型、让 Crush 用任意模型、OpenCode 接入其他模型、让 AtomCode 用任意模型。遇到报错？见 常见错误排查，或到 Discord 提问。
