MiniMax 与编程套餐接入 Claude Code、Codex、Gemini CLI 和 OpenCode

MiniMax 提供兼容 OpenAI 的 Chat API 和兼容 Anthropic 的接口，有国际站和国内站，按量付费和编程套餐的 Key 都能用。在 magpie 里添加一次 Key，Claude Code、Codex、Gemini CLI、OpenCode 以及你接入的其他工具都能通过 magpie 的本地网关 127.0.0.1:3425 用上 MiniMax-M3、MiniMax-M2.7 等模型。

添加 MiniMax

  1. 拿到 Key国内在 platform.minimaxi.com 创建，国际站在 platform.minimax.io。编程套餐的 Key 以 sk-cp- 开头。
  2. 添加供应商在 magpie 的 供应商 页点 ＋ 添加供应商，选 MiniMax (China) 或 MiniMax，粘贴 Key 并保存。按量付费和编程套餐的 Key 都这样添加。
  3. 给工具选上在 Agent 页点工具那一行的模型，选一个 MiniMax 模型。
终端
magpie provider add minimax-cn sk-cp-…  # 编程套餐，platform.minimaxi.com
magpie provider add minimax sk-…        # 国际站，platform.minimax.io

套餐与接口地址

预设平台Chat CompletionsAnthropic Messages
MiniMax minimaxplatform.minimax.io（国际）https://api.minimax.io/v1https://api.minimax.io/anthropic
MiniMax (China) minimax-cnplatform.minimaxi.com（国内）https://api.minimaxi.com/v1https://api.minimaxi.com/anthropic

编程套餐和按量付费用的是同一组接口地址，请求按哪种计费由 Key 决定。国际站和国内站是不同的账号，各自的 Key 放在各自站点的预设下。

在各个工具里用

在 Agent 页里点某个工具那一行的模型来选，或者在终端里选。每篇指南都写了 magpie 在那个工具的配置里改了什么、怎么换回去。

终端
magpie claude minimax-cn/MiniMax-M3
magpie codex minimax-cn/MiniMax-M3
magpie gemini model minimax-cn/MiniMax-M2.7
magpie opencode minimax-cn/MiniMax-M3
  • Claude Code 说的是 Anthropic Messages，MiniMax 的 Anthropic 接口也说这种协议，所以请求原样转过去。opus、sonnet、haiku 三档默认都用你选的模型，也可以给某一档单独指定。Claude Code 接入其他模型。
  • Codex 只说 OpenAI Responses。MiniMax 提供 Chat Completions 和 Anthropic Messages，不提供 Responses，所以 magpie 会转换请求和回复，流式输出和工具调用都保留。模型会出现在 Codex 的 /model 里，带着推理强度。Codex 接入其他模型。
  • Gemini CLI 说 Gemini 的 API。magpie 把它指向本地网关并做转换。Gemini CLI 接入其他模型。
  • OpenCode：magpie 把模型写进 opencode.json，带上推理档位和价格。OpenCode 接入其他模型。

MiniMax Code 也是 magpie 支持的工具：它那一行可以选 MiniMax 的模型，也可以选其他厂商的。

思考与推理强度

  • 交错思考。MiniMax 的 Chat API 把模型的思考放在回复正文的 <think> 标签里，并要求之后的轮次原样带回。magpie 把它作为思考交给工具，再放回 MiniMax 要的位置。
  • 推理强度。MiniMax-M3.1-Flash 及其预览版有从 low 到 max 的思考档位。magpie 像 MiniMax Code 一样把工具要的档位写进 output_config.effort，不会被 token 预算吃掉。
  • 一直思考的模型。MiniMax-M3.1-Flash-Preview 不允许关掉思考。工具要求关掉时，magpie 会保持思考开启再问一次，工具拿到的是回答而不是报错。

编程套餐窗口与用量

  • 编程套餐窗口。编程套餐 Key 那一行显示 MiniMax 告知的每个窗口还剩多少：一个滚动窗口和一个按周的窗口，从 MiniMax 读取。模型用的是通用额度；单独计量的额度（比如视频）显示为次数，例如 4 / 5。按量付费的 Key 没有窗口，也没有卡片。
  • 路由。有多个编程套餐 Key 时，magpie 按窗口分配请求，窗口用完的 Key 会休息到重置。
  • 用量。用量 页会统计经过 magpie 的每个工具和模型的 token、缓存命中和费用。

常见问题

MiniMax 怎么接入 Claude Code？

在 magpie 里添加 MiniMax 的 Key（供应商 → 添加供应商 → MiniMax (China) 或 MiniMax），然后在 Claude Code 那一行选一个模型，比如 MiniMax-M3，或者运行 magpie claude minimax-cn/MiniMax-M3。magpie 会写好 Claude Code 的 settings.json，把请求转给 MiniMax 的 Anthropic 接口 https://api.minimaxi.com/anthropic。

MiniMax 编程套餐怎么用？

把编程套餐的 Key（sk-cp- 开头）添加到你购买套餐那个站点的 MiniMax 预设下，和按量付费的 Key 一样。magpie 根据 MiniMax 对这个 Key 的答复区分两者，并在编程套餐 Key 那一行显示用量窗口。

Codex 能用 MiniMax 吗？

能。MiniMax 提供 Chat Completions 和 Anthropic Messages，不提供 Responses，所以 magpie 会转换 Codex 的请求和 MiniMax 的回复。在 Codex 那一行选模型，或运行 magpie codex minimax-cn/MiniMax-M3，模型会出现在 Codex 的 /model 里。

MiniMax Code 能用其他模型吗？

能。MiniMax Code 是 magpie 支持的工具之一，在 Agent 页它那一行可以选你添加的任何模型，MiniMax 的或其他厂商的都行。

为什么 MiniMax 的思考出现在正文里？

MiniMax 的 Chat API 把模型的思考放在回复正文的 <think> 标签里。magpie 把它取出来作为思考交给工具，在之后的轮次再按 MiniMax 要求的方式放回去。

能用多个 MiniMax Key 吗？

能。把它们都添加到 MiniMax 供应商下并逐个勾选。magpie 会把请求分摊到这些 Key 上，并按编程套餐 Key 的窗口来分配和让它休息：用完窗口的 Key 会等到重置后再用。

各个工具的指南：Claude Code 接入其他模型、Codex 接入其他模型、Gemini CLI 接入其他模型、OpenCode 接入其他模型。遇到问题可以在 Discord 提问。
