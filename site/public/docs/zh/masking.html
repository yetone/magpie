本地脱敏

magpie 可以在 Agent 发出的请求离开这台电脑之前先做脱敏。API Key、密码和 Token，以及你选择的邮箱、手机号和自定义词，会以 {{API_KEY_es6eu6jk}} 这样的占位符发给模型厂商；回复里的占位符再换回原值，所以 Agent 和你的文件里始终是真值，厂商看不到。脱敏在这台电脑上、在 magpie 的网关里完成，默认关闭。

只覆盖经过 magpie 的请求。接入 magpie 的 Agent 通过网关发请求，不管由哪个供应商或账号回答都会脱敏。绕过 magpie、直接请求厂商的 Agent 不在范围内。

打开它

  1. 打开页面进入 设置 → 隐私。
  2. 脱敏密钥在 要遮什么 下把 脱敏密钥 设为 开启：API Key、私钥、Token 和密码。
  3. 个人信息（按需）把 脱敏个人信息 设为 开启，邮箱、手机号、身份证号和银行卡号也一并脱敏。打开后，下面会列出其他各类个人信息，每类有自己的开关。
  4. 自定义词在 脱敏词 里填不想让厂商看到的人名、项目代号或主机名，每行一个（粘贴用逗号隔开的几个词，会各占一行）。脱敏词不区分大小写 打开后，Nightjar 也会遮掉 NIGHTJAR。magpie 不认识的密钥（比如你自己网关的 key）加到 自定义脱敏规则：填它的开头，或一个正则表达式。
  5. 试一试把一段文字粘到 试一试，就能看到厂商实际会收到什么。粘进去的内容不会保存。

改动从下一个请求开始生效，不用重启，Agent 那边也不用改。实际做脱敏的是内置插件 隐私遮盖（redact，在 设置 → 插件），只要设置里要求了任何脱敏，它就是开着的。

没有专门的命令行命令。没有窗口时（magpie serve、Docker），可以用 magpie web 打开同一个页面，或者直接写 ~/.config/magpie/settings.json（Docker 里是 /config/magpie/settings.json）。每个请求都会重新读这个文件：

settings.json 
{
  "redact": true,
  "redactPersonal": true,
  "redactWords": ["Nightjar", "db.acme-corp.cn"]
}

会遮掉什么

开关能找到什么
脱敏密钥私钥块（-----BEGIN … PRIVATE KEY-----）。按格式识别的 API Key：sk-…（OpenAI、Anthropic、OpenRouter）、ghp_/github_pat_、glpat-、AIza…、xox…-、sk_live_、AKIA/ASIA、hf_、gsk_、xai-、npm_、pypi-、dop_v1_、SG.、Cloudflare 的（cfut_、cfat_、cfk_、cfoat_、Origin CA v1.0-、Tunnel token），以及 oc_sk_… 这类中转站的 key。JWT。user:password@host 里的密码。.env 和配置文件里以密钥命名的字段的值：DB_PASSWORD=…、api_key: …、client_secret、token、credential。以及你的 自定义脱敏规则。 钱包私钥按钱包导出的格式匹配：比特币 WIF、BIP32 xprv、以太坊和 TRON 的 0x 私钥、Solana 私钥与 id.json 密钥对、Sui suiprivkey1…、Aptos ed25519-priv-0x…、Stellar 种子、NEAR ed25519:…、Nostr nsec1…、age 身份、Zcash 扩展支出密钥，以及 seed、助记词 后面、每个词都在 BIP39 词表里的 12 到 25 个单词。没有固定前缀的私钥要先通过校验才会被替换：WIF 和 xprv 看校验和，Solana 私钥看后半段公钥，Stellar 种子看 CRC，所以 Solana 交易签名照原样发送。0x 私钥和交易哈希形状相同，只在私钥的名字后面才替换（PRIVATE_KEY=、--private-key、new Wallet(…)、私钥）；哈希、存储槽和 sha256 校验值照原样发送。交易所的 API key、secret 和 passphrase 按字段名替换。
脱敏个人信息邮箱、中国大陆手机号（11 位的编号不算：在 order_id 下或跟在「订单号」后面的照原样发出）、校验位对得上的身份证号和银行卡号。默认也开着的：美国社会安全号、护照号（跟在 passport、护照或パスポート后面）、IBAN、生日（旁边有 birthday、DOB 或「生日」，且是一年以前的日期，所以今天的日期不动）、MAC 地址、序列号（跟在 S/N 后面）。默认关闭、需要自己打开的（Agent 几乎每个请求都会带）：主目录里的用户名（以一个每轮都相同的假名发出，模型看到的是正常的文件夹，而不是占位符）、用户名和主机名（user@host）、公网 IP 地址（以 public-ip-kvxqmrtz 这样的名字发出，模型仍知道这是公网地址，照常用它连接，命令里再换回真实地址）、云存储桶。钱包或合约地址（0x 加 40 位十六进制）是公开的，照原样发出；私钥照样脱敏。
脱敏词你填的每个词，精确匹配，换成 {{TERM_…}}。填的是日期（比如 1990-05-12）时，同一天的各种写法都会遮掉：1990/5/12、1990.05.12、1990年5月12日、19900512、May 12, 1990；13/05/1990 这种日在前的写法只在日和月不会混淆时才算。别的日期和 1990.5.12.1 这样的版本号不会被遮。
用本地模型查找在 怎么找 下面。一个在这台电脑上运行的模型能找出规则找不到的东西：自由文本里的人名、地址。除非你关掉，它默认打开：第一个要脱敏的请求开始下载 AstrLink Guard，下载完成前只用规则脱敏。需要先打开 脱敏密钥 或 脱敏个人信息，找到的内容按同样的开关处理。旁边的菜单选择模型：AstrLink Guard（中英文，下载 39 MB，代码里很少误判，在 Mac 上用神经网络引擎运行；默认）或 OpenAI 的 Privacy Filter（1.6 GB，可用 GPU，代码里会遮盖更多普通值）。下面的 置信度阈值 是模型要多确定才遮盖一个值：Privacy Filter 默认 0.5，AstrLink Guard 默认 0.8（发布者的值）。调高会少遮一些普通值，也会让更多真实的人名、地址原样发出去；模型之后的规则已经去掉了大部分误判，所以默认值是我们测下来漏掉真实信息最少的那一档。

占位符是「类型 + 8 位带密钥的哈希」。同一个值每次得到同一个占位符，所以对话每一轮读起来都一样，厂商的提示词缓存也不会失效。原值只保存在内存里。

一个例子

打开 脱敏密钥 和 脱敏个人信息，并在 脱敏词 里填 Nightjar。Agent 发出：

Agent 发出 
Deploy Nightjar with OPENAI_API_KEY=sk-proj-8fK2mQx7Lp4Rt9Vw3Yz6Ab1Cd, then mail li.wei@acme-corp.cn or call 13800138000.
厂商收到 
Deploy {{TERM_5hmsrhdc}} with OPENAI_API_KEY={{API_KEY_srhjgvja}}, then mail {{EMAIL_eh5um6mb}} or call {{PHONE_uf7iy2qq}}.

模型回复 “我已在 .env 里把 OPENAI_API_KEY 设为 {{API_KEY_srhjgvja}}” 时，Agent 读到的是真实的 key，流式文本和工具调用参数里都一样，所以它写进文件的也是真 key。模型把占位符稍微改了样子（花括号里加了空格、大小写变了）也照样能换回来。

怎么确认生效

  • 事前：设置 → 隐私 里的 试一试 会显示厂商收到的文本，以及每个值的类型。
  • 每个请求：在 网关 页的最近调用和 路由 日志里，被脱敏的请求会带一个盾牌徽标和数字。鼠标指上去看类型，点开看这个请求的记录。
  • 一段时间：观测 → 脱敏（隐私页的 脱敏记录 也能进）按类型、Agent、供应商显示 7 天或 30 天里遮掉的值，以及每个请求在厂商眼里的原文，占位符会标出来。

记录保存在 ~/.config/magpie/masking，保留 30 天：Agent、供应商、模型，以及每个占位符的类型、长度和开头几个字符，从不保存原值。

发现敏感值时

在 发现敏感值时 下，每种类型可以选：

  • 脱敏（默认）：换成占位符发出。
  • 提醒：原样发出，徽标用琥珀色计数。
  • 拦截：请求被拦下，返回 400：“magpie held this request back: Settings › Privacy blocks API_KEY, and it has one (sk-…, 33 characters). Nothing was sent.” 消息里不会出现原值。

任务必须原样使用的值（团队邮箱、测试用的 key）加进 从不脱敏：只要整段匹配，就原样发出。

不处理的内容与限制

  • 思考内容保持厂商原样。带签名的 thinking 块、Gemini 的 thoughts、Responses 的加密推理都由厂商签过名，原样发回，签名才对得上。里面只会替换请求其他地方已经遮掉的值。
  • ID 和工具定义原样发送：模型 ID、消息和调用 ID、UUID、工具名、MCP 服务名、工具 schema（其中的描述文字会脱敏），这样厂商和工具还能校验它们。
  • 图片和文件数据原样发送。截图里的文字不会被遮。
  • 失败即不发送。脱敏已打开却运行不了（手动关掉了 隐私遮盖 插件，或你打开的本地模型没响应），请求返回 503，说明什么都没发出，绝不会退回成不脱敏直接发送。默认打开的模型没响应时，只用规则脱敏。
  • 供应商可以跳过。打开供应商的 请求不脱敏，它的请求就原样发出：本机或局域网的模型（Ollama、LM Studio），以及你选择的任何其他供应商，订阅和插件提供的供应商也可以。对不在本地的供应商打开时，编辑器会提示请求会不脱敏地发给它的服务商。可能回退到仍在脱敏的供应商的请求照样脱敏。命令行是 magpie provider set ollama unmasked=yes。
  • 也可以把会被脱敏的请求改发给它。在 设置 › 隐私 的 命中脱敏时改用 里选一个这样的模型。智能体的请求一旦命中脱敏规则，就原样发给它，它能按真实名称回答；没有要脱敏内容的请求照常发往原来的模型。这个模型失败时请求直接失败，绝不会脱敏后改发给云端厂商。默认关闭。
  • 模型只看到占位符。它无法读懂或推理被遮掉的值，只能原样传递。需要模型读的值放进 从不脱敏。
  • 规则按格式匹配。其他国家格式的电话号码、自由文本里的人名，需要 用本地模型查找，或者自己的 脱敏词 和 自定义脱敏规则。先用 试一试 测一下你自己的文本。

magpie 自己会发出什么，见 隐私。代码在 internal/redact 和 internal/masking。
